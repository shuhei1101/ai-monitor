# マージ

配下の PR を base ブランチへ squash マージし、ブランチ / worktree を削除して次の担当へ引き継ぐ単一ユースケース（手順は `規約/マージ手順.md`）。

対応エージェント: `subsystem-conductor` / `story-conductor` / `epic-conductor` / `system-conductor`

- 対応テストファイル: `tests/e2e/単一ユースケース/test_マージ.py`

## 正常シナリオ（成果物 PR → レイヤーブランチ）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| 成果物 PR | 担当の完了報告コメント（自分宛・未解決）あり + ユーザー承認済み | 図は複合UCシナリオで代表。モック / 各シナリオ / インターフェース定義 / モジュール構成 / テスト / 実装のいずれも同型 |
| レイヤー PR | 成果物 PR の base。`## タスク一覧` の該当行がチェック済み | 記入は成果物を作った担当 |
| base ブランチ | コンフリクトなし | - |
| assignee | 未設定 | エージェント起動条件 |

### フロー

```mermaid
sequenceDiagram
  participant GH as GitHub
  participant ORC as モニター
  participant MON as epic-conductor
  participant REPO as リポジトリ

  Note over MON: 既存セッションを継続利用
  ORC-->>GH: polling（確認ラベル + assignee なし を検知）
  ORC->>MON: 既存セッションへ送信（マージ）
  activate MON
  MON->>GH: 担当の完了報告と<br>レイヤー PR のタスク一覧のチェックを確認
  MON->>GH: 担当の完了報告コメントを Resolve
  MON->>GH: 成果物 PR の Draft を解除
  MON->>REPO: base ブランチ取り込み・<br>コンフリクトなしを確認
  MON->>GH: 成果物 PR を squash マージ + ブランチ削除
  MON->>REPO: worktree をローカルから削除
  MON->>ORC: 成果物 PR の番号を監視面から除去
  deactivate MON
  Note over MON: セッションは epic PR マージまで常駐
```

### 期待値

- 成果物 PR が merged 状態、リモートブランチ・ローカル worktree とも削除済み
- レイヤーブランチに成果物が 1 コミットとして載っている（応答ループの commit が畳まれている）
- レイヤー PR は open のまま（成果物 PR のマージに巻き込まれていない）
- 成果物 PR の番号が監視面から除去されている
- 担当の完了報告コメントが Resolve 済み

## 正常シナリオ（subsystem レベル・ユーザー承認後）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| subsystem PR | Ready + タスク一覧 全チェック済み + `確認:subsystem-conductor` + `議論中` + `assignee=ユーザー`（マージ起動のゲート中） | 配下の成果物 PR は全てマージ済み |
| ユーザー操作 | `議論中` 除去 + assignee 外し（最終承認） | 分岐を決定的に誘発 |
| base ブランチ | コンフリクトなし | - |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant GH as GitHub
  participant ORC as モニター
  participant MON as subsystem-conductor
  participant REPO as リポジトリ

  Note over MON: 既存セッションを継続利用
  U->>GH: subsystem PR の 議論中 除去 +<br>assignee 外し（最終承認）
  ORC-->>GH: polling（議論中 除去 + assignee なし を検知）
  ORC->>MON: 既存セッションへ送信（マージ）
  activate MON
  MON->>GH: subsystem PR の<br>自分宛コメント一括 Resolve
  MON->>GH: PR の Draft を解除
  MON->>REPO: base ブランチ取り込み・<br>コンフリクトなしを確認
  MON->>GH: PR を squash マージ + ブランチ削除
  MON->>REPO: worktree をローカルから削除
  MON->>GH: 親 story PR に 完了報告コメント<br>（subsystem 完了・マージした PR のリンク・<br>@story-conductor 宛） +<br>確認:story-conductor 付与
  MON->>GH: subsystem PR の<br>確認:subsystem-conductor 除去
  deactivate MON
  Note over MON: セッションは epic PR マージまで常駐
```

### 期待値

- subsystem PR が merged 状態、リモートブランチ・ローカル worktree とも削除済み
- 親 story PR に `確認:story-conductor` + 完了報告コメント（subsystem 完了・@story-conductor 宛・未解決）が付与・投稿されている
- 完了報告の本文にマージした subsystem PR へのリンクが載っている（受け取った側が経緯を追える）
- 親 story PR が open のまま（巻き込まれていない）
- subsystem PR の自分宛コメントが全て Resolve 済みで、`確認:subsystem-conductor` が除去されている
- Issue を close する操作が行われていない（面は PR で、マージが完了の印）

- intake 配下の Issue / PR に `確認:*` が 1 つも残っていない
- 最終マージを行ったセッションの監視面が空になっている
- intake 配下の全エージェントの tmux セッションが解放済み（ゾンビセッションなし）

## 異常シナリオ（コンフリクト発生）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| subsystem PR | マージ実行の直前まで完了（ユーザー最終承認済み） | 図は subsystem レベルで代表 |
| base ブランチ | 同一ファイルが base 側で先に変更済み | 意図的にコンフリクトを仕込む |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant GH as GitHub
  participant ORC as モニター
  participant MON as subsystem-conductor
  participant REPO as リポジトリ

  MON->>REPO: base ブランチ取り込みでコンフリクト検知
  MON->>GH: subsystem PR に競合ファイルと<br>どちらを残すかの相談コメント +<br>議論中 付与 + assignee=ユーザー 設定

  loop 応答ループ（解消方針が確定するまで）
    U->>GH: subsystem PR に判断コメント + assignee 外し
    ORC-->>GH: polling（ユーザー返信 + assignee なし を検知）
    ORC->>MON: 既存セッションへ送信
    MON->>REPO: 指示どおり解消 commit
    MON->>GH: 解消内容を同スレッドに返信追記<br>（追加の競合・<br>疑問があれば再相談 + assignee=ユーザー 再設定）
  end

  Note over MON: 全競合解消後は正常シナリオの<br>squash merge に合流
```

### 期待値

- PR が merged 状態（解消 commit を含む）
- 解消内容が相談コメントのスレッドに記録されている
