# モニターの起動

ユーザーがモニターを起動し、待受ポートが確定して監視が始まるまでの単一ユースケース。

待受ポートは設定で固定値も指定できるが、`0` を指定すると OS が空いているポートを選ぶ。
本番と E2E、あるいは複数の E2E を同時に動かしても、ポートの取り合いで起動に失敗しないようにするため。

空きを探して閉じてから開き直す方式は採らない。
探索と bind の間に他プロセスへ取られる余地が残るため、最初から bind したソケットをそのまま使う。

使用中ポートの台帳は持たない。
プロセスが異常終了したときに残骸が残り、誰が掃除するかという問題が必ず出るため、OS に選ばせて実績値を公開する形にする。

確定したポートはファイルへ公開する。
監視役の生存判定と、外部から `POST /reload` 等を叩くときの参照先になる。
エージェントへ渡す MCP の接続先とフックの送信先はモニターが起動時に組み立てるため、確定値が自動で伝わる。

本 UC にはエージェントが登場せず、GitHub も tmux も使わない。
そのため E2E ハーネスではなく、実プロセスを起動する結合テストで検証する。

- 対応テストファイル: `tests/integration/monitor/test_モニターの起動.py`

## 正常シナリオ（ポート自動確定）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | GitHub API を差し替え（対象一覧に空を返す） | 実リポジトリを持たずにポーリングを回すため |
| 設定ファイル | 待受ポートに `0` を指定 | 自動確定を決定的に誘発 |
| 監視役 | 無効化 | 起動の検証にプロセスを増やさない |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant MON as モニター
  participant OS as OS
  participant FS as ポートファイル

  U->>MON: 起動コマンドを実行
  MON->>OS: 待受ソケットを bind（ポート 0 を要求）
  OS-->>MON: 空いているポート番号
  MON->>MON: 確定したポートを設定へ書き戻す
  MON->>FS: 確定したポートを書き出す
  MON->>MON: bind 済みソケットで待受を開始
  MON-->>U: 起動ログ（環境名・監視対象・確定ポート）
```

### 期待値

- ポートファイルに 1 以上のポート番号が書かれている
- そのポートで HTTP の応答が返る
- 起動ログの先頭に環境名・監視対象リポジトリ・確定ポートが出ている
- エージェント起動時に組み立てる MCP の接続先が、確定したポートを指している

## 正常シナリオ（ポート指定）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | GitHub API を差し替え（対象一覧に空を返す） | - |
| 設定ファイル | 待受ポートに空いている固定値を指定 | 指定値の尊重を確認 |
| 監視役 | 無効化 | - |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant MON as モニター
  participant OS as OS
  participant FS as ポートファイル

  U->>MON: 起動コマンドを実行
  MON->>OS: 待受ソケットを bind（指定ポートを要求）
  OS-->>MON: 指定どおりのポート番号
  MON->>FS: 確定したポートを書き出す
  MON->>MON: bind 済みソケットで待受を開始
```

### 期待値

- 指定した番号がそのまま待受ポートになっている
- ポートファイルの内容が指定値と一致している

## 正常シナリオ（2 本目の同時起動）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | GitHub API を差し替え（対象一覧に空を返す） | - |
| 1 本目 | 待受ポートに `0` を指定して起動済み | - |
| 2 本目 | 別の作業ディレクトリ・別のポートファイルで、待受ポートに `0` を指定 | 並行起動を決定的に誘発 |
| 監視役 | 双方とも無効化 | - |

### フロー

```mermaid
sequenceDiagram
  participant M1 as モニター 1 本目
  participant M2 as モニター 2 本目
  participant OS as OS

  M1->>OS: 待受ソケットを bind（ポート 0）
  OS-->>M1: ポート A
  M2->>OS: 待受ソケットを bind（ポート 0）
  OS-->>M2: ポート B（A とは別）
  M2->>M2: 起動を継続（衝突しない）
```

### 期待値

- 2 本のモニターが同時に待受している
- 互いのポート番号が異なる
- それぞれのポートファイルに自分のポートだけが書かれている

## 異常シナリオ（指定ポートが使用中）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | GitHub API を差し替え（対象一覧に空を返す） | - |
| 占有 | 対象ポートを別のソケットが占有済み | bind 失敗を決定的に誘発 |
| 設定ファイル | その占有済みポートを固定値で指定 | - |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant MON as モニター
  participant OS as OS

  U->>MON: 起動コマンドを実行
  MON->>OS: 待受ソケットを bind（占有済みポートを要求）
  OS-->>MON: bind 失敗
  MON->>MON: 理由をログに残して起動を中止
  MON-->>U: 非 0 の終了コード
```

### 期待値

- 非 0 の終了コードで終了している
- ログに「指定ポートが使用中」であることと該当ポート番号が出ている
- ポートファイルが作成 / 更新されていない（古い値を残さない）
