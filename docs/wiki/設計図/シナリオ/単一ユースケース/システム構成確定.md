# システム構成確定

system-conductor が立ち上げ Issue から system ブランチ + Draft PR を作り、その本文（概要 / 背景 / 構成要件 / エピック一覧）を確定して system-architect に土台生成を引き渡す単一ユースケース。

対応エージェント: `system-conductor`（初回呼び出し）

- 対応テストファイル: `tests/e2e/単一ユースケース/test_システム構成確定.py`

## 正常シナリオ（新規プロジェクト）

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| 立ち上げ Issue | 作りたいものを書いた Issue に `確認:system-conductor` 付与済み | ユーザーが直接起票。ユーザーが付けるのは確認ラベルだけで `layer:system` はエージェントが付与する |
| assignee | 未設定 | エージェント起動条件 |
| 対象リポジトリ | 実装コードも `docs/` も無い空のリポジトリ | コードを読まない条件 |
| モニター | 対象リポを polling 中 | - |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant GH as GitHub
  participant ORC as モニター

  U->>GH: 立ち上げ Issue 起票 +<br>確認:system-conductor 付与
  ORC-->>GH: polling（確認ラベル + assignee なし を検知）
  create participant MON as system-conductor
  ORC->>MON: tmux セッション作成 +<br>フェーズドキュメント注入
  participant REPO as リポジトリ
  activate MON
  MON-->>GH: 立ち上げ Issue の本文から<br>実現したいことと制約を読む
  MON->>GH: 立ち上げ Issue に layer:system + type:feat 付与
  MON->>REPO: system ブランチ作成<br>（docs/system/{ドメイン}/base・base=master）+<br>空 commit push
  MON->>GH: system Draft PR 作成（base=master・<br>本文は 紐づく Issue のみ）
  MON->>ORC: 作成した PR の番号を<br>自セッションの監視面として台帳に登録
  MON->>GH: 立ち上げ Issue の 確認:system-conductor 除去 +<br>system PR に 確認:system-conductor 付与
  MON-->>MON: 満たすべき構成要件を<br>リポジトリ / サブシステム / 言語 /<br>外部システム の 4 カテゴリで整理
  MON-->>MON: 実現したいことを機能単位に分解し<br>エピック分割の判定に沿って epic に束ねる
  MON->>GH: 概要 / 背景 / 構成要件 / エピック一覧 を<br>system PR 本文に反映
  MON->>GH: system PR に確認事項コメント<br>（判断が割れる論点は複数案の比較と推奨）を投稿
  MON->>GH: system PR に 議論中 付与 +<br>assignee=ユーザー 設定
  deactivate MON

  loop 応答ループ（修正指示がある間）
    U->>GH: system PR にフィードバックコメント +<br>assignee 外し
    ORC-->>GH: polling（ユーザー返信 + assignee なし を検知）
    ORC->>MON: 既存セッションへ送信
    activate MON
    MON->>GH: system PR の本文修正 +<br>assignee=ユーザー 再設定
    deactivate MON
  end

  U->>GH: system PR の 議論中 除去 + assignee 外し
  ORC-->>GH: polling（議論中 除去 + assignee なし を検知）
  ORC->>MON: 既存セッションへ送信（完了処理）
  activate MON
  MON->>GH: system PR の自分宛コメント一括 Resolve
  MON->>GH: system PR 本文に タスク一覧 を追記
  MON->>REPO: 土台生成の成果物ブランチ作成<br>（docs/system/{ドメイン}/foundation・<br>base=system ブランチ）+ 空 commit push
  MON->>GH: 成果物 Draft PR 作成 + 親のスタックへ接続
  MON->>ORC: 作成した PR の番号を<br>自セッションの監視面として台帳に登録
  MON->>GH: 成果物 PR に 土台生成の依頼コメント投稿 +<br>確認:system-architect 付与
  MON->>GH: system PR の 確認:system-conductor 除去
  deactivate MON
  Note over MON: セッションは system PR マージまで常駐
```

### 期待値

- system ブランチ（base=master）と Draft PR が作成されている
- system PR 本文に `## 概要` / `## 背景` / `## 構成要件` / `## エピック一覧` が揃っている
- system PR 本文の `## 紐づく Issue` に立ち上げ Issue の番号が入っている
- 立ち上げ Issue に `layer:system` と `type:feat` が付与されている（ユーザーは確認ラベルしか付けていない）
- 立ち上げ Issue から `確認:system-conductor` が外れ、以降のやり取りは system PR 上で行われている
- `## 構成要件` の各行が銘柄ではなく満たすべき性質で書かれている（`認証は外部 IdP に委譲する` の形）
- `## エピック一覧` の各行に所属ユースケースと着手順が入り、`対応 PR` 列が全行 `未作成`
- 着手順に重複がない
- system PR 本文の `## タスク一覧` に `.gitignore` の作成と `.claude/settings.json` へのルール索引の宣言が含まれている
- 土台生成の成果物ブランチと Draft PR（base=system ブランチ）が作成され、`確認:system-architect` と依頼コメント（未解決）が付与・投稿されている
- 作成した PR の番号が自セッションの監視面（モニターの台帳）に登録されている
- 自分宛コメントが全て Resolve 済み
