# システム土台生成

system-architect が確定した構成をもとに `設計図/アーキテクチャ図.md`・`docs/wiki/` の骨格・`docs/rules.yaml`・`README.md` の骨格・`.gitignore`・`.claude/settings.json` を土台生成の成果物 PR 上で生成し、ユーザー承認を経て system-conductor に完了報告する単一ユースケース。

対応エージェント: `system-architect`

- 対応テストファイル: `tests/e2e/単一ユースケース/test_システム土台生成.py`

## 正常シナリオ

### セットアップ

| セットアップ | 説明 | 補足 |
| --- | --- | --- |
| Mock | なし（実環境で実行） | - |
| 成果物 Draft PR | `docs/system/{ドメイン}/base`（base=system ブランチ）に `確認:system-architect` 付与済み + system-conductor の依頼コメント（自分宛・未解決）あり | [システム構成確定](./システム構成確定.md) の完了状態 |
| 親 system PR | 本文の構成要件が確定済み | 生成の元ネタ |
| assignee | 未設定 | エージェント起動条件 |
| 対象リポジトリ | `README.md` も `docs/` も無い | 土台を新規生成する条件 |
| モニター | 対象リポを polling 中 | - |

### フロー

```mermaid
sequenceDiagram
  actor U as ユーザー
  participant GH as GitHub
  participant ORC as モニター

  Note over GH: 成果物 PR に 確認:system-architect 付与済み
  ORC-->>GH: polling（確認ラベル + assignee なし を検知）
  create participant MON as system-architect
  ORC->>MON: tmux セッション作成 +<br>フェーズドキュメント注入
  activate MON
  participant REPO as リポジトリ
  MON-->>GH: 親 system PR の構成要件と<br>依頼コメントを読む
  MON->>REPO: docs/wiki 骨格・各 README・<br>空の docs/rules.yaml・README.md 骨格・<br>.gitignore を作成
  MON->>REPO: .claude/settings.json に<br>ルール索引（INJECT_RULES_INDEXES）を宣言<br>（my-plugins + ai-monitor + 自プロジェクト）
  MON->>REPO: 設計図/アーキテクチャ図.md を<br>確定した構成要件どおりに作成 / 上書き<br>（全体図 / リポジトリ構成 /<br>サブシステム一覧 / 外部システム連携）
  MON->>REPO: 設計図/非機能要件.md を作成<br>（外部の制約からアプリの決定値を確定・<br>逆算できない項目は仮置き・<br>決められない項目は 未確定）
  MON->>GH: GitHub ラベルを一括作成
  MON->>REPO: 生成物を成果物ブランチへ commit push
  MON->>GH: 親 system PR のタスク一覧の<br>該当行にチェックを入れる
  MON->>GH: 確認事項 / 補足事項を<br>該当行にインラインコメント投稿
  MON->>GH: 成果物 PR に完了報告コメント +<br>議論中 付与 + assignee=ユーザー 設定
  deactivate MON

  loop 応答ループ（修正指示がある間）
    U->>GH: 成果物 PR にフィードバックコメント + assignee 外し
    ORC-->>GH: polling（ユーザー返信 + assignee なし を検知）
    ORC->>MON: 既存セッションへ送信
    activate MON
    MON->>REPO: 指摘箇所を修正して commit push
    MON->>GH: 決着したインライン確認事項スレッドに<br>確定内容を返信して Resolve<br>（未回答が残るものは畳まない）
    MON->>GH: ユーザーが指摘したコメントに<br>返信追記 +<br>成果物 PR の assignee=ユーザー 再設定
    deactivate MON
  end

  U->>GH: 成果物 PR の 議論中 除去 + assignee 外し
  ORC-->>GH: polling（議論中 除去 + assignee なし を検知）
  ORC->>MON: 既存セッションへ送信（完了処理）
  activate MON
  MON->>GH: 成果物 PR の自分宛コメント一括 Resolve
  MON->>GH: 成果物 PR に 完了報告コメント投稿<br>（生成したページ一覧 + 作成したラベル） +<br>確認:system-conductor 付与
  MON->>GH: 成果物 PR の 確認:system-architect 除去
  deactivate MON
  Note over MON: セッションは system PR マージまで常駐
```

### 期待値

- 成果物ブランチに `README.md`・`docs/rules.yaml`・`docs/wiki/` の骨格が commit され、全ディレクトリに `README.md` が併置されている
- 応答ループで積んだ手直しの commit が成果物ブランチ側にあり、親 system ブランチには入っていない（マージ時に 1 コミットへ畳まれる）
- `設計図/アーキテクチャ図.md` の全体図・サブシステム一覧・外部システム連携が、親 system PR の `## 構成要件` の各行と対応している
- `リバースエンジニアリング` ラベルがある場合、本 PR の Files changed がアーキテクチャ図の現状からあるべき姿への変更範囲になっている
- 銘柄未定の外部システムが `{種別}（銘柄未定）` の形で記録され、詳細列と対応非機能要件テスト列が `-` になっている
- `docs/rules.yaml` が空の索引（`rules: []`）として存在する
- `.claude/settings.json` の `INJECT_RULES_INDEXES` に my-plugins・ai-monitor・自プロジェクトの `docs/rules.yaml` が宣言されている（ユーザーが手で設定しなくても規約が注入される）
- `.gitignore` が存在し、`.claude/worktrees/` と環境変数ファイルが追跡対象から外れている（構成要件の実装言語に応じた依存・キャッシュの除外も入っている）
- `設計図/非機能要件.md` の `## 一覧` の各行に 外部の制約 / 出所 / アプリの決定値 / 根拠 が揃っている
- 一覧の各行が詳細セクションへのリンクになっていて、対応する `## {項目名}` が存在する
- 銘柄未定など決められない項目は決定値列が `未確定` で、根拠列に決める条件が入っている
- 外部の制約から逆算できない項目（コスト予算 等）に対する確認事項がインラインコメントで投稿されている
- `テスト/テスト実行方法.md` は見出しのみで本文が `未確定`
- `外部API/README.md` と `外部ライブラリ/README.md` が空の索引として存在する
- 親 system PR の `## タスク一覧` の土台生成の行がチェック済み
- `constants.env` の全ラベルが対象リポジトリに作成されている
- 成果物 PR に `確認:system-conductor` + 完了報告コメント（未解決）が付与・投稿され、`確認:system-architect` が除去されている
- 自分宛コメントが全て Resolve 済み
- 応答ループの各ターンで、決着したインライン確認事項スレッドが確定内容の返信付きで Resolve されている
- 応答ループの返信が、ユーザーが指摘したコメントのスレッドに積まれている（自分の過去の報告コメントに追記していない）
- 完了処理に入った時点で未解決のインライン確認事項が残っていない（残る場合は `議論中` を戻して聞き直す）
- commit した内容に対する補足事項がインラインコメントで残っている（判断を仰ぐ論点がある場合は `@ユーザー` 宛の確認事項として投稿されている）
