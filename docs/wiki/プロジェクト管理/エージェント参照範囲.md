# エージェント参照範囲

各エージェントが監視対象プロジェクトの何を読み書きしてよいかの一覧。
担当外のものを読みに行くと、そのレイヤーで決めるべきでない論点を持ち込むことになる（実装コードを読んだ conductor が実装レベルの確認質問を投げる 等）。

| 記号 | 意味 |
| --- | --- |
| 作成 | そのエージェントが作成・更新する成果物 |
| 参照 | 判断材料として読んでよい |
| - | 読まない |

「モック」は `docs/mock/` 配下のモック画面（HTML）。
「その他の設計書」は アーキテクチャ図 / 非機能要件 / ER図 / 画面構成 / 外部ライブラリ を指す。

## 補足

- conductor 4 種（system / epic / story / subsystem）は実装コードを読まない。
  実装の現状調査は subsystem-conductor が起票した後、architect と RE 担当が行う
- RE 担当 5 種は「実装コードを読んで設計書を起こす」のが役割なので、実装コードの参照が前提になる。
  ただし実装コードは変更しない
- tester / implementer が作成する実装コードは、それぞれテストコードと実装コード。
  互いの担当ファイルは参照にとどめ、修正は担当側へ差し戻す
- architect は実装レビューで diff を読むため実装コードを参照するが、修正はしない（worker に差し戻す）
- モックは mock-designer が作成し、mock-reverse-engineer が現状の画面から起こす。
  フロントエンドを実装・テストする側（implementer / tester / scenario-tester）は、画面の見た目と遷移の根拠としてモックを参照する
- questioner は調査が役割なので全てを参照できる。
  ただし作成はしない（依頼された起票は intake-issue-triager に渡す）
