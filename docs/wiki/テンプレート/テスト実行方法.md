# ai-monitor テンプレート: テスト実行方法

プロジェクトの **テスト種別ごとの実行コマンド** をまとめる書式。
トリアージ時にサブエージェントが「実際にテストを走らせる」ときの参照元として使う。

ファイル名は `テスト実行方法.md`（固定）。

## ファイル構成

`docs/wiki/テスト/テスト実行方法.md`

## セクション一覧

| セクション | 必須or条件 | 担当 | 補足 |
| --- | --- | --- | --- |
| 冒頭リード | 必須 | architect | 前提条件（Node バージョン / DB 起動 等） |
| `## 非機能要件テスト` | 必須 | architect | `設計図/非機能要件.md` の決定値を実測で検証する |
| `## E2E テスト` | E2E テスト運用時 | architect | Playwright 等の起動コマンド |
| `## 結合テスト（フロント）` | 必須 | architect | vitest + MSW 等の起動コマンド |
| `## 結合テスト（バック）` | 必須 | architect | pytest + httpx TestClient 等の起動コマンド |
| `## 単体テスト（フロント）` | 必須 | architect | vitest 等の起動コマンド |
| `## 単体テスト（バック）` | 必須 | architect | pytest 等の起動コマンド |
| `## 外部疎通テスト` | 外部 API 利用時 | architect | 実 API に接続する疎通テスト（料金 / 副作用注意） |

## `冒頭リード`

### 記述例

```markdown
# テスト実行方法

プロジェクトのテスト種別ごとの実行コマンドと前提条件。

## 前提

- Node.js 22 以上 + pnpm 9 以上
- DB: PostgreSQL 16 のローカル起動（`docker compose up -d postgres`）
- 環境変数: `.env.test` を配置
```

### 補足

- 全種別共通の前提条件（言語ランタイム / 依存サービス / 環境変数）を冒頭にまとめる
- 種別固有の前提は各セクションに書く
- 初回に書いた内容のまま保ち、後から情報を足さない。
  実行コマンドと種別固有の条件は各テスト種別のセクションに書く（両方に書くと同じ内容を 2 箇所で持つことになる）。
  対象そのものが変わったときだけ既存の記述を書き換える

## `## 非機能要件テスト`

### 記述例

````markdown
## 非機能要件テスト

`設計図/非機能要件.md` の決定値を実測で確認するテスト。
性能 / 負荷限界 / 耐障害 / 耐久 / 可用性 と、外部システムへの疎通確認を扱う。
実測に時間がかかり結果が実行環境に依存するため **通常の CI では実行しない**。

**前提:**

- 計測対象を本番同等の構成で起動: `docker compose -f compose.nfr.yaml up -d`
- 負荷生成は locust（`tests/nfr/locustfile.py`）を pytest から起動する
- 実行マシンの条件を `設計図/非機能要件.md` の測定方法と揃える（CPU / メモリ / ネットワーク）
- 誤実行防止のため `--run-nfr` フラグ必須（フラグなしだと skip される）
- 外部システムへの疎通確認は `## 外部疎通テスト` の手順で実行する

**全件実行:**

```bash
uv run pytest tests/nfr/ --run-nfr
```

**個別項目実行:**

```bash
uv run pytest {非機能要件テストファイルパス} --run-nfr
```
````

### 補足

- 対象は `設計図/非機能要件.md` の `## 一覧` の各行。
  1 項目 = 1 テストファイル（`tests/nfr/test_{項目の英語名}.py`）で、詳細セクションの `### 非機能要件テスト` 表の 1 行が 1 ケースに対応する
- 分類は 性能 / 負荷限界 / 耐障害 / 耐久 / 可用性 / 外部疎通。
  外部疎通は料金・副作用という別の前提を持つため `## 外部疎通テスト` に分け、本セクションからは参照だけする
- 実測の再現条件（起動構成・負荷生成ツール・実行マシンの条件）を前提に明記する
- 決定値が `未確定` の項目はテスト対象外
- 記法ルールは E2E テストの補足を参照

## `## E2E テスト`

### 記述例

````markdown
## E2E テスト

Playwright + Chromium ヘッドレスで実行。

**前提:**

- **フロントサーバー**: Playwright が `webServer` 設定で自動起動（手動不要）
- **バックエンドサーバー**: 別ターミナルで起動が必要
  ```bash
  uv run fastapi dev src/main.py --port 8000
  ```
- **DB 起動**: `docker compose up -d postgres-test`
- **外部 API のモック化**: デフォルトで Mock（MSW / pytest-httpx）
  - 実 API を叩きたい場合は `E2E_USE_REAL_EXTERNAL_API=true` 環境変数を付与（料金 / 副作用が発生するため要注意 → `## 外部疎通テスト` 参照）

**全件実行:**

```bash
pnpm test:e2e
```

**個別シナリオ実行:**

```bash
pnpm test:e2e {シナリオファイルパス}
```
````

### 補足（全種別共通）

- `**前提:**` を先頭に置く（種別固有の前提: 開発サーバー起動要否 / Mock 状況 / DB 起動 等）
- `**全件実行:**` / `**個別{X}実行:**` は各 1 コマンドだけコードブロックで書く
- 個別実行は **プレースホルダー形式**（`{シナリオファイルパス}` / `{画面テストファイルパス}` 等）で 1 コマンドだけ書く。
- コマンドは言語指定 `bash` で書く → GitHub の 1 クリックコピーで貼り付け可能

## `## 外部疎通テスト`

### 記述例

````markdown
## 外部疎通テスト

**実 API に接続して疎通を確認** するテスト（非機能要件テストのうち外部疎通の分類）。
料金発生 / 副作用（実メール送信 / 実決済 / 実 SMS 等）があるため **通常の CI では実行しない**。

**前提:**

- 実 API 認証情報を環境変数 or `.env.external` に設定
  - 例: `OPENAI_API_KEY` / `SENDGRID_API_KEY` / `STRIPE_SECRET_KEY`
- **料金 / 副作用の発生を認識した上で実行**（テストごとの料金目安は `外部API/{API名}.md` を参照）
- 誤実行防止のため `--run-external` フラグ必須（フラグなしだと skip される）
- 通常の CI（GitHub Actions 等）では **実行禁止**

**全件実行:**

```bash
uv run pytest tests/external/ --run-external
```

**個別実行:**

```bash
uv run pytest {外部疎通テストファイルパス} --run-external
```
````

### 補足

- 対象は `設計図/アーキテクチャ図.md` の `## 外部システム連携` の各行（1 外部システム = 1 テストファイル）
- 料金 / 副作用の警告を **必ず前提に明記**
- `--run-external` のような誤実行防止フラグを必須にする
- 対象外部 API の詳細は `外部API/{API名}.md` を参照させる
- 記法ルールは E2E テストの補足を参照
