# ai-monitor テンプレート: PR 本文 / 成果物

レイヤーブランチの配下に切る成果物ブランチの PR 本文書式（規約『ブランチ戦略』の成果物ブランチ）。

成果物 PR は **1 つの成果物を作るための PR**。
要件はベース PR が持つので本文には転記せず、書くのはその成果物の To Do だけ。

固有のセクションを持つ成果物は専用のテンプレートを使う。

| 成果物 | テンプレート |
| --- | --- |
| 土台生成 / 複合UCシナリオ / 単一UCシナリオ / インターフェース定義 / モジュール構成 / 実装 / RE / バグ修正 | 本ページ |
| モック | [モック](./モック.md) |
| 複合UC統合テスト / 単一UC統合テスト | [統合テスト](./統合テスト.md) |
| 単体・結合テスト | [単体・結合テスト](./単体・結合テスト.md) |

## セクション一覧

| セクション | サブセクション | 必須or条件 | 担当 | 補足 |
| --- | --- | --- | --- | --- |
| `## 紐づく Issue` | - | 必須（PR 作成時） | 成果物ブランチを切る conductor | 起点の Issue 番号 |
| `## タスク一覧` | - | 必須 | 成果物ブランチを切る conductor | その成果物の To Do。チェックは各行を担当した作業者が入れる |

## `## 紐づく Issue`

### 記述例

```markdown
## 紐づく Issue

- #200 プロフィール編集機能
```

### 補足

- 起点の Issue（intake Issue、system レイヤーから始まる場合は立ち上げ Issue）の番号を書く（1 件のみ）
- 親 PR の番号は書かない（base を 1 段辿れば親に着く）

## `## タスク一覧`

### 記述例

並ぶ行は成果物ごとに変わる。

設計ドキュメントの例:

```markdown
## タスク一覧

- [ ] `設計図/インターフェース定義/バックエンド/プロフィール更新.py.md` を新規作成
- [ ] `設計図/インターフェース定義/バックエンド/README.md` の索引に行を追加
- [ ] `設計図/ER図/ユーザー.md` の `users` テーブルに `bio` カラムを追記
```

土台生成の例:

```markdown
## タスク一覧

- [ ] `docs/wiki/` の骨格と `docs/rules.yaml` を生成
- [ ] `設計図/アーキテクチャ図.md` を作成
- [ ] `設計図/非機能要件.md` を作成
- [ ] `README.md` を作成
- [ ] `.gitignore` を作成
- [ ] `.claude/settings.json` にルール索引を宣言
- [ ] GitHub ラベルを一括作成
```

シナリオの例:

```markdown
## タスク一覧

- [ ] `設計図/シナリオ/単一ユースケース/プロフィール編集.md` を新規作成
- [ ] `設計図/シナリオ/README.md` の `## 目次` に行を追加
```

実装の例:

```markdown
## タスク一覧

- [ ] `src/services/user_service.py` に更新処理を実装
- [ ] `src/api/users.py` に PATCH エンドポイントを追加
- [ ] `設計図/モジュール構成/バックエンド/ユーザー.py.md` を実装に合わせて更新
```

### 補足

- チェックボックス形式で やることリスト を列挙
- 1 行 = 1 To Do とし、1 行を 1 人の担当で完結させる
- `[x]` はその行の作業をした本人が commit 直後に入れる（発注元は全行チェック済みかを確認するだけ）
- 全行がチェックされてからマージする
- 成果物そのものの内容（設計の中身・実装の詳細）は書かない。
  変更ファイル一覧で読めるため、本文に書くと二重管理になる
