# ai-monitor テンプレート: PR 本文 / ストーリー

`layer:story` が付いた PR の本文書式。

story PR は **単一ユースケースシナリオを設計するための PR**。
親 story Issue の `## ユースケース要件` を元に、`docs/wiki/設計図/シナリオ/単一ユースケース/{機能名}.md` を作成 / 更新する。
書くのは **タスク一覧（実施すべき To Do）** と **単一ユースケースシナリオテストの結果** だけ（変更内容の詳細は変更ファイル一覧で見る）。

## セクション一覧

| セクション | サブセクション | 必須or条件 | 担当 | 補足 |
| --- | --- | --- | --- | --- |
| `## 紐づく Issue` | - | 必須（PR 作成時） | story-conductor（PR 作成者） | 親 story Issue 番号 |
| `## タスク一覧` | - | 必須（PR 作成時。単一 UC 影響なしで下位へ通過する場合は不要） | story-conductor（PR 作成者） | Wiki 修正・単一 UC E2E テストの作成 / 実行の To Do。チェックは各行を担当した作業者が入れる |
| `## 単一ユースケースシナリオテスト結果` | - | 必須（テスト実装時にセクション新設 → 実行後に結果記入） | single-scenario-tester | 作成 / 変更した単一 UC E2E テストの結果（新規 + 回帰） |

## `## 紐づく Issue`

### 記述例

```markdown
## 紐づく Issue

- #123 プロフィール編集ストーリー
```

### 補足

- 親 story Issue 番号を必須で書く（1 件のみ。祖先は Sub-issue リンクで辿れる）

## `## タスク一覧`

### 記述例

```markdown
## タスク一覧

- [ ] `設計図/シナリオ/単一ユースケース/プロフィール編集.md` を新規作成
- [ ] `設計図/シナリオ/README.md` の `## 一覧` に該当行を追加
- [ ] 単一ユースケース E2E テストコードを作成
- [ ] 単一ユースケース E2E テストを実行
```

### 補足

- チェックボックス形式で **やることリスト**を列挙
- 各タスクは 1 行 = 1 To Do とし、1 行を 1 人の担当で完結させる（E2E テストは「作成」と「実行」で担当が分かれるため行を分ける）
- Wiki 修正・テスト作成・テスト実行の 3 種類に分けて書く
- `[x]` はその行の作業をした本人が commit 直後に入れる（指示者は全行チェック済みかを確認するだけ）
- 全行がチェックされてからマージする

## `## 単一ユースケースシナリオテスト結果`

### 記述例

```markdown
## 単一ユースケースシナリオテスト結果

| ファイル | メソッド | 結果 | 補足 |
| --- | --- | --- | --- |
| `tests/e2e/profile_edit.spec.ts` | 全実行 | ✅ | 対応シナリオ: `プロフィール編集` |
```

### 補足

- 本 story で作成 / 変更した単一 UC E2E テストを全て実行して結果を記録
- 結果列: `✅`（pass）/ `❌`（fail）
- 補足列に対応シナリオ名を明記（`docs/wiki/設計図/シナリオ/単一ユースケース/{機能名}.md` と 1:1 対応）
- 単一ユースケースシナリオが無い story はそもそも成立しないが、テスト未整備の暫定 PR なら本文に「なし」と記載
