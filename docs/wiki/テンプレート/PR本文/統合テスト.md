# ai-monitor テンプレート: PR 本文 / 統合テスト

統合テストの成果物ブランチ（`test/epic/{ドメイン}/integration` / `test/story/{ドメイン}/{UC名}/integration`）の PR 本文書式。

統合テストの成果物 PR は **ユースケースシナリオに対応する E2E テストを作って実行するための PR**。
実行結果をこの本文に置き、親のベース PR は要件だけを持つ。

対象のレイヤーで使うセクションが変わる。

| 発注元 | 使うテスト結果セクション |
| --- | --- |
| epic-conductor | `## 複合ユースケースシナリオテスト結果` |
| story-conductor | `## 単一ユースケースシナリオテスト結果` |

## セクション一覧

| セクション | サブセクション | 必須or条件 | 担当 | 補足 |
| --- | --- | --- | --- | --- |
| `## 紐づく Issue` | - | 必須（PR 作成時） | 発注元の conductor | 起点の Issue 番号 |
| `## タスク一覧` | - | 必須 | 発注元の conductor | テストの作成と実行の To Do |
| `## 複合ユースケースシナリオテスト結果` | - | epic 配下の場合 | complex-scenario-tester | - |
| `## 単一ユースケースシナリオテスト結果` | - | story 配下の場合 | single-scenario-tester | - |

## `## 紐づく Issue`

### 記述例

```markdown
## 紐づく Issue

- #200 プロフィール編集機能
```

### 補足

- 起点の Issue の番号を書く（1 件のみ）

## `## タスク一覧`

### 記述例

```markdown
## タスク一覧

- [ ] {この成果物でやること}
```

### 補足

- 書式はテンプレート「成果物」の `## タスク一覧` と同じ
- `[x]` はその行の作業をした本人が commit 直後に入れる

## `## 複合ユースケースシナリオテスト結果`

### 記述例

```markdown
## 複合ユースケースシナリオテスト結果

| ファイル | メソッド | 変更種別 | 結果 | 補足 |
| --- | --- | --- | --- | --- |
| `tests/e2e/onboarding/signup-to-first-task.spec.ts` | 全実行 | 新規 | ✅ | 対応シナリオ: `新規登録から初回タスク作成` |
| `tests/e2e/tasks/create-then-edit-by-other.spec.ts` | 全実行 | 実行のみ | ✅ | 回帰確認 |
```

### 補足

- 本 epic で作成 / 変更した複合 UC E2E テストを全て実行して結果を記録
- 変更種別列: `新規` / `変更` / `削除` / `実行のみ`（回帰確認でコードを触っていないもの）
- 結果列: `✅`（pass）/ `❌`（fail）。
  変更種別が `削除` の行は `-` にする
- 補足列に対応シナリオ名を明記（`docs/wiki/設計図/シナリオ/複合ユースケース/{論理名}.md` と 1:1 対応）
- 複合ユースケースシナリオが無い epic の場合も本セクションは残し、本文に「なし」と記載

## `## 単一ユースケースシナリオテスト結果`

### 記述例

```markdown
## 単一ユースケースシナリオテスト結果

| ファイル | メソッド | 変更種別 | 結果 | 補足 |
| --- | --- | --- | --- | --- |
| `tests/e2e/profile_edit.spec.ts` | 全実行 | 新規 | ✅ | 対応シナリオ: `プロフィール編集` |
```

### 補足

- 本 story で作成 / 変更した単一 UC E2E テストを全て実行して結果を記録
- 変更種別列: `新規` / `変更` / `削除` / `実行のみ`（回帰確認でコードを触っていないもの）
- 結果列: `✅`（pass）/ `❌`（fail）。
  変更種別が `削除` の行は `-` にする
- 補足列に対応シナリオ名を明記（`docs/wiki/設計図/シナリオ/単一ユースケース/{機能名}.md` と 1:1 対応）
- 単一ユースケースシナリオが無い story はそもそも成立しないが、テスト未整備の暫定 PR なら本文に「なし」と記載
