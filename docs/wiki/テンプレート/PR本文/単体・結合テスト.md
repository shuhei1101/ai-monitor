# ai-monitor テンプレート: PR 本文 / 単体・結合テスト

単体・結合テストの成果物ブランチ（`test/{scope}/{ドメイン}/{UC名}/{変更内容}`）の PR 本文書式。

単体・結合テストの成果物 PR は **モジュール構成とインターフェース定義に対応するテストを作って実行するための PR**。
実行結果をこの本文に置き、親 subsystem のベース PR は要件（SA）だけを持つ。

## セクション一覧

| セクション | サブセクション | 必須or条件 | 担当 | 補足 |
| --- | --- | --- | --- | --- |
| `## 紐づく Issue` | - | 必須（PR 作成時） | subsystem-conductor（PR 作成者） | 起点の Issue 番号 |
| `## タスク一覧` | - | 必須 | subsystem-conductor | テストの作成と実行の To Do |
| `## 単体テスト結果` | - | 必須（テスト作成時にセクション新設 → 実行後に結果記入） | tester | - |
| `## 結合テスト結果` | - | 必須（テスト作成時にセクション新設 → 実行後に結果記入） | tester | - |

## `## 紐づく Issue`

### 記述例

```markdown
## 紐づく Issue

- #200 プロフィール編集機能
```

### 補足

- 起点の Issue の番号を書く（1 件のみ）

## `## タスク一覧`

### 記述例

```markdown
## タスク一覧

- [ ] {この成果物でやること}
```

### 補足

- 書式はテンプレート「成果物」の `## タスク一覧` と同じ
- `[x]` はその行の作業をした本人が commit 直後に入れる

## `## 単体テスト結果`

### 記述例

```markdown
## 単体テスト結果

| ファイル | メソッド | 変更種別 | 結果 | 補足 |
| --- | --- | --- | --- | --- |
| `tests/services/test_user_service.py` | 全実行 | 新規 | ✅ | 3 テスト pass |
| `tests/repositories/test_user_repo.py` | 全実行 | 実行のみ | ✅ | 2 テスト pass |
```

### 補足

- **単体テストは全部実行**して結果を記録する
- ファイル単位で 1 行、`メソッド` 列は `全実行` と書く（個別実行時のみメソッド名）
- 変更種別列: `新規` / `変更` / `削除` / `実行のみ`（回帰確認でコードを触っていないもの）
- 結果列: `✅`（pass）/ `❌`（fail）。
  変更種別が `削除` の行は `-` にする
- fail した場合は補足列にエラー要約
- 単体テストが 1 件もないプロジェクトなら本文に「なし」と記載

## `## 結合テスト結果`

### 記述例

```markdown
## 結合テスト結果

| ファイル | メソッド | 変更種別 | 結果 | 補足 |
| --- | --- | --- | --- | --- |
| `tests/api/test_users.py` | `test_put_users_id_e2e` | 新規 | ✅ | 新規追加テスト |
| `tests/api/test_profile.py` | 全実行 | 実行のみ | ✅ | 既存テスト、回帰確認 |
```

### 補足

- **関連する結合テストのみ実行**（今回の変更に該当するもの + 新規作成したもの）
- 全部回す必要はない
- 変更種別列: `新規` / `変更` / `削除` / `実行のみ`（回帰確認でコードを触っていないもの）
- 結果列: `✅`（pass）/ `❌`（fail）。
  変更種別が `削除` の行は `-` にする
- 関連する結合テストがない場合は本文に「なし」と記載
