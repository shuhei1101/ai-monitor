# ai-monitor テンプレート: コンテナ構成

Docker Compose 等でオーケストレーションされるコンテナ群の構成書式。
**1 YAML ファイル = 1 ページ** に対応させる。

配置先は `docs/wiki/設計図/コンテナ構成/{スタック名}.yaml.md`（例: `docs/wiki/設計図/コンテナ構成/compose.yaml.md`）。
新規作成時は `docs/wiki/設計図/コンテナ構成/README.md`（一覧）に行を追加する。

**上流ドキュメントへの参照リンク:**
- 冒頭リードに **Docker Compose 公式仕様（Compose file specification）への URL** を書く: <https://docs.docker.com/compose/compose-file/>
- 各サービス詳細の説明文中で、対応する **外部ライブラリ Wiki**（`docs/wiki/外部ライブラリ/{名前}.md`）や **外部API Wiki**（`docs/wiki/外部API/{名前}.md`）にインラインリンクで参照する
- 詳細情報（ライセンス・公式ドキュメント・API 仕様）は上流に集約し、本ページでは重複させない

## セクション一覧

| セクション | サブセクション | 必須or条件 | 担当 | 補足 |
| --- | --- | --- | --- | --- |
| `## サービス一覧` | - | 必須 | issue-arch | 表形式で全サービスを俯瞰 |
| `## {サービス名}` | `### 環境変数` / `### ボリューム` / `### {その他複数値項目}` | 必須（一覧表の各行につき 1 セクション） | issue-arch | 単一値項目は冒頭表・複数値項目は H3 サブセクション |
| `## {Dockerfile 名}` | - | 任意（Dockerfile がある場合のみ） | issue-arch | ビルド処理を番号付きで |

## `## サービス一覧`

### 記述例

```markdown
## サービス一覧

| サービス名 | イメージ | 用途 | 公開ポート | 依存 | 補足 |
| --- | --- | --- | --- | --- | --- |
| [otel-collector](#otel-collector) | `otel/opentelemetry-collector-contrib:0.113.0` | OTLP 受信 + Loki 転送 | `4317` / `4318` | loki | - |
| [loki](#loki) | `grafana/loki:3.2.1` | Log 保存 | `3100` | - | 単一バイナリ / filesystem storage |
| [grafana](#grafana) | `grafana/grafana:11.3.0` | 可視化 UI | `3000` | loki | admin / admin |
```

### 補足

**サービス名列:**
- 詳細セクションへのリンクで書く（`[{名前}](#{アンカー})`）

**イメージ列:**
- `{registry}/{repo}:{tag}` 形式でタグ固定を推奨（`latest` は避ける）

**用途列:**
- 1 行で要約

**公開ポート列:**
- host 側のポートを書く（複数は ` / ` 区切り）

**依存列:**
- `depends_on` に相当。依存なしは `-`

## `## {サービス名}`

各サービスの詳細。
一覧表の各行につき 1 セクション。

冒頭に blockquote で **設定ファイル（マウント元）の格納パス** を書く。
続けて 1〜2 行の説明。
その下に **単一値項目の表**（キーごとに値が 1 つで確定するもの）を置く。
複数値項目（環境変数・ボリューム 等）は H3 サブセクションに分ける。

### 記述例

````markdown
## otel-collector
> 設定ファイル: `./otel-collector-config.yaml`

OTLP プロトコル（gRPC / HTTP）で telemetry を受信して Loki の `/loki/api/v1/push` に転送する中継サーバー。

| 項目 | 値 | 補足 |
| --- | --- | --- |
| イメージ | `otel/opentelemetry-collector-contrib:0.113.0` | ビルドを使う場合は `-` |
| ビルド | `-` | 使う場合は Dockerfile セクションへのリンク（同ページ or 別ページ）を貼る |
| 公開ポート | `4317:4317` / `4318:4318` | OTLP gRPC / HTTP |
| コマンド | `--config=/etc/otelcol-contrib/config.yaml` | - |
| 依存 | `loki` | Loki 起動後に受付開始 |
| リスタート | `unless-stopped` | - |
| ヘルスチェック | `curl -f http://localhost:13133/` | 30s 間隔 |

### 環境変数

| 環境変数 | 値 | 補足 |
| --- | --- | --- |
| `GOMEMLIMIT` | `512MiB` | Collector の GC 上限 |

### ボリューム

| ソース | マウント先 | モード | 補足 |
| --- | --- | --- | --- |
| `./otel-collector-config.yaml` | `/etc/otelcol-contrib/config.yaml` | `ro` | bind mount（設定ファイル） |
````

### 補足

**冒頭 blockquote:**
- `> 設定ファイル: `{格納パス}`` を必ず 1 行書く（設定ファイルを持たないサービスは `-` or 行自体を省略）
- 複数の設定ファイルを持つ場合はカンマ区切りで並べる（例: `> 設定ファイル: `./loki-config.yaml`, `./rules.yaml``）

**単一値項目の表（冒頭表）:**
- 1 サービスに対して値が 1 つで確定する項目のみを表に書く
- 基本項目: `イメージ` / `ビルド` / `公開ポート` / `コマンド` / `依存` / `リスタート`
- 必要に応じて追加: `ヘルスチェック` / `エントリポイント` / `ユーザー` / `ネットワーク`（既定以外を使う場合）
- `イメージ` と `ビルド` はどちらか一方が実値、もう一方が `-`（Docker Compose の `image:` / `build:` に対応）

**ビルド行のリンク書式:**
- Dockerfile を build で使うサービスは、`ビルド` セルに Dockerfile セクションへのリンクを貼る
- **同ページ内の Dockerfile を使う場合**: 同ページアンカーリンク（例: `[Dockerfile（custom-collector）](#dockerfile-custom-collector)`）
- **別ページの Dockerfile を使う場合**（複数スタックで共有する Dockerfile 等）: 別ページへの相対リンク（例: `[custom-collector](../shared/custom-collector.dockerfile.md)`）

**複数値項目のサブセクション（H3）:**
- 1 サービスに対して値が複数取りうる項目は個別の H3 サブセクションで書く
- 代表: `### 環境変数` / `### ボリューム`
- 各サブセクションは 1 項目 = 1 行 の表で書く
  - 環境変数表: `環境変数 / 値 / 補足`
  - ボリューム表: `ソース / マウント先 / モード / 補足`（`モード` は `ro` / `rw` / `-`）
- 該当する項目がなければサブセクション自体を省略してよい

**バージョン固定:**
- イメージタグは採用時点の固定値。アップグレード時はここを更新
- ライセンス / 公式 URL は対応する `docs/wiki/外部ライブラリ/{名前}.md` で管理（本ページで重複させない）

**上流ドキュメントリンク:**
- サービス見出し直下の説明文中に、対応する外部ライブラリ / 外部API Wiki への相対リンクを貼る（例: `[ライブラリ名](../../外部ライブラリ/{ライブラリ名}.md) の設定 ...`）
- 上流 Wiki が未整備の場合は空欄で OK（整備されたタイミングでリンクを埋める）

## `## {Dockerfile 名}`

自プロジェクトで Dockerfile をビルドするサービスがある場合のみ書く。
1 Dockerfile = 1 セクション。
ビルド処理をユーザーが上から辿れるように **番号付きで箇条書き** する（モジュール構成テンプレの「処理」節と同じスタイル）。

### 記述例

````markdown
## Dockerfile（custom-collector）
> ファイル: `./collector/Dockerfile`
> ベースイメージ: `otel/opentelemetry-collector-contrib:0.113.0`

社内独自 receiver を組み込んだカスタム OTel Collector イメージのビルド。

1. ベースイメージ `otel/opentelemetry-collector-contrib:0.113.0` から出発
2. `apt-get install -y ca-certificates` で証明書を追加
3. `COPY ./receivers/custom_receiver.so /etc/otelcol-contrib/receivers/` で独自 receiver をコピー
4. `COPY ./config.yaml /etc/otelcol-contrib/config.yaml` で既定設定をコピー
5. `USER 10001` で非 root ユーザーに切り替え
6. `ENTRYPOINT ["/otelcol-contrib", "--config=/etc/otelcol-contrib/config.yaml"]` を上書き
````

### 補足

**冒頭 blockquote:**
- `> ファイル: `{Dockerfile のパス}`` を書く
- 必要なら `> ベースイメージ: `{タグ}`` も併記

**処理:**
- 番号付き箇条書きで **上から順に何をするか** を書く
- 各ステップは 1 行で要約し、Dockerfile 実物の行番号との対応が取れる粒度にする
- 実際の Dockerfile の全文は書かない（実ファイルで見られるため）

**独立ページ化のタイミング:**
- **同一 Dockerfile を複数の Docker Compose（スタック）から共有する場合**は、独立ページ `docs/wiki/設計図/コンテナ構成/{名前}.dockerfile.md` として切り出す
- 独立ページの場合も本テンプレの Dockerfile セクションと同じ書式（冒頭 blockquote + 番号付き処理）で書く
- 参照側の Docker Compose ページは `ビルド` セルから相対リンクで参照する
