# モックの応答ループ

モックの待機中に来たユーザーフィードバックに応じてモック HTML を修正 push し、再び待機に入る。

## 手順

### 内容に応じた対応

| フィードバックの種別 | 対応 |
| --- | --- |
| 特定画面のレイアウト・要素の修正 | 該当 HTML を修正して push |
| 遷移リンクの修正 | 該当 HTML の遷移リンクを修正して push |
| 共通コンポーネントの修正 | `docs/mock/components/` を修正して push（利用画面すべてに反映される） |
| 質問への回答 | 回答内容だけ返信追記（本文・HTML は触らない） |

修正内容はユーザーがその指摘を書いたコメントに返信追記する（規約『コメント』の「どのコメントに返信するか」）。
自分が過去に投稿したモック URL コメントに積み増さない。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: ユーザーが指摘を書いたコメントの node_id
- `sender`: `mock-designer`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 修正内容の要約（URL は変わらないため再共有不要）

### タスク一覧のチェック

モックを修正して push した場合だけ実行する。

親 epic PR 本文の `## タスク一覧` のうち、自分が作成したモックの行が未チェックなら `[x]` にする。
チェックを入れるのは作業した本人なので、シナリオ・E2E テストの行には触れない。
待機を挟むと、ユーザーが開いたときに push 済みなのに未チェックの状態になる。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### 決着したスレッドの Resolve

インライン確認事項のスレッドを 1 件ずつ見て、この往復で内容が確定したものだけを畳む。

MCP `list_review_threads` を呼ぶ:
- `pr_number`: 対象 PR の番号
- `addressee`: 自分のエージェント名
- `include_resolved`: false

スレッドごとに、ユーザーの返信（`thumbs_up_by` に本人が入っていれば推奨案への同意とみなす）で論点が決まったかを判断する。

- 決まった場合、MCP `reply_review_thread` で確定内容を返信してから MCP `resolve_review_threads` で畳む
- 決まっていない場合（回答がない・回答だけでは実装を決められない）は畳まず、次の「未決着スレッドの再確認」へ持ち越す

### 未決着スレッドの再確認

畳めなかったスレッドが 1 件も無い場合、本手順は実行しない。

残っている場合は、何が未回答かを名指しした確認コメントを MCP `comment` で投稿する:
- `number`: 対象 PR の番号
- `is_pr`: true
- `sender`: 自分のエージェント名
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 未決着スレッドの一覧（各スレッドへのリンク + 何が決まっていないか + 選べる案）

続けて MCP `add_labels` で `$AI_MONITOR_LABEL_IN_DISCUSSION` の値を付ける（既に付いていれば冪等）。
ユーザーが `議論中` を外して完了へ進めようとした場合でも、決めきれていない論点が残っていればここで議論に戻す。

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `mock-designer`
- `number`: $pr_number
