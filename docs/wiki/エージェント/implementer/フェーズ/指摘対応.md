# 指摘対応

architect のインライン指摘に沿って実装を修正し、同じスレッドに返信して再レビューに戻す。

## 手順

### 指摘の取得

MCP `list_review_threads` を呼ぶ:
- `pr_number`: $pr_number
- `include_resolved`: false

各スレッドの `path` / `line` / `diff_hunk` / 本文から、指摘対象の箇所と期待する修正を把握する。

### 実装の修正

subsystem ブランチの worktree へ移動し、指摘 1 件ずつ修正する。

修正のたびにテストを実行し、全テストが Green のままであることを確認して commit push する。

- 指摘の内容が設計 Wiki の見直しを要する場合、「実装」の「設計の差し戻し」を実行して自ターンを終える（以降の手順は実行しない）

### テスト結果表の更新

テストの増減や結果が変わった場合、subsystem PR 本文のテスト結果表を実態に合わせる。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### 対応依頼への返信

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: architect の対応依頼コメントの node_id
- `sender`: `implementer`
- `receiver`: `architect`
- `body`: 修正完了の報告（指摘ごとの対応内容 + テストの実行結果（全 Green）+ 積んだ commit の表。commit の書式は共通ルール『コミット報告』）

### ラベル遷移

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_IMPLEMENTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `implementer`
- `number`: $pr_number
