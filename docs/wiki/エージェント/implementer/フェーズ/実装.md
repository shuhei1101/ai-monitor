# 実装

タスク一覧の実装タスクを消化して Red のテストを Green にし、テスト結果表を埋めて Draft を解除する。

## 手順

### 割り当て内容の確認

architect の割り当てコメント（または設計修正後の再開指示）から、Red のテストファイル一覧と実装の根拠になる設計 Wiki のページ名を読む。

### 設計 Wiki とテストの確認

subsystem ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は subsystem PR の `head_ref`）へ移動して最新化する。

割り当てられた設計 Wiki（ER図 / 画面構成 / 結合 / モジュール構成）と Red のテストコードを読み、実装する対象と期待される振る舞いを把握する（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。
モジュール構成の `#### 処理` の各ステップは、実装側でコメントとして関数内に入れる。

再開指示で起動した場合は、修正 commit の内容を取り込んだうえで対象を洗い直す（差分の取得は共通ルール『PR差分の取得』）。

### 実装

subsystem PR 本文の `## タスク一覧` の実装タスクを上から順に消化し、区切りごとに commit push する。
各 commit の後にテストを実行し、全テストが Green になるまで繰り返す。

- メソッドシグネチャの変更・複数関数に重複する処理の共通化など設計判断が必要になった場合、または解消できないテスト失敗が残る場合、「設計の差し戻し」を実行して自ターンを終える（以降の手順は実行しない）

### テスト結果表の記入

テスト結果表（`## 単体テスト結果` / `## 結合テスト結果` / `## 単一ユースケースシナリオテスト結果` / `## 複合ユースケースシナリオテスト結果`）の結果列を実行結果で埋める（`✅` / `❌`）。
tester が追加した行に加え、実装で増えたテストがあれば行を足す。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### Draft 解除

MCP `mark_pr_ready` を呼ぶ:
- `pr_number`: $pr_number

### 差し戻しスレッドの Resolve

再開指示で起動した場合に実行する（設計修正の反映が済んで対応が確定したため）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分が投稿した差し戻し報告コメントの node_id

### architect への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `implementer`
- `receiver`: `architect`
- `body`: 実装の完了報告（消化した実装タスク + テストの実行結果（全 Green）+ 積んだ commit の表。commit の書式は共通ルール『コミット報告』）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_IMPLEMENTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

「作業完了報告」へ進む。

### 設計の差し戻し

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `implementer`
- `receiver`: `architect`
- `body`: 差し戻し報告（設計 Wiki のどの記述が実装として成立しないか + 理由 + 想定する修正の方向。解消できないテスト失敗の場合は失敗内容と調査結果）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_IMPLEMENTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `implementer`
- `number`: $pr_number
