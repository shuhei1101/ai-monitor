# 実装

確定済みの設計 Wiki（結合 / モジュール構成）のとおりに実装コードを書いて architect に報告する。
テストの実行・テスト結果表の記入・Draft 解除は architect の領分。

## 手順

### 割り当て内容の確認

architect の割り当てコメント（または設計修正後の再開指示）から、実装の根拠になる設計 Wiki のページ名と、そのページを作成 / 更新した commit 範囲を読む。

### 設計 Wiki とテストの確認

subsystem ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は subsystem PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

割り当てられた設計 Wiki（ER図 / 画面構成 / 結合 / モジュール構成）と commit 済みのテストコードを読み、実装する対象と期待される振る舞いを把握する（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。
モジュール構成の `#### 処理` の各ステップは、実装側でコメントとして関数内に入れる。

あわせて渡された commit 範囲の差分を取り、今回新規に定義された構成要素と既存から変更された構成要素を区別する（差分の取得は共通ルール『PR差分の取得』）。
新規は実装を書き起こし、変更は既存実装の改修になる。

### 実装

設計 Wiki の構成要素（コンテナ・物理名・依存方向）のとおりに実装コードを書き、区切りごとに commit push する（テストの実行は architect が行うので、ここでは実行しない）。

- メソッドシグネチャの変更・複数関数に重複する処理の共通化など、設計 Wiki だけでは決まらない判断が必要になった場合、「設計の差し戻し」を実行して自ターンを終える（以降の手順は実行しない）

### タスク一覧のチェック

subsystem PR 本文の `## タスク一覧` のうち、自分が実装した行を `[x]` にする。
チェックを入れるのは作業した本人なので、設計・テスト作成・テスト実行の行には触れない。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### インラインコメントの投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って確認事項と補足事項を該当行へ投稿する。

### 差し戻しスレッドの Resolve

再開指示で起動した場合に実行する（設計修正の反映が済んで対応が確定したため）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分が投稿した差し戻し報告コメントの node_id

### 依頼コメントの Resolve

起動のトリガーになった依頼 / 割り当てコメント（再開指示で起動した場合は再開指示コメント）を畳む。
受け取った依頼は自分の作業が終わった時点で片付ける（ユーザーが読む必要はなく、未解決のまま溜めない）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 初期処理で取得した、起動のトリガーになった依頼コメントの `node_id`

- 依頼コメントを伴わずに確認ラベルだけで起動した場合は、本手順を実行しない

### architect への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `implementer`
- `receiver`: `architect`
- `format`:
  - `type`: `commits`
  - `body`: 実装の完了報告（実装した構成要素 + 元にした設計ページ）
  - `entries`: 積んだ commit の `commit` と `summary` の組

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_IMPLEMENTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

「作業完了報告」へ進む。

### 設計の差し戻し

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `implementer`
- `receiver`: `architect`
- `format`:
  - `type`: `plain`
  - `body`: 差し戻し報告（設計 Wiki のどの記述が実装として成立しないか + 理由 + 想定する修正の方向）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_IMPLEMENTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `implementer`
- `number`: $pr_number
