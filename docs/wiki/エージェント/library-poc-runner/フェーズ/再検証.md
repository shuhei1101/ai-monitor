# 再検証

発注元が追加した検証観点を実行し、結果を PoC PR 本文へ追記して発注元へ報告する。

## 手順

### 再検証指示の確認

再検証指示コメントから、追加する検証観点とその成功条件を読む。
既に記入済みの `## 検証観点と結果` と `## 最小再現コード` を読み、初回検証で作った PoC コードのどこを流用できるかを把握する。

### 追加検証の実行

PoC ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は PoC PR の `head_ref`）へ移動して最新化する。

追加観点の実測に必要なコードを足して commit push し、実行して実測値を収集する（ターミナルへの報告は共通ルール『ターミナル出力』）。

### 結果の追記

`## 検証観点と結果` に追加観点の行を足し、実測値・判定（`✅` / `❌`）・所感を記入する。
PoC コードを足した場合は `## 最小再現コード` にも反映する。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### 再検証指示の Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 再検証指示コメントの node_id

### 発注元への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `library-poc-runner`
- `receiver`: 再検証指示コメントの送信者
- `body`: 再検証の完了報告（追加観点の実測値と判定 + 所感 + 積んだ commit の表。commit の書式は共通ルール『コミット報告』）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_LIBRARY_POC_RUNNER` の値
- `add_labels_`:
  - 発注元が architect なら `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `library-poc-runner`
- `number`: $pr_number
