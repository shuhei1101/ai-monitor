# テスト結果の判定

single-scenario-tester の実行報告を受けて、全 pass なら story-conductor へ完了報告し、fail なら原因をトリアージして差し戻し先を決める。

## 手順

### 結果の確認

story PR 本文の `## 単一ユースケースシナリオテスト結果` と実行報告コメントを照合する。

分岐:

- 全行が `✅` の場合、「全 pass の完了報告」へ進む
- `❌` がある場合、「fail のトリアージ」へ進む（「全 pass の完了報告」は実行しない）

### 全 pass の完了報告

MCP `resolve_comments` を呼ぶ:
- `node_ids`: single-scenario-tester の実行報告コメントの `node_id`

続けて MCP `comment` を呼ぶ:
- `number`: 親 story Issue 番号（story PR 本文の `## 紐づく Issue` から取得）
- `is_pr`: false
- `sender`: `single-scenario-writer`
- `receiver`: `story-conductor`
- `body`: 統合テストの完了報告（実行したテストの一覧と全 pass の結果）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 story Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値

「ラベル除去」へ進む。

### fail のトリアージ

失敗したケースの内容を単一 UC シナリオ・実装コード・E2E テストコードと照合し、原因を 3 つのいずれかに判定する。

| 判定 | 根拠 | 対応 |
| --- | --- | --- |
| 実装側の問題 | シナリオもテストコードも正しく、実装が期待値を満たしていない | 「実装側の問題の報告」へ進む |
| シナリオ側の問題 | シナリオの期待値が実装すべき要件と矛盾している | 「シナリオ側の問題の修正」へ進む |
| テストコード側の問題 | シナリオも実装も正しく、テストコードが誤っている | 「テストコード側の問題の差し戻し」へ進む |

### 実装側の問題の報告

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: single-scenario-tester の失敗報告コメントの node_id
- `sender`: `single-scenario-writer`
- `receiver`: `single-scenario-tester`
- `body`: トリアージ結果（実装側の問題と判定した根拠）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: single-scenario-tester の失敗報告コメントの `node_id`

続けて MCP `comment` を呼ぶ:
- `number`: 親 story Issue 番号
- `is_pr`: false
- `sender`: `single-scenario-writer`
- `receiver`: `story-conductor`
- `body`: 失敗報告（fail 内容の要約 + 該当するシナリオ + 元報告コメントへのリンク）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 story Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値

「ラベル除去」へ進む。

### シナリオ側の問題の修正

story ブランチの worktree で単一 UC シナリオを修正して commit push する。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: single-scenario-tester の失敗報告コメントの node_id
- `sender`: `single-scenario-writer`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `body`: 修正内容（修正したシナリオページ名 + 修正 commit の ID）と確認依頼

続けて MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

`確認:single-scenario-writer` は除去しない（承認後の再開指示で復帰するため）。
「作業完了報告」を実行して自ターンを終える（「ラベル除去」は実行しない）。

### テストコード側の問題の差し戻し

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: single-scenario-tester の失敗報告コメントの node_id
- `sender`: `single-scenario-writer`
- `receiver`: `single-scenario-tester`
- `body`: テストコードの誤りの指摘と、修正 + 再実行の再開指示（スレッドは Resolve しない = tester が処理時に Resolve する）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_WRITER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_TESTER` の値

「作業完了報告」を実行して自ターンを終える（「ラベル除去」は実行しない）。

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_WRITER` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `single-scenario-writer`
- `number`: $pr_number
