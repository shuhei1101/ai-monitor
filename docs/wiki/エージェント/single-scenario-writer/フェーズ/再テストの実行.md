# 再テストの実行

バグ修正後に再委任された統合テストについて、レビュー済みのテストをそのまま再実行して結果を判定する。

## 手順

### テストの再実行

story ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は story PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

`テスト/テスト実行方法.md` のコマンドで、テスト結果表の全行（新規 + 回帰）を再実行する。

実行結果でテスト結果表の結果列を更新する。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

分岐:

- 全行が `✅` の場合、「タスク一覧のチェック」へ進む
- `❌` がある場合、「統合テストレビュー」の「fail のトリアージ」以降を実行して自ターンを終える（以降の手順は実行しない）

### タスク一覧のチェック

story PR 本文の `## タスク一覧` の E2E テスト実行の行を `[x]` にする（実行したのは自分）。
本手順の後に全行がチェック済みになるので、未チェックの行が残っていないかも併せて確認する。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- 他人の担当行が未チェックで残っている場合、その担当への完了報告コメントに追記して指摘し、チェックを入れてもらう（自分では入れない）

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### 全 pass の完了報告

MCP `comment` を呼ぶ:
- `number`: 親 story Issue 番号（story PR 本文の `## 紐づく Issue` から取得）
- `is_pr`: false
- `sender`: `single-scenario-writer`
- `receiver`: `story-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 統合テストの完了報告（再実行したテストの一覧と全 pass の結果）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 story Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_WRITER` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `single-scenario-writer`
- `number`: $pr_number
