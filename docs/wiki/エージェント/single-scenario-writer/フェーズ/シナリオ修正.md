# シナリオ修正

story-conductor のエスカレーション対応で決まった方針に沿って単一ユースケースシナリオを修正し、親 story PR へ完了報告する。

## 手順

### 修正指示の確認

修正指示コメントから、決定した方針とシナリオのどこをどう直すかを読む。

### シナリオファイルの修正

成果物ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

対象の単一ユースケースシナリオを修正する。
索引の記述が変わる場合は `docs/wiki/設計図/シナリオ/README.md` も更新する。

修正したファイルを commit + push する。

### タスク一覧のチェック

成果物 PR 本文の `## タスク一覧` のうち、自分が作成 / 更新した単一 UC シナリオとシナリオ索引の行を `[x]` にする。
commit を積んだ直後に入れる（待機を挟むと、ユーザーが開いたときに commit 済みなのに全行未チェックの状態になる）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### 修正指示への返信

この返信が story-conductor への修正完了報告になる。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: story-conductor の修正指示コメントの node_id
- `sender`: `single-scenario-writer`
- `receiver`: `story-conductor`
- `format`:
  - `type`: `commits`
  - `body`: 修正内容（修正したシナリオページ名）
  - `entries`: 積んだ commit の `commit` と `summary` の組

スレッドは Resolve しない（規約『コメント』の「手番を渡したスレッドは Resolve しない」）。
畳むと受け取る側の `list_comments` に出ず、story-conductor が起動条件を満たさなくなる。

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_WRITER` の値
- `add_labels_`: なし

### 親 story PR への完了報告

初期処理で取得した `parent` から親 story PR 番号を得る。

MCP `comment` を呼ぶ:
- `number`: 親 story PR 番号
- `is_pr`: true
- `sender`: `single-scenario-writer`
- `receiver`: `story-conductor`
- `format`:
  - `type`: `commits`
  - `body`: エスカレーション対応で指示されたシナリオ修正の完了報告（修正したシナリオページ名 + 反映した方針）
  - `entries`: 積んだ commit の `commit` と `summary` の組

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 story PR 番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `single-scenario-writer`
- `number`: $pr_number
