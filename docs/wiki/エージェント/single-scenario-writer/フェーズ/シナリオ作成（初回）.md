# シナリオ作成（初回）

親 story PR の `## ユースケース要件` から単一ユースケースシナリオを設計し、成果物ブランチに commit + 索引更新 push した上で待機に入る。

## 手順

### 親 story PR の確認


初期処理で取得した `parent`（base ブランチを head に持つ親 story PR）の番号で MCP `get_issue_or_pr` を呼ぶ:
- `number`: 親 story PR 番号
- `is_pr`: true
- `comments`: false

成果物 PR 本文の `## ユースケース要件` と `## 背景` を読み、対象 UC の名前（story タイトル = 親 epic の `## ユースケース一覧` の UC 名 = 単一UC ファイル名）と要件・関連する epic 横断要件を把握する。

### シナリオファイルの新規作成


テンプレート（シナリオ）に従い、`docs/wiki/設計図/シナリオ/単一ユースケース/{UC名}.md` を新規作成する（`{UC名}` は story タイトル）。

- 冒頭リードに対応エージェント（該当する場合）と対応テストファイル行のプレースホルダを置く
- 正常シナリオ + 起こりうる異常シナリオを H2 で並列に書く
- 各シナリオは `### セットアップ` / `### フロー` / `### 期待値` の 3 サブセクション構成
- フロー図の粒度は「ユーザーの 1 操作 → サブシステム貫通」。1 UC の内部で結合を跨いだ流れを sequenceDiagram で描く

### 索引の更新


`docs/wiki/設計図/シナリオ/README.md` の索引に行を追加する（種別カラム = `単一ユースケース`）。

### commit + push


成果物ブランチの worktree（`.claude/worktrees/{ブランチ名}` = `${BRANCH}` を `/` → `-` 置換したパス）で以下を実行する:

- `git add docs/wiki/設計図/シナリオ/単一ユースケース/{UC名}.md docs/wiki/設計図/シナリオ/README.md`
- `git commit -m "{UC名}単一シナリオを追加"`
- `git push`

### タスク一覧のチェック

成果物 PR 本文の `## タスク一覧` のうち、自分が作成 / 更新した単一 UC シナリオとシナリオ索引の行を `[x]` にする。
チェックを入れるのは作業した本人なので、E2E テストの行には触れない。
commit を積んだ直後に入れる（待機を挟むと、ユーザーが開いたときに commit 済みなのに全行未チェックの状態になる）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### 確認事項の投稿


確認したい論点を洗い出し、1 論点 = 1 コメントで投稿する。
投稿先は論点がシナリオの特定箇所に紐づくかで分ける。

特定の記述についての判断（期待値の置き方・異常シナリオの切り出し方 等）は、論点 1 件ごとに MCP `create_review_comment` を呼ぶ:
- `pr_number`: $pr_number
- `path`: 対象シナリオのパス
- `line`: 論点にあたる行
- `sender`: `single-scenario-writer`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `body`: その行で選んだ内容 + 他に取り得た選択肢 + 推奨（いま書いてある案）と理由

シナリオに紐づかない全体の方向性（UC の粒度・他 UC との境界 等）は、論点 1 件ごとに MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `single-scenario-writer`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 論点 + 他に取り得た選択肢 + 推奨と理由

### 補足事項の投稿


commit した内容を読み返し、共通ルール『インラインコメント』に沿って補足事項を該当行へ投稿する。

### 議論中 付与 + 待機


MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告


MCP `report_completion` を呼ぶ:
- `agent_name`: `single-scenario-writer`
- `number`: $pr_number
