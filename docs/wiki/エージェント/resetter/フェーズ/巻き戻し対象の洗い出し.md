# 巻き戻し対象の洗い出し

対象 Issue の配下にある成果物を再帰的に洗い出し、削除範囲の確認を依頼して待機に入る。

## 手順

### 子孫 Issue の走査

初期処理で取得した `sub_issues` を起点に、各子 Issue へ MCP `get_issue_or_pr`（`sub_issues`: true）を再帰的に呼び、孫以下まで辿って一覧にする。

### 紐づく PR とブランチの特定

MCP `search_issues_and_prs` を呼ぶ:
- `query`: 対象 Issue と各子孫 Issue の番号を含む open / closed の PR を引く検索式

見つかった PR の `head_ref` から、削除対象のリモートブランチ・ローカルブランチ・worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`）を割り出す。
ライブラリ選定を経ている場合は `poc/` 始まりのブランチも対象に含める。

### 巻き戻し対象一覧の投稿

MCP `comment` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `sender`: `resetter`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `plain`
  - `body`: 巻き戻し対象の一覧（子孫 Issue / PR / ブランチ / worktree を種別ごとの表で。story にマージ済みの subsystem の commit もブランチごと消える点を明記）と、残したいものがあれば指示してほしい旨

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `resetter`
- `number`: $issue_number
