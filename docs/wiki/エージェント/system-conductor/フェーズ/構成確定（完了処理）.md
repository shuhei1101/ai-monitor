# 構成確定（完了処理）

承認された構成要件をもとに system Draft PR を作成し、system-architect に土台生成を引き渡す。

## 手順

### 自分宛コメントの選別

未回答・未対応の自分宛コメントが残る場合は「応答ループ」に戻ってユーザーに確認質問を投げる（以降の手順は実行しない）。

### 一括 Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: system Issue の自分宛コメントの `node_id` 配列

### Draft PR の作成

system Issue の本文から決めたドメイン名で system ブランチを組み立てる。

MCP `worktree_create` を呼ぶ:
- `branch`: `docs/system/{ドメイン}`
- `base_ref`: `origin/master`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: `master`
- `title`: system Issue のタイトル
- `body`: `## 紐づく Issue`（`- #$issue_number`）と `## タスク一覧`
- `labels`: `$AI_MONITOR_LABEL_LAYER_SYSTEM` の値

`## タスク一覧` は構成要件から、アーキテクチャ図・`docs/wiki/` 骨格・`docs/rules.yaml`・`README.md`・GitHub ラベル一括作成の To Do をチェックボックスで列挙する（テンプレート「PR本文/システム」の記述例に準拠）。

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `system-conductor`
- `number`: $issue_number
- `watch_numbers`: 作成した PR の番号

### 土台生成の依頼

MCP `comment` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `sender`: `system-conductor`
- `receiver`: `system-architect`
- `format`:
  - `type`: `plain`
  - `body`: 土台生成の依頼（確定した構成要件の要約 + タスク一覧の場所 + 生成後に完了報告を返す旨）

続けて MCP `add_labels` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_SYSTEM_ARCHITECT` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SYSTEM_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `system-conductor`
- `number`: $issue_number
