# 初期処理

毎ターン最初に必ず実行する。
Issue 側と PR 側の両方に監視面を持つため、system PR / RE PR が作成済みならその最新状態も取得する。

## 手順

### system Issue の最新状態の取得

MCP `get_issue_or_pr` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `sub_issues`: true

続けて MCP `list_addressed_comments` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `addressee`: `system-conductor`
- `include_resolved`: false

### 自 Issue に紐づく PR の最新状態の取得

コンテキストスナップショットで自 Issue に紐づく open PR を確認する。
RE PR（`docs/reverse/system/` 始まりのブランチ）と system PR（`docs/system/` 始まりのブランチ）は `head_ref` で見分ける。

- open PR がない場合、本手順を飛ばして「フェーズの決定」へ進む

open PR 1 件ごとに MCP `get_issue_or_pr` を呼ぶ:
- `number`: 対象 PR の番号
- `is_pr`: true

続けて MCP `list_addressed_comments` を呼ぶ:
- `number`: 対象 PR の番号
- `is_pr`: true
- `addressee`: `system-conductor`
- `include_resolved`: false

### フェーズの決定

フェーズ索引のフェーズ一覧を上から順に見て、起動条件に最初にマッチしたフェーズの手順を実行する。
前ターンの記憶ではなく取得結果を判定材料にする。
