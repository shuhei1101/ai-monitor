# 初期処理

毎ターン最初に必ず実行する。
Issue 側と PR 側の両方に監視面を持つため、system PR / RE PR が作成済みならその最新状態も取得する。

## 手順

### system PR の最新状態の取得

MCP `get_issue_or_pr` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `sub_issues`: true

続けて MCP `list_comments` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `addressee`: `system-conductor`
- `include_resolved`: false

### 自 Issue に紐づく PR の最新状態の取得

コンテキストスナップショットで自 Issue に紐づく open PR を確認する。
RE PR（`docs/reverse/system/` 始まりのブランチ）と system PR（`docs/system/` 始まりのブランチ）は `head_ref` で見分ける。

- open PR がない場合、本手順を飛ばして「フェーズの決定」へ進む

open PR 1 件ごとに MCP `get_issue_or_pr` を呼ぶ:
- `number`: 対象 PR の番号
- `is_pr`: true

続けて MCP `list_comments` を呼ぶ:
- `number`: 対象 PR の番号
- `is_pr`: true
- `addressee`: `system-conductor`
- `include_resolved`: false

### closed 対象の終了判定

取得結果の `state` が `closed` の場合、着手せず自ターンを終える（規約『フェーズ索引の網羅』）。
本文・コメントには手を加えない。

MCP `transition_phase` を呼ぶ:
- `number`: closed だった対象の番号
- `is_pr`: 対象が PR なら true
- `remove_labels_`:
  - 自分の確認ラベル（`AI_MONITOR_LABEL_CONFIRM_*`）の値
  - 自分の処理中ラベル（`AI_MONITOR_LABEL_PROCESSING_*`）の値

続けて MCP `report_completion` を呼び、以降の手順は実行しない。

- `state` が `open` の場合、「フェーズの決定」へ進む

### フェーズの決定

フェーズ索引のフェーズ一覧を上から順に見て、起動条件に最初にマッチしたフェーズの手順を実行する。
前ターンの記憶ではなく取得結果を判定材料にする。
