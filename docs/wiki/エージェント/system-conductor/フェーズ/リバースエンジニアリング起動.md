# リバースエンジニアリング起動

RE ブランチと RE PR を作り、architecture-reverse-engineer に現状のアーキテクチャ図の作成を依頼する。
構成確定より前に通す工程で、実装コードを読むのは依頼先だけに絞る。

## 手順

### ラベルの付与

MCP `add_labels` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_LAYER_SYSTEM` の値
  - `$AI_MONITOR_LABEL_TYPE_DOCS` の値

### 起こす対象の決定

system Issue の本文から対象リポジトリのドメイン名を決め、起こしてもらう範囲（リポジトリ全体のアーキテクチャ図 + 機能の洗い出し）を確定する。

### RE ブランチと RE PR の作成

MCP `worktree_create` を呼ぶ:
- `branch`: `docs/reverse/system/{ドメイン}`
- `base_ref`: `origin/master`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: `master`
- `title`: 現状アーキテクチャ図の起こし
- `body`: `## 紐づく Issue`（`- #$issue_number`）と `## タスク一覧`（起こす対象ページのチェックボックス）

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `system-conductor`
- `number`: $issue_number
- `watch_numbers`: 作成した RE PR の番号

### 作成依頼

MCP `comment` を呼ぶ:
- `number`: 作成した RE PR の番号
- `is_pr`: true
- `sender`: `system-conductor`
- `receiver`: `architecture-reverse-engineer`
- `format`:
  - `type`: `plain`
  - `body`: 起こす対象（`設計図/アーキテクチャ図.md`）と担当範囲（リポジトリ全体）+ 完了報告に機能の洗い出しを添える依頼

続けて MCP `add_labels` を呼ぶ:
- `number`: 作成した RE PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECTURE_REVERSE_ENGINEER` の値
  - `$AI_MONITOR_LABEL_REVERSE_ENGINEERING` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `system-conductor`
- `number`: $issue_number
