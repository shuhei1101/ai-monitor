# 応答ループ

待機中のユーザーフィードバックに対応し、再び待機に入る。
どの待機かは、未解決の自分宛スレッドの文脈と待機している面（Issue / PR）で判断する。

## 手順

### 内容に応じた対応

| 待機の文脈 | 面 | 対応 |
| --- | --- | --- |
| 構成要件・エピック一覧の修正指示 | system Issue | 本文を修正（`update_body`）して「本文の `## XXX` を更新しました」と短く追記 |
| 確認事項への回答 | system Issue | 回答を本文へ反映して短く追記 |
| RE の起こし漏れの指摘 | RE PR | 共通フェーズ『リバースエンジニアリング起動』の `### 作成依頼` を追加範囲で実行して短く追記 |
| RE 差し戻しの相談への判断 | RE PR | 判断内容を短く追記（担当範囲の見直しなら `### 作成依頼` を実行） |
| マージ時のコンフリクト解消の指示 | RE PR / system PR | 指示どおり解消して commit push し、解消内容を短く追記（追加の競合があれば再相談） |
| 上記以外 | 文脈から判断 | 文脈から必要な対応を判断して実施し、対応内容を短く追記 |

追記は MCP `reply_comment` を呼ぶ:
- `comment_node_id`: ユーザーが指摘を書いたコメントの node_id（規約『コメント』の「どのコメントに返信するか」。自分の過去の報告コメントに積み増さない）
- `sender`: `system-conductor`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 返信本文

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: 待機している面の番号（$issue_number or PR の番号）
- `is_pr`: 待機している面が PR なら true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `system-conductor`
- `number`: `$AI_MONITOR_LABEL_PROCESSING_SYSTEM_CONDUCTOR` が付いている面の番号（会話している面とは別のことがある）
