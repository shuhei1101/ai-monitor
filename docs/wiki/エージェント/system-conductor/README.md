# system-conductor

判定は毎ターン、最新の取得結果（本文・ラベル・自分宛の未解決コメント）を材料に、上から順に見て最初にマッチしたフェーズを 1 つ実行する。
監視面は 立ち上げ Issue（構成確定の起点）と system PR（構成確定・子epicPR作成）と 土台生成の成果物 PR（受領とマージ）と RE PR（現状のアーキテクチャ図の起こし）の 4 つで、起動条件の「本文」「ラベル」はフェーズごとに対象の面のものを見る。
立ち上げ Issue は system PR を作るまでの入口で、PR を作った時点で確認ラベルを PR へ移す。
`リバースエンジニアリング` ラベルが付いている場合だけ RE 系のフェーズを通り、構成確定はその後に始まる。

## リバースエンジニアリングの担当範囲

共通フェーズ中の記号は下表の値に読み替える。
`リバースエンジニアリング` ラベルが付いた system PR でだけ RE 系のフェーズを通る。

| 項目 | 値 |
| --- | --- |
| `{自分}` | `system-conductor` |
| `{依頼先}` | `architecture-reverse-engineer` |
| `{RE ブランチ}` | `docs/reverse/system/{ドメイン}` |
| `{base}` | system ブランチ |
| `{起こす範囲}` | リポジトリ全体 |
| `{成果物}` | `設計図/アーキテクチャ図.md` + 機能の洗い出し（完了報告コメント） |
| 依頼先の確認ラベル | `$AI_MONITOR_LABEL_CONFIRM_ARCHITECTURE_REVERSE_ENGINEER` |
| `{レイヤーラベル}` | `$AI_MONITOR_LABEL_LAYER_SYSTEM` |
| `layer:*` / `type:*` の付与 | 必要（`$AI_MONITOR_LABEL_LAYER_SYSTEM` + `$AI_MONITOR_LABEL_TYPE_DOCS`。ユーザーが直接起票するため） |
