# 応答ループ

待機中のユーザーフィードバックに対応し、再び待機に入る。
どの待機（内容確認・マージ衝突の解消）かは、未応答のユーザー発言が付いた自分宛スレッドの文脈で判断する。

## 手順

### 内容に応じた対応

| 待機の文脈 | 対応 |
| --- | --- |
| 修正内容への指示 | worktree で修正して commit push し、積んだ commit の表を追記 |
| マージ衝突の解消方針の指示 | 指示された方針で衝突を解消して commit push し、解消内容と commit の表を追記 |
| 変更範囲への質問 | 変更した箇所とその理由を追記（本文・コードは触らない） |

追記は MCP `reply_comment` を呼ぶ:
- `comment_node_id`: 返信対象コメントの node_id
- `sender`: `quick-implementer`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `commits`
  - `body`: 返信本文
  - `entries`: 積んだ commit の `commit` と `summary` の組

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `quick-implementer`
- `number`: $issue_number
