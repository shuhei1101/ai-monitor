# 要件確定（完了処理）

承認された要件をもとに、PoC 要否・画面変更有無・複合ユースケースへの影響の回答に応じて Draft PR を作成し、次フェーズの担当へ引き継ぐ。

複合ユースケースへの影響がない場合は本フェーズに入らない（作る成果物 PR が無く、実行できる手順が 1 つも無いため）。
`確認:epic-conductor` を保持したまま「子storyPR作成」へ進む（判定フローチャート（レイヤー）の「複合シナリオを更新せず story を起票」）。

## 手順

### 自分宛コメントの選別

未回答・未対応の自分宛コメントが残る場合は「応答ループ」に戻ってユーザーに確認質問を投げる（以降の手順は実行しない）。

### 一括 Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分宛コメントの `node_id` 配列

### 親 system PR への申し送り

要件確定の過程で親 system PR の `## 構成要件` に関わる決定が出た場合だけ実行する（`## 構成要件` は system-conductor しか更新できない）。
ユーザーとの議論は本 epic で決着しているため `議論中` は付けない。

初期処理で取得した `parent` から親 system PR 番号を得る（親が無ければ本手順は実行しない）。

MCP `comment` を呼ぶ:
- `number`: 親 system PR 番号
- `is_pr`: true
- `sender`: `epic-conductor`
- `receiver`: `system-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 反映してほしい構成要件の内容 + 決着の経緯（本 epic PR へのリンク）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 system PR 番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_SYSTEM_CONDUCTOR` の値

### 成果物 Draft PR の作成

自分の epic PR は既に存在するので新しく作らない。
要件確定で確定した回答に応じて、次の担当が作業する成果物ブランチ + Draft PR を 1 本作る。

| 回答 | 作るブランチ | title | 次の担当 |
| --- | --- | --- | --- |
| PoC 必要 | `poc/epic/{ドメイン}/{検証テーマ}` | `PoC: {検証テーマ}（epic #$number）` | epic-poc-runner |
| PoC 不要・画面変更あり | `docs/epic/{ドメイン}/mock` | `{epic のタイトル}（モック）` | mock-designer |
| PoC 不要・画面変更なし・複合 UC 影響あり | `docs/epic/{ドメイン}/scenario` | `{epic のタイトル}（複合ユースケースシナリオ）` | complex-scenario-writer |
| PoC 不要・画面変更なし・複合 UC 影響なし | 作らない | - | 自分（次ターンで「子storyPR作成」へ） |

MCP `worktree_create` を呼ぶ:
- `branch`: 上表のブランチ
- `base_ref`: `origin/{自分の epic ブランチ}`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: 自分の epic ブランチ
- `title`: 上表の title
- `body`: `## 紐づく Issue`（`- #$number`）と `## タスク一覧`
- `labels`: `$AI_MONITOR_LABEL_TYPE_DOCS` の値

`## タスク一覧` はその成果物の To Do をチェックボックスで列挙する（書式はテンプレート「PR本文/成果物」。モックは「PR本文/モック」）。

| 成果物 | 並べる行 |
| --- | --- |
| モック | 画面ごとのモック作成・画面一覧と画面遷移の記入 |
| 複合UCシナリオ | 作成 / 更新する複合 UC シナリオのページ・シナリオ索引の更新 |
| PoC | 検証構成の実装・検証の実行・結果の記入 |

チェックは各行を担当した作業者が入れるので、ここでは全行を未チェックで作る。
複合 UC E2E テストの作成 / 実行は、後続で切る `test/epic/{ドメイン}/integration` の成果物 PR が持つ。

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $number
- `watch_numbers`: 作成した PR の番号

### 次フェーズの割り当て

分岐ごとに、指示コメントの投稿（MCP `comment`・`is_pr`: true）を済ませてから、作成した PR に次の確認ラベルを付与する（MCP `add_labels`・`is_pr`: true）。

| 分岐 | 先に投稿する指示コメント | 後に付与するラベル |
| --- | --- | --- |
| PoC 必要 | `receiver`: `epic-poc-runner`。検証テーマの背景 + 成立条件の想定 | `$AI_MONITOR_LABEL_CONFIRM_EPIC_POC_RUNNER` の値 |
| PoC 不要・画面変更あり | `receiver`: `mock-designer`。画面方針の要点 | `$AI_MONITOR_LABEL_CONFIRM_MOCK_DESIGNER` の値 |
| PoC 不要・画面変更なし・複合 UC 影響あり | なし | `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値 |
| PoC 不要・画面変更なし・複合 UC 影響なし | なし | なし（複合シナリオ設計を挟まない） |

### ラベル除去

複合 UC 影響なしの場合は本手順を実行しない（`確認:epic-conductor` を保持したまま自ターンを終え、次のターンで「子story起票」に入る）。

MCP `transition_phase` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値
- `add_labels_`: なし（次の呼び出しは配下からの完了報告で復帰する）

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $number
