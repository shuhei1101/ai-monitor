# エスカレーション対応（実行）

承認された方針を epic 本文に反映し、発生元の story へ決定を降ろす。

## 手順

### 選択された方針の確認

対応方針案コメントへのユーザー返信から、選ばれた案を確定する。

- 複合 UC シナリオの変更を伴う案が選ばれた場合、「複合シナリオ修正の指示」へ進む（「発生元 story への決定通知」は実行しない）
- ユーザー自身が実行する案（リセット / 別 Issue への切り出し）が選ばれた場合、「決定の記録」で経緯を残したうえで「ラベル除去」へ進む（「発生元 story への決定通知」は実行しない）

### epic 本文の更新

決定が epic 本文（`## ユースケース一覧` / `## 横断要件` 等）の変更を伴う場合に実行する。

MCP `update_body` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `body`: 更新後本文

### 複合シナリオ修正の指示

MCP `add_labels` を呼ぶ:
- `number`: epic PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値

続けて MCP `comment` を呼ぶ:
- `number`: epic PR の番号
- `is_pr`: true
- `sender`: `epic-conductor`
- `receiver`: `complex-scenario-writer`
- `body`: 決定した方針と、複合 UC シナリオのどこをどう直すか

発生元 story への決定通知は、シナリオ修正の完了報告を受けてから「エスカレーション対応（決定通知）」で行う。
「決定の記録」へ進む。

### 発生元 story への決定通知

MCP `add_labels` を呼ぶ:
- `number`: 発生元の story Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値

続けて MCP `comment` を呼ぶ:
- `number`: 発生元の story Issue 番号
- `is_pr`: false
- `sender`: `epic-conductor`
- `receiver`: `story-conductor`
- `body`: 決定した方針と、それを踏まえて再開してほしい作業（epic 本文を変更した場合はその箇所）

### 決定の記録

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: story-conductor の中継コメントの node_id
- `sender`: `epic-conductor`
- `receiver`: `story-conductor`
- `body`: 決定内容（ユーザー自身が実行する案の場合はその旨と、ユーザーの操作待ちであること）

続けて MCP `resolve_comments` で自分宛コメントを一括 Resolve する。

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $issue_number
