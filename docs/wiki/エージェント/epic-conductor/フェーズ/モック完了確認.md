# モック完了確認

mock-designer の完了報告を受けてモックの成果物 PR をマージし、複合UCシナリオの成果物 PR を切って複合シナリオ設計へ引き継ぐ。
モック・UI 設計は全体UI設計のユーザー承認ゲートで合意済みのため、ユーザー承認なしの自動完了で次へ進める。

## 手順

### UI 設計の確認

モックの成果物 PR 本文の `## UI 設計`（画面一覧 / 画面遷移 / モック URL）と `## タスク一覧` の全行チェック、mock-designer の完了報告コメントを確認する。

- 未チェックのまま残っている行がある場合、完了報告コメントに追記して指摘し、チェックを入れてもらってからマージする

### 完了報告の Resolve

MCP `resolve_comments` で完了報告コメントを Resolve する。

### モックの成果物 PR のマージ

`規約/マージ手順.md` に沿って base（自分の epic ブランチ）を取り込み、コンフリクトがないことを確認する。

MCP `mark_pr_ready` を呼ぶ:
- `pr_number`: モックの成果物 PR の番号

続けて MCP `merge_pr` を呼ぶ:
- `pr_number`: モックの成果物 PR の番号
- `strategy`: `squash`

続けて MCP `worktree_remove` を呼ぶ:
- `branch`: `docs/epic/{ドメイン}/mock`

続けて MCP `remove_watch_targets` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $number
- `watch_numbers`: マージした成果物 PR の番号

### 複合UCシナリオの成果物 Draft PR の作成

複合 UC 影響なしの場合は本手順を実行せず、次ターンで「子storyPR作成」へ進む（「complex-scenario-writer への引き継ぎ」も実行しない）。

MCP `worktree_create` を呼ぶ:
- `branch`: `docs/epic/{ドメイン}/scenario`
- `base_ref`: `origin/{自分の epic ブランチ}`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: 自分の epic ブランチ
- `title`: `{epic のタイトル}（複合ユースケースシナリオ）`
- `body`: `## 紐づく Issue`（epic PR と同じ起点の Issue 番号）と `## タスク一覧`
- `labels`: `$AI_MONITOR_LABEL_TYPE_DOCS` の値

`## タスク一覧` は作成 / 更新する複合 UC シナリオのページとシナリオ索引の更新を全行未チェックで列挙する（書式はテンプレート「PR本文/成果物」）。

続けて MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $number
- `watch_numbers`: 作成した PR の番号

### complex-scenario-writer への引き継ぎ

MCP `add_labels` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値

### 手番の置き場所

複合 UC 影響なしで成果物 PR を作らなかった場合だけ、手番を自 epic PR へ戻して「子storyPR作成」に続ける。

MCP `transition_phase` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `remove_labels_`: なし
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $number
