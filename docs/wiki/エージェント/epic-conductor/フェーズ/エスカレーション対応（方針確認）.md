# エスカレーション対応（方針確認）

story-conductor から上がった論点に対して、epic レベルで打てる手を選択肢にしてユーザーに確認する。
epic は指揮系統の終端なので、上位への中継の選択肢は持たない。

## 手順

### 論点の整理と解決案の検討

中継コメントから論点と経緯を読む。
そのうえで、epic レベル（複数画面・複数 UC をまたぐ範囲）で打てる手を洗い出す。

代表的な選択肢:

| 案 | 内容 | 補足 |
| --- | --- | --- |
| 要件の変更 | epic 本文の `## ユースケース一覧` / `## 横断要件` を変更して制約を回避する | 影響する story を明示する |
| 機能そのものの見直し | 実現方式を別のものに置き換える（該当 UC の作り直し） | 既存の story / subsystem のやり直し範囲を明示する |
| 別 epic への切り出し | 今回の epic から外し、新しい Issue として起票し直す | 起票はユーザーが行う |
| リセット | 対象を巻き戻してなかったことにする | 実行はユーザーが対象 Issue に `確認:resetter` を付与する |

論点に応じて上表から該当するものを選び、他に有効な案があれば追加する。

### 対応方針案の投稿

MCP `comment` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `sender`: `epic-conductor`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `body`:
  ```
  {論点の要約} について、epic レベルでの対応方針案です。

  | 案 | 内容 | 想定影響 |
  | --- | --- | --- |
  | A | {案の内容} | {やり直しになる story / subsystem} |
  | B | {案の内容} | {影響範囲} |

  推奨: {A / B}（{理由}）

  - 方針が決まったら記号で返信 + `議論中` ラベルを外す → その方針で進めます
  - 調整が必要なら assignee を外してフィードバックコメントを記入
  ```

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false

`確認:epic-conductor` は除去しない（選択後の実行で復帰するため）。

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $issue_number
