# 要件確定（初回）

epic PR 本文（概要 / 背景 / ユースケース一覧 / 横断要件）の草案を作成し、実現可能性 PoC の要否と画面変更の有無を質問して待機に入る。

## 手順

### 親 intake の確認

MCP `get_issue_or_pr` を呼び、親 intake の内容を読む:
- `number`: 初期処理で取得した `parent` の番号
- `is_pr`: true
- `comments`: true

親 intake の本文と、コメントに残る承認済みのサブ Issue 案（Resolve 済みスレッド）から、この epic が担当する範囲を把握する。

### 本文の作成

テンプレート（PR本文/エピック）に沿って 4 セクション（`## 概要` / `## 背景` / `## ユースケース一覧` / `## 横断要件`）の草案を作成する。

- `## 概要` / `## 背景` はユーザー入力（親 intake の記述）の範囲内で整文する
- `## ユースケース一覧` の `対応 story` 列は全行 `未作成` にする
- `## ユースケース一覧` の `変更種別` 列を全行埋める（`新規` / `変更` / `削除`）。
  下位レイヤーがこの列で現状調査の要否を決めるため空欄にしない。
  `削除` の行も一覧から消さずに残す
- `## 横断要件` に書けるのは複数 UC を跨いで初めて成立する要件だけ（用語の整合・後方互換・検証方法のような横断しない備考は書かない）。
  ユースケースが 1 件の epic では `なし（本 epic のユースケースは 1 件のため、ユースケース間を横断する要件は発生しない）` と書く
- 複合ユースケースへの影響の判定結果（判定フローチャート（レイヤー）の ※2）を `## ユースケース一覧` の直後に 1 行で書く。
  影響なしと判断した場合は `複合ユースケースへの影響: なし（{根拠}）` と明記する（下位レイヤーと後続ターンがこの記述で経路を決める）

MCP `update_body` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `body`: 作成した本文

### 確認質問の投稿

観点例に限らず、今回の epic に確認が必要な事項（ユースケースの過不足・横断要件の水準など）を洗い出し、本文・親 intake の内容から AI 側で推奨案を判断して投稿する。

下表は判断が分かれやすい観点の例で、毎回出す質問ではない。
本文・既存の設計書・上位 Issue から答えが一意に定まる観点は質問せず、前提として置いた判断を完了報告に書く。
質問する範囲は epic レイヤーが決める論点（UC の切り方・横断要件の水準）に限る。
実装方法・関数シグネチャ・型・ライブラリ選定・ファイル構成は subsystem 以下の担当なので質問しない。

| 観点 | 質問 | 選択肢例 |
| --- | --- | --- |
| 実現可能性 PoC 要否 | 「この epic の成立は前例のない技術機構（未検証のプロトコル連携・性能が成立条件 等）に依存しますか？」 | 依存しない（PoC 不要） / 依存する（PoC 必要: {検証テーマ}） |
| 画面変更の有無 | 「画面の新規作成・レイアウト変更を含みますか？」 | 含まない / 含む |
| 複合ユースケースへの影響 | 「`設計図/シナリオ/複合ユースケース/` の新規作成・更新を伴いますか？」 | 伴わない（実装だけの変更） / 伴う |
| 上記以外 | epic レイヤーで決める論点のうち、判断が分かれるもの | その場で組み立てる |

MCP `ask_questions` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `sender`: `epic-conductor`
- `receiver`: ユーザーログイン名
- `questions`: 上記の質問

### 議論中 付与 + 待機

確認質問を 1 件も投稿しなかった場合は本手順を実行しない。
`確認:{自分}` を保持したまま自ターンを終え、次のターンで「要件確定（完了処理）」へ進む（判断が分かれる論点が無いのに手を止めない）。

MCP `add_labels` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `epic-conductor`
- `number`: $number
