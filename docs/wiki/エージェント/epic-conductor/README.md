# epic-conductor

判定は毎ターン、最新の取得結果（本文・ラベル・自分宛の未解決コメント）を材料に、上から順に見て最初にマッチしたフェーズを 1 つ実行する。

## 目次

| ページ | 概要 | 起動条件 |
| --- | --- | --- |
| [初期処理](./フェーズ/初期処理.md) | 本文・ラベル・自分宛コメントの取得 | 毎ターン最初に必ず実行（以降の判定材料を取得） |
| [要件確定（初回）](./フェーズ/要件確定（初回）.md) | epic Issue 本文 5 セクションの草案作成と PoC / 画面変更の要否質問 | 本文の 5 セクション未記入（未作業） |
| [応答ループ](./フェーズ/応答ループ.md) | フィードバックへの対応 | `議論中` あり + 未解決の自分宛コメントがある |
| [要件確定（完了処理）](./フェーズ/要件確定（完了処理）.md) | 回答に応じた Draft PR の作成と次フェーズ担当への引き継ぎ | `議論中` なし + 本文確定済み + epic / PoC Draft PR 未作成 |
| [PoC結果確認](./フェーズ/PoC結果確認.md) | 検証結果の確認と PoC の畳み込み、epic Draft PR の作成 | 未解決の自分宛コメントに epic-poc-runner の完了報告、または PoC 疑問スレッドへのユーザー回答がある |
| [モック完了確認](./フェーズ/モック完了確認.md) | epic PR の UI 設計確認と複合シナリオ設計への引き継ぎ | 未解決の自分宛コメントに mock-designer の完了報告がある |
| [子story起票](./フェーズ/子story起票.md) | ユースケース一覧の各 UC に対応する子 story Issue の起票 | 未解決の自分宛コメントに complex-scenario-writer のシナリオ設計完了報告がある |
| [統合テスト起動](./フェーズ/統合テスト起動.md) | 全子 story の close 確認と複合 UC 統合テストの委任 | 未解決の自分宛コメントに story-conductor の完了報告（story 完了）がある |
| [バグ差し戻し（方針確認）](./フェーズ/バグ差し戻し（方針確認）.md) | 失敗報告を受けた対応方針案の確認 | 未解決の自分宛コメントに complex-scenario-writer の失敗報告があり、対応方針案コメント未投稿 |
| [バグ差し戻し（実行）](./フェーズ/バグ差し戻し（実行）.md) | 承認された方針での該当 story Issue への差し戻し | `議論中` なし + 対応方針案コメント投稿済み（未 Resolve） |
| [epicマージ](./フェーズ/epicマージ.md) | epic PR を master へマージする終端処理 | 未解決の自分宛コメントに complex-scenario-writer の完了報告（全 pass）がある |
