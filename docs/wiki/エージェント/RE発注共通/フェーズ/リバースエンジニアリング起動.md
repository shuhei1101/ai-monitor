# リバースエンジニアリング起動

RE ブランチと RE PR を作り、担当の `*-reverse-engineer` に現状の設計書の作成を依頼する。
自レイヤーの要件確定より前に通す工程で、実装コードを読むのは依頼先だけに絞る。
`{自分}` / `{依頼先}` / `{RE ブランチ}` / `{base}` / `{起こす範囲}` / `{成果物}` はフェーズ索引の担当範囲表の値に読み替える。

## 手順

### ラベルの付与

自 Issue に `layer:*` / `type:*` が未付与の場合だけ実行する（ユーザーが直接起票する system レイヤーが該当する）。

MCP `add_labels` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `labels`: フェーズ索引の担当範囲表が指定する `layer:*` と `type:*` の値

### 起こす対象の決定

自 Issue の本文と親 Issue から、`{起こす範囲}` に沿って起こしてもらうページを確定する。
依頼先が複数ある場合は、依頼先ごとに対象を分けて以降の手順を繰り返す（該当しない依頼先には作らない）。

### RE ブランチと RE PR の作成

MCP `worktree_create` を呼ぶ:
- `branch`: `{RE ブランチ}`
- `base_ref`: `origin/{base}`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: `{base}`
- `title`: 現状の `{成果物}` の起こし
- `body`: `## 紐づく Issue`（`- #$issue_number`）と `## タスク一覧`（起こす対象ページのチェックボックス）

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `{自分}`
- `number`: $issue_number
- `watch_numbers`: 作成した RE PR の番号

### 作成依頼

応答ループから追加範囲を依頼する場合も本手順を実行する（その場合は PR 作成を伴わない）。

MCP `comment` を呼ぶ:
- `number`: RE PR の番号
- `is_pr`: true
- `sender`: `{自分}`
- `receiver`: `{依頼先}`
- `format`:
  - `type`: `plain`
  - `body`: 起こす対象ページと担当範囲（完了報告に添えてほしい内容があればそれも）

続けて MCP `add_labels` を呼ぶ:
- `number`: RE PR の番号
- `is_pr`: true
- `labels`:
  - `{依頼先}` の確認ラベル（担当範囲表の環境変数名）の値
  - `$AI_MONITOR_LABEL_REVERSE_ENGINEERING` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `{自分}`
- `number`: $issue_number
