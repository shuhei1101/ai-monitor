# リバースエンジニアリング起動

RE ブランチと RE PR を作り、担当の `*-reverse-engineer` に現状の設計書の作成を依頼する。
自レイヤーの要件確定より前に通す工程で、実装コードを読むのは依頼先だけに絞る。
`{自分}` / `{依頼先}` / `{RE ブランチ}` / `{base}` / `{起こす範囲}` / `{成果物}` はフェーズ索引の担当範囲表の値に読み替える。

## 手順

### ラベルの付与

自 Issue に `layer:*` / `type:*` が未付与の場合だけ実行する（ユーザーが直接起票する system レイヤーが該当する）。

MCP `add_labels` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `labels`: フェーズ索引の担当範囲表が指定する `layer:*` と `type:*` の値

### 起こす対象の決定

自 Issue の本文と親 Issue から、`{起こす範囲}` に沿って起こしてもらうページを確定する。
依頼先が複数ある場合は、依頼先ごとに対象を分けて以降の手順を繰り返す（該当しない依頼先には作らない）。

### 自レイヤーブランチの確認

RE ブランチは自レイヤーのブランチから生やすため、`{base}` が存在しない場合は先に作る（規約『ブランチ戦略』の「自レイヤーのブランチは RE PR より先に作る」）。

`{base}` の有無は MCP `get_issue_or_pr` の `head_ref` で確かめる。

| 自レイヤーの面 | `{base}` の状態 | やること |
| --- | --- | --- |
| PR（epic / story / subsystem） | 既に存在する（面の head そのもの） | 何もしない |
| Issue（system の立ち上げ Issue） | 存在しない | 下の `worktree_create` で作る |

面が Issue の場合だけ MCP `worktree_create` を呼ぶ:
- `branch`: `{base}`
- `base_ref`: `origin/master`

このブランチは以降のレイヤー PR の head になるので、RE が終わった後も残す。

### RE ブランチと RE PR の作成

MCP `worktree_create` を呼ぶ:
- `branch`: `{RE ブランチ}`
- `base_ref`: `origin/{base}`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: `{base}`
- `title`: 現状の `{成果物}` の起こし
- `body`: `## 紐づく Issue`（`- #$number`）と `## タスク一覧`（起こす対象ページのチェックボックス）
- `labels`: `{レイヤーラベル}`（担当範囲表の環境変数名）の値

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `{自分}`
- `number`: $number
- `watch_numbers`: 作成した RE PR の番号

### 作成依頼

応答ループから追加範囲を依頼する場合も本手順を実行する（その場合は PR 作成を伴わない）。

MCP `comment` を呼ぶ:
- `number`: RE PR の番号
- `is_pr`: true
- `sender`: `{自分}`
- `receiver`: `{依頼先}`
- `format`:
  - `type`: `plain`
  - `body`: 起こす対象ページと担当範囲（完了報告に添えてほしい内容があればそれも）

続けて MCP `add_labels` を呼ぶ:
- `number`: RE PR の番号
- `is_pr`: true
- `labels`:
  - `{依頼先}` の確認ラベル（担当範囲表の環境変数名）の値
  - `$AI_MONITOR_LABEL_REVERSE_ENGINEERING` の値

### 手番の引き渡し

依頼先へ手番を渡したので、自分が確認ラベルを持っている面からそれを外す（規約『フェーズ索引の網羅』の 1 面 1 確認ラベル）。
外さないと依頼中も毎周期自分が起動し続ける。
依頼先が完了報告で RE PR に `確認:{自分}` を付け直すので、そこで「RE完了確認」から再開する。

初回の依頼では自分の確認ラベルが自 Issue 側にあるため、MCP `transition_phase` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `remove_labels_`:
  - `{自分}` の確認ラベル（担当範囲表の環境変数名）の値
- `add_labels_`: なし

応答ループからの追加依頼では自分の確認ラベルが RE PR 側にあるため、上の `add_labels` は呼ばずに MCP `transition_phase` 1 回でまとめる:
- `number`: RE PR の番号
- `is_pr`: true
- `remove_labels_`:
  - `{自分}` の確認ラベル（担当範囲表の環境変数名）の値
- `add_labels_`:
  - `{依頼先}` の確認ラベル（担当範囲表の環境変数名）の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `{自分}`
- `number`: $number
