# 問い合わせ応答

索引の他のどのフェーズにも該当しないまま起こされたとき、未解決の自分宛コメントに答えて手番を返す。

## 手順

### 依頼内容の判定

未解決の自分宛コメントを読み、次のどちらかを判定する。

| 種類 | 例 | 対応 |
| --- | --- | --- |
| 情報を求めるもの | 進捗の状況確認・担当範囲の質問・判断の根拠の確認 | 「現状の確認」へ進む |
| 成果物を求めるもの | 設計・実装・テストの依頼、既存フェーズの工程に当たるもの | 「対応できない旨の返信」へ進む |

### 現状の確認

初期処理で取得した本文・ラベル・コメントと、必要なら worktree の状態から、聞かれている内容の答えを組み立てる。

不足する情報がある場合だけ、追加で MCP `get_issue_or_pr` を呼んで関連する Issue / PR を読む。

子 Issue や依頼先など他の面の経緯を調べるときは、規約『コメント』の「他の面の経緯を調べるとき」に従う。
Issue にコメントが無くても、作業と会話は紐づく PR 側に Resolve 済みで残っていることがあるため、`include_resolved: true` で PR まで見てから判断する。

本文・タスク一覧・他の面のラベルは変更しない（問い合わせに答えるだけで、工程を進めない）。

### 返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: 問い合わせコメントの node_id
- `sender`: `{自分}`
- `receiver`: 問い合わせ元
- `format`:
  - `type`: `plain`
  - `body`: 聞かれた内容への回答（進捗を聞かれた場合は、今どの工程にいて次に何を待っているか）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: 問い合わせコメントの `node_id`

### 対応できない旨の返信

成果物を求める依頼で、既存フェーズの工程に当たる場合は、どのフェーズが担当するかを返信して手番を返す。
自分の担当外の場合は、担当するエージェント名を添える（`プロジェクト管理/エージェント組織図.md`）。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: 問い合わせコメントの node_id
- `sender`: `{自分}`
- `receiver`: 問い合わせ元
- `format`:
  - `type`: `plain`
  - `body`: 本フェーズでは受けられない旨と、担当するフェーズ / エージェント

Resolve はしない（依頼元が読んで判断するため）。

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: 起動要因になった対象の番号
- `is_pr`: 対象が PR なら true
- `remove_labels_`:
  - 自分の確認ラベル（`AI_MONITOR_LABEL_CONFIRM_*`）の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `{自分}`
- `number`: 起動要因になった対象の番号
