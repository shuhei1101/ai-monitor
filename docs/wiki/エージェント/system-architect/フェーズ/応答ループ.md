# 応答ループ

待機中のユーザーフィードバックに対応し、再び待機に入る。

## 手順

### 作業ディレクトリの最新化

system ブランチの worktree へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

### 内容に応じた対応

| 待機の文脈 | 対応 |
| --- | --- |
| アーキテクチャ図の修正指示 | 該当セクションを修正して commit push |
| `docs/wiki/` 骨格の過不足の指摘 | ディレクトリ / README を追加・削除して commit push |
| `README.md` の修正指示 | 該当箇所を修正して commit push |
| 非機能要件の値の指定 | `設計図/非機能要件.md` の決定値列を書き換え、出所列に `ユーザー要望（{回答コメントへのリンク}）` を入れて commit push |
| 生成方針への質問 | 回答の追記のみ（生成物は触らない） |
| 上記以外 | 文脈から必要な対応を判断して実施し、対応内容を短く追記 |

対応内容はユーザーがその指摘を書いたコメントに返信追記する（規約『コメント』の「どのコメントに返信するか」）。
自分が過去に投稿した完了報告コメントに積み増さない。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: ユーザーが指摘を書いたコメントの node_id
- `sender`: `system-architect`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 修正内容の要約

指摘が複数あるときは、指摘の数だけ別々のコメントへ返信する。

### 決着したスレッドの Resolve

インライン確認事項のスレッドを 1 件ずつ見て、この往復で内容が確定したものだけを畳む。

MCP `list_review_threads` を呼ぶ:
- `pr_number`: 対象 PR の番号
- `addressee`: 自分のエージェント名
- `include_resolved`: false

スレッドごとに、ユーザーの返信（`thumbs_up_by` に本人が入っていれば推奨案への同意とみなす）で論点が決まったかを判断する。

- 決まった場合、MCP `reply_review_thread` で確定内容を返信してから MCP `resolve_review_threads` で畳む
- 決まっていない場合（回答がない・回答だけでは実装を決められない）は畳まず、次の「未決着スレッドの再確認」へ持ち越す

### 未決着スレッドの再確認

畳めなかったスレッドが 1 件も無い場合、本手順は実行しない。

残っている場合は、何が未回答かを名指しした確認コメントを MCP `comment` で投稿する:
- `number`: 対象 PR の番号
- `is_pr`: true
- `sender`: 自分のエージェント名
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 未決着スレッドの一覧（各スレッドへのリンク + 何が決まっていないか + 選べる案）

続けて MCP `add_labels` で `$AI_MONITOR_LABEL_IN_DISCUSSION` の値を付ける（既に付いていれば冪等）。
ユーザーが `議論中` を外して完了へ進めようとした場合でも、決めきれていない論点が残っていればここで議論に戻す。

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `system-architect`
- `number`: $pr_number
