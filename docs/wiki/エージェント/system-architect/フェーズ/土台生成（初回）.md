# 土台生成（初回）

確定した構成要件をもとに、以降の全エージェントが参照する土台（アーキテクチャ図・`docs/wiki/` 骨格・`docs/rules.yaml`・`README.md`）を土台生成の成果物ブランチ上に生成し、GitHub ラベルを一括作成して待機に入る。

## 手順

### 構成要件の確認

初期処理で取得した `parent`（base ブランチを head に持つ親 system PR）の番号を取り出す。

MCP `get_issue_or_pr` を呼ぶ:
- `number`: 特定した親 PR の番号
- `is_pr`: true
- `comments`: false

`## 構成要件` の 4 カテゴリ（リポジトリ / サブシステム / 言語 / 外部システム）と `## エピック一覧` を読み、生成する土台の範囲を確定する。
依頼コメントに追加の指定がある場合はそれも読む。

### 作業ディレクトリの準備

成果物ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は 成果物 PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

### docs/wiki 骨格の生成

`規約/Wiki管理.md` のトップ構造に沿って `docs/wiki/` のディレクトリを作り、全ディレクトリに目次だけの `README.md` を併置する（書式はテンプレート「README書式」）。

以下は骨格として空の状態で置く。

| 生成物 | 初期状態 |
| --- | --- |
| `docs/rules.yaml` | 空の索引（`rules: []`） |
| `テスト/テスト実行方法.md` | 見出しのみで本文は `未確定` |
| `外部API/README.md` | 空の索引 |
| `外部ライブラリ/README.md` | 空の索引 |

### アーキテクチャ図の作成

`設計図/アーキテクチャ図.md` を構成要件どおりに作成する（`リバースエンジニアリング` ラベルがある場合は master に入っている現状版を上書きする）。

| セクション | 記入内容 |
| --- | --- |
| 全体図 | リポジトリ構成とサブシステムの関係 |
| サブシステム一覧 | サブシステム名・`scope` 列・担当範囲 |
| 外部システム連携 | 連携先・詳細・対応非機能要件テスト（銘柄未定は `{種別}（銘柄未定）` とし、詳細列と対応非機能要件テスト列を `-`） |

### 非機能要件の作成

`設計図/非機能要件.md` を作る（書式はテンプレート「非機能要件」）。

アーキテクチャ図の `## 外部システム連携` で挙げた外部システムごとに `## 一覧` の行を作る。

決定値をここで埋めるのは、実行基盤の公開仕様から直接引ける行だけにする（ランタイムの上限・ホスティングの制限 等）。
外部システムの銘柄・バージョンが決まっていない段階で制限値を書くと裏づけの無い値が残るため、それ以外の行は決定値を `未確定` にし、根拠列に決める条件（どの工程で銘柄が決まるか）を書く。
値は銘柄を決めたレイヤー（architect のライブラリ選定 等）が後から埋める。

書く範囲はコンポーネントをまたいで効く要件に限る（`判定フローチャート/非機能要件のレイヤー.md`）。
1 コンポーネント内で閉じる要件は subsystem PR 本文の `### 非機能要件` の担当なので、ここには書かない。

コスト予算・想定利用者数のようにユーザーの意向で決まる項目は、決定値を `未確定` のままにして確認事項を「インラインコメントの投稿」で出す。
応答ループでユーザーが値を示したら決定値列を書き換え、出所種別を `ユーザー要望`・出所列にその回答コメントへのリンクを入れる。

一覧の行ごとに詳細セクション（`## {項目名}`）を作り、超過時の挙動 / 内訳 / 非機能要件テスト を書く（該当しないサブセクションは「なし」）。

### README.md の作成

リポジトリルートの `README.md` を、プロジェクトの概要・構成・セットアップ手順の骨格として作成する。

### .gitignore の作成

リポジトリルートに `.gitignore` を作成する（既にある場合は不足分だけ追記し、既存の行は消さない）。

必ず入れるもの:

| 対象 | パターン | 理由 |
| --- | --- | --- |
| worktree の実体 | `.claude/worktrees/` | エージェントが作る作業ツリーで、追跡すると成果物と混ざる |
| 環境変数ファイル | `.env` / `.env.*`（`.env.example` は除外しない） | 秘匿値がリポジトリに入る |
| OS 由来ファイル | `.DS_Store` / `Thumbs.db` | 成果物と無関係 |

続けて、構成要件で確定した実装言語の依存・キャッシュ・ビルド生成物を足す。

| 言語 | パターン例 |
| --- | --- |
| Python | `__pycache__/` / `*.pyc` / `.venv/` / `.pytest_cache/` |
| TypeScript / JavaScript | `node_modules/` / `dist/` / `.next/` |

構成要件に出てこない言語のパターンは書かない（使わない除外を並べても読み手の判断材料にならない）。

### ルール索引の宣言

リポジトリルートの `.claude/settings.json` に、inject-rules が読むルール索引を宣言する。
ここを設定しないと、以降のエージェントにコーディング規約も設計ドキュメントの書式も注入されない。

`env.INJECT_RULES_INDEXES` にカンマ区切りで 3 つ並べる:

| 索引 | URL | 内容 |
| --- | --- | --- |
| my-plugins | `https://raw.githubusercontent.com/shuhei1101/my-plugins/master/docs/rules.yaml` | 言語 / フレームワーク横断のコーディング規約 |
| ai-monitor | `https://raw.githubusercontent.com/shuhei1101/ai-monitor/master/docs/rules.yaml` | 設計ドキュメントの書式テンプレートと横断規約 |
| 自プロジェクト | `https://raw.githubusercontent.com/{owner}/{repo}/master/docs/rules.yaml` | このプロジェクト固有の規約（土台生成時点では空の索引） |

`{owner}` / `{repo}` は対象リポジトリの値に読み替える。

```json
{
  "env": {
    "INJECT_RULES_INDEXES": "https://raw.githubusercontent.com/shuhei1101/my-plugins/master/docs/rules.yaml,https://raw.githubusercontent.com/shuhei1101/ai-monitor/master/docs/rules.yaml,https://raw.githubusercontent.com/{owner}/{repo}/master/docs/rules.yaml"
  }
}
```

- `.claude/settings.json` が既にある場合は `env` に本キーだけを足す（他の設定は消さない）
- 既に `INJECT_RULES_INDEXES` がある場合は、不足している索引だけを末尾に追加する

### GitHub ラベルの一括作成

`python -m ai_monitor.setup_labels --repo {owner/name}` を実行し、`constants.env` の全ラベルを対象リポジトリに作成する。

### commit push とタスク一覧のチェック

生成物を commit push する。

親 system PR 本文の `## タスク一覧` の生成タスクを `[x]` にする。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### インラインコメントの投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って確認事項と補足事項を該当行へ投稿する。

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `system-architect`
- `number`: $pr_number
