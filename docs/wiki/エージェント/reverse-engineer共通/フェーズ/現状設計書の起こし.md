# 現状設計書の起こし

担当範囲の実装コードを読み、現状の構造をそのまま設計書の書式で起こして RE PR に commit し、発注元の conductor へ報告する。
`{自分}` / `{発注元}` / `{成果物}` はフェーズ索引の担当範囲表の値に読み替える。

## 手順

### 依頼内容の確認

未解決の自分宛コメントの依頼コメントと、初期処理で取得した紐づく Issue の本文から、起こす対象ページと担当範囲を読む。

### 作業ディレクトリの最新化

RE ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は RE PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

### 実装コードの読み取り

担当範囲の実装コードを読み、型・関数・依存関係・分岐を洗い出す。

- 担当範囲に対応する実装が存在しない場合、「差し戻し報告」へ進む（以降の手順は実行しない）

### 設計書の作成

現状の構造をそのまま `{成果物}` の書式で作成して commit push する（書式テンプレートのオンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。

| 書くもの | 書かないもの |
| --- | --- |
| 実装の物理名（ファイルパス・関数名・型名）と一致する構成要素 | 実装に存在しない要素（推測での補完） |
| 実装から読み取れた分岐・依存関係 | あるべき姿への整理・リファクタ提案 |

実装から読み取れなかった箇所は完了報告に載せるため控えておく。

### インラインコメントの投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って確認事項と補足事項を該当行へ投稿する。

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - 自分の確認ラベル（フェーズ索引の担当範囲表の環境変数名）の値
- `add_labels_`:
  - `{発注元}` の確認ラベル（同上）の値

### 完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `{自分}`
- `receiver`: `{発注元}`
- `format`:
  - `type`: `commits`
  - `body`: 起こしたページ一覧 + 実装から読み取れなかった箇所（`architecture-reverse-engineer` は機能の洗い出しも添える）
  - `entries`: 積んだ commit の `commit` と `summary` の組

「作業完了報告」を実行して自ターンを終える（「差し戻し報告」は実行しない）。

### 差し戻し報告

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - 自分の確認ラベルの値
- `add_labels_`:
  - `{発注元}` の確認ラベルの値

続けて MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `{自分}`
- `receiver`: `{発注元}`
- `format`:
  - `type`: `plain`
  - `body`: 差し戻し報告（探した範囲と、担当範囲の実装が見つからなかった理由）

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `{自分}`
- `number`: $pr_number
