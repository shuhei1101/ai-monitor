# テストレビュー

tester のテストコードを自分が確定させた設計 Wiki と照合し、テストを実行して Red を確認したうえで implementer に実装を割り当てる。
ユーザーとのやり取りはせず、指摘は tester に直接差し戻す。

## 手順

### テストコードのレビュー

完了報告のコミット表から見る範囲を決め、差分を取得する（共通ルール『PR差分の取得』）。
取得したテストコードを設計 Wiki（結合 / モジュール構成）と一対一で突き合わせて確認し、テスト観点の過不足と粒度（1 設計書 = 1 テストファイル・結合フローの正常 / 異常が漏れなくケース化されているか）を見る。

- 指摘がある場合、「インライン指摘の投稿」へ進む
- 指摘がない場合、「Red の確認」へ進む（「インライン指摘の投稿」は実行しない）

### インライン指摘の投稿

指摘 1 件ごとに MCP `create_review_comment` を呼ぶ:
- `pr_number`: $pr_number
- `path`: 指摘対象のファイルパス
- `line`: 指摘対象の行
- `sender`: `architect`
- `receiver`: `tester`
- `body`: 設計 Wiki との差異と期待する修正

続けて MCP `reply_comment` を呼ぶ:
- `comment_node_id`: tester の完了報告コメントの node_id
- `sender`: `architect`
- `receiver`: `tester`
- `format`:
  - `type`: `plain`
  - `body`: インライン指摘への対応依頼（指摘の件数と要点。スレッドは Resolve しない）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値

「作業完了報告」を実行して自ターンを終える（以降の手順は実行しない）。

### Red の確認

subsystem ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は subsystem PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

`テスト/テスト実行方法.md` のコマンドでテストを実行する。
設計どおりに fail する Red 状態であることを確認する（実装ファイル不在による import エラーも Red として扱う）。

- Red にならないテストがある場合、「インライン指摘の投稿」へ進む
- 全て Red の場合、「対応テストファイルの記入」へ進む

### 対応テストファイルの記入

レビューしたテストファイルのパスを、対応する結合 / モジュール構成ページの冒頭リードの `対応テストファイル` 行に記入して commit push する。

### レビュー結果の返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: tester の完了報告コメントの node_id
- `sender`: `architect`
- `receiver`: `tester`
- `format`:
  - `type`: `plain`
  - `body`: レビュー結果（指摘なし + 確認した観点の要約 + Red の実行結果）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: tester の完了報告コメントの `node_id`

### インライン指摘スレッドの解決

MCP `list_review_threads` を呼ぶ:
- `pr_number`: $pr_number
- `include_resolved`: false

続けて MCP `resolve_review_threads` を呼ぶ:
- `thread_node_ids`: 取得したスレッドの `node_id` 配列

### タスク一覧のチェック

subsystem PR 本文の `## タスク一覧` のテスト作成タスクを `[x]` にする。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### implementer への実装の割り当て

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `architect`
- `receiver`: `implementer`
- `format`:
  - `type`: `pages`
  - `body`: 実装の指示（実装の根拠になる設計 Wiki のページ名+ 対応するテストファイル一覧）
  - `entries`: 各ページの `page` と `commit`（範囲があれば `start_commit` も）の組

### ラベル遷移

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_IMPLEMENTER` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
