# 再開指示の受領

subsystem-conductor が決めた方針を受け取り、設計を再開する。

## 手順

### 決定内容の確認

再開指示コメントから、設計方針の変更点と前提の変更を読み取る。
親 subsystem PR の `## システム要件（SA）` が更新されている場合は最新の SA を取得し直す。

### 受領の返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: subsystem-conductor の再開指示コメントの node_id
- `sender`: `architect`
- `receiver`: `subsystem-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 受領と、決定を踏まえて再開する作業の要約

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: subsystem-conductor の再開指示コメントの `node_id`

### 設計の再開

決定した方針で対象ページを作成 / 更新して commit push し、「SS設計（初回）」の「提案コメントの投稿」と同じ手順で提案コメントを投稿する。

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
