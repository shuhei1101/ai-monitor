# テスト作成の委任

subsystem-conductor から実装・テストの成果物 PR を受け取り、tester にテスト作成を割り当てる。

設計は前段の成果物 PR（インターフェース定義 / モジュール構成）で確定済みなので、本フェーズで設計はしない。
この面では tester → implementer の順に自分が割り当て、それぞれのレビューまで面倒を見る。

## 手順

### 委任内容の確認

成果物 PR の base ブランチを辿って親 subsystem PR を特定する。

MCP `get_issue_or_pr` を呼ぶ:
- `number`: 特定した親 PR の番号
- `is_pr`: true
- `comments`: false

`## システム要件（SA）` と、conductor の割り当てコメントに載っている設計 Wiki のページ名を読み、テスト観点の起点を確定する。

### tester へのテスト作成の割り当て

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `architect`
- `receiver`: `tester`
- `format`:
  - `type`: `pages`
  - `body`: テスト作成の指示（テスト観点の起点になるインターフェース定義 / モジュール構成のページ名）
  - `entries`: 各ページの `page` と `commit`（範囲があれば `start_commit` も）の組

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
