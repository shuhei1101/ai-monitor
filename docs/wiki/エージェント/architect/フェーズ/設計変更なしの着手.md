# 設計変更なしの着手

設計タスクを持たない修正用 PR で、設計変更が本当に不要かを影響調査で確定し、tester にテスト作成を割り当てる。

## 手順

### システム要件の確認

subsystem PR 本文の `## 紐づく Issue` から親 subsystem Issue 番号を取り出す。

MCP `get_issue_or_pr` を呼ぶ:
- `number`: 取り出した subsystem Issue の番号
- `is_pr`: false
- `parent`: true
- `comments`: false

`## システム要件（SA）` の機能 / 非機能要件と `### スコープ外` を読み、修正の対象範囲を確定する。

### 影響調査

subsystem ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は subsystem PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

差し戻された fail の内容と、既存の設計 Wiki・実装コードを読む（設計 Wiki のオンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。
`チェックシート/設計変更影響調査.md` の前半（判定一覧の作成まで）を実施し、維持 / 修正 / 廃止の判定一覧を作る。

- 判定一覧に「修正」or「廃止」がある場合、`## タスク一覧` に該当する設計タスクを MCP `update_body` で追記し、「作業完了報告」を実行して自ターンを終える（次ターンは「SS設計（初回）」を通る）
- 全て「維持」の場合、「tester へのテスト作成の割り当て」へ進む

### tester へのテスト作成の割り当て

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `architect`
- `receiver`: `tester`
- `format`:
  - `type`: `plain`
  - `body`: 影響調査の判定一覧と設計変更が不要と判断した理由 + テスト作成の指示（差し戻された fail を再現する既存テストの所在と、不足する観点の追加）

### ラベル遷移

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
