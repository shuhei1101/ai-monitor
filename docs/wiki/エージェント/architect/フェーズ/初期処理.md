# 初期処理

毎ターン最初に必ず実行する。
ライブラリ選定で PoC を発注している間は PoC PR も監視面になるため、作成済みなら PoC PR の最新状態も取得する。

## 手順

### subsystem PR の最新状態の取得

MCP `get_issue_or_pr` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

続けて MCP `list_addressed_comments` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `addressee`: `architect`
- `include_resolved`: false

### PoC PR の最新状態の取得

コンテキストスナップショットで、自 PR と同じ subsystem Issue にぶら下がる PoC PR を確認する。

- PoC PR がない場合、本手順を飛ばして「フェーズの決定」へ進む

PoC PR ごとに MCP `get_issue_or_pr` を呼ぶ:
- `number`: PoC PR の番号
- `is_pr`: true

続けて MCP `list_addressed_comments` を呼ぶ:
- `number`: PoC PR の番号
- `is_pr`: true
- `addressee`: `architect`
- `include_resolved`: false

### フェーズの決定

フェーズ索引のフェーズ一覧を上から順に見て、起動条件に最初にマッチしたフェーズの手順を実行する。
前ターンの記憶ではなく取得結果を判定材料にする（本文・ラベル・コメントはターン間にユーザーや他エージェントが変更している可能性がある）。
