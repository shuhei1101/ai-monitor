# エスカレーション報告

subsystem レイヤーで解決できない論点を、経緯を添えて subsystem-conductor へ引き上げる。

## 手順

### 論点の整理

相談コメントのスレッドから、何が subsystem レイヤーで決められないのか（適合候補の不在・要件の矛盾・外部制約）と、検討済みの選択肢を整理する。

### エスカレーション報告の投稿

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `architect`
- `receiver`: `subsystem-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 経緯（調査・検討した内容）+ 論点（何を決められないか）+ 検討済みの選択肢と却下理由

続けて MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`: なし

設計 Wiki への新規 commit はせず、上位の決定が降りてくるまで保留する。

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
