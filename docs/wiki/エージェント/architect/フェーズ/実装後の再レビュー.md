# 実装後の再レビュー

実装レビューでテストコード側の問題と判定して tester へ差し戻した後、修正されたテストコードを Green の実測で確認し、一式完了報告へ進む。

初回の「テストレビュー」と違い実装は完了しているため、Red ではなく Green を期待する（判定フローチャート『差し戻し復帰先』）。

## 手順

### テストコードのレビュー

worktree を最新化し、テストコードの diff と設計 Wiki（結合 / モジュール構成）を照合する。
差し戻したときに指摘した内容が反映されているかを見る。

- 指摘が反映されていない場合、「テストレビュー」の「指摘の投稿と差し戻し」と同じ手順で tester へ差し戻す（以降の手順は実行しない）

### Green の実測確認

worktree でテストを実行し、全て pass することを確認する。

- fail が残る場合、「実装レビュー」の「fail のトリアージ」へ進む（以降の手順は実行しない）

実測結果を 親 subsystem PR 本文のテスト結果表に記入する。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: テスト結果表を更新した本文

### レビュー結果の返信

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: tester の完了報告コメントの node_id
- `sender`: `architect`
- `receiver`: `tester`
- `format`:
  - `type`: `plain`
  - `body`: レビュー結果（Green の実測結果 + 指摘なし）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: tester の完了報告コメントの `node_id`

### インライン指摘スレッドの解決

MCP `list_review_threads` を呼ぶ:
- `pr_number`: $pr_number
- `addressee`: `architect`
- `include_resolved`: false

続けて MCP `resolve_review_threads` を呼ぶ:
- `thread_node_ids`: 取得したスレッドの `node_id` 配列

### 一式完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `architect`
- `receiver`: `subsystem-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 一式完了報告（設計 → テスト → 実装 → レビューの結果要約 + テスト実測結果 + 差し戻しの経緯）

### ラベル遷移

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
