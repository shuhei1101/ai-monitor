# 応答ループ

待機中のユーザーフィードバックに対応し、再び待機に入る。
どの待機かは、未応答のユーザー発言が付いた自分宛スレッドの文脈で判断する。
ユーザーとの会話面は 成果物 PR のみ（PoC PR 側は発注元とのやり取りだけ）。

## 手順

### 内容に応じた対応

| 待機の文脈 | 対応 |
| --- | --- |
| 設計提案への修正指示 | 対象ページを修正して commit push し、「本ページの {箇所} を更新しました」と短く追記 |
| 設計提案の議論中に生じたライブラリ選定論点 | 「SS設計（初回）」の「ライブラリ候補の提示」を実行する |
| 候補・検証観点への修正指示 | 候補の追加調査 / 検証観点の見直しを行い、更新後の候補比較を追記 |
| 結果まとめへの質問 | PoC PR 本文の記録を根拠に回答を追記 |
| 結果まとめへの追加検証の依頼 | 該当 PoC PR に追加の検証観点を書いた再検証指示コメント（`receiver`: `library-poc-runner`）を投稿してから `$AI_MONITOR_LABEL_CONFIRM_LIBRARY_POC_RUNNER` を再付与し、依頼を受け付けた旨を追記 |
| 外部ライブラリ Wiki への修正指示 | `外部ライブラリ/{lib名}.md` を修正して commit push し、短く追記 |
| 適合候補なしの相談への方針指示 | 指示された方針（自作 / 要件緩和 / 設計変更）で候補調査をやり直し、結果を追記 |
| 設計差し戻しの修正内容への修正指示 | 設計 Wiki を修正して commit push し、修正 commit の ID を追記 |
| 上記以外 | 文脈から必要な対応を判断して実施し、対応内容を短く追記 |

対応内容はユーザーがその指摘を書いたコメントに返信追記する（規約『コメント』の「どのコメントに返信するか」）。
自分が過去に投稿した提案・報告コメントに積み増さない。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: ユーザーが指摘を書いたコメントの node_id
- `sender`: `architect`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `plain`
  - `body`: 返信本文

### 決着したスレッドの Resolve

インライン確認事項のスレッドを 1 件ずつ見て、この往復で内容が確定したものだけを畳む。

MCP `list_review_threads` を呼ぶ:
- `pr_number`: 対象 PR の番号
- `addressee`: 自分のエージェント名
- `include_resolved`: false

スレッドごとに、ユーザーの返信（`thumbs_up_by` に本人が入っていれば推奨案への同意とみなす）で論点が決まったかを判断する。

- 決まった場合、MCP `reply_review_thread` で確定内容を返信してから MCP `resolve_review_threads` で畳む
- 決まっていない場合（回答がない・回答だけでは実装を決められない）は畳まず、次の「未決着スレッドの再確認」へ持ち越す

### 未決着スレッドの再確認

畳めなかったスレッドが 1 件も無い場合、本手順は実行しない。

残っている場合は、何が未回答かを名指しした確認コメントを MCP `comment` で投稿する:
- `number`: 対象 PR の番号
- `is_pr`: true
- `sender`: 自分のエージェント名
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 未決着スレッドの一覧（各スレッドへのリンク + 何が決まっていないか + 選べる案）

続けて MCP `add_labels` で `$AI_MONITOR_LABEL_IN_DISCUSSION` の値を付ける（既に付いていれば冪等）。
ユーザーが `議論中` を外して完了へ進めようとした場合でも、決めきれていない論点が残っていればここで議論に戻す。

- ただし戻すのは 1 回まで。回答なしの除去が 2 回目以降なら推奨案への承認とみなし、本手順を実行せず各スレッドに確定の返信をして Resolve する（共通ルール『議論中ラベル』の「回答なしで外されたとき」）

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
