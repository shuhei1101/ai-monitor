# 設計完了の引き渡し

担当分の設計 Wiki が全て確定したので、設計タスクにチェックを入れて発注元の subsystem-conductor へ成果物 PR を返す。

次の段階（モジュール構成 / テスト作成）は成果物ブランチが別になるため、tester へは直接渡さず conductor がマージしてから次のブランチを切る（`プロジェクト管理/エージェント組織図.md`）。

## 手順

### 自分宛コメントの選別

未回答・未対応の自分宛コメントが残る場合は「応答ループ」に戻ってユーザーに確認質問を投げる（以降の手順は実行しない）。

未解決のインライン確認事項スレッドが残っている場合も同じ扱いにする（応答ループの「決着したスレッドの Resolve」で畳めなかったものが該当する）。
決めきれていない論点を残したまま次工程へ渡さない。

### 一括 Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 成果物 PR の自分宛コメントの `node_id` 配列

### タスク一覧のチェック

成果物 PR 本文の `## タスク一覧` の設計タスクを `[x]` にする。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### subsystem-conductor への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `architect`
- `receiver`: `subsystem-conductor`
- `format`:
  - `type`: `pages`
  - `body`: 設計の完了報告（確定させたページ名と要点。次の段階でテスト観点の起点になるページも書く）
  - `entries`: 各ページの `page` と `commit`（範囲があれば `start_commit` も）の組

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `architect`
- `number`: $pr_number
