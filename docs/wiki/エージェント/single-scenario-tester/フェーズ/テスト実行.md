# テスト実行

テスト結果表に並んだ全行（新規 + 回帰）を実行し、結果を本文へ記入して single-scenario-writer に報告する。

## 手順

### 実行対象の確認

story ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は story PR の `head_ref`）へ移動して最新化する。

story PR 本文の `## 単一ユースケースシナリオテスト結果` から実行するテストを確定する。

- 修正 + 再実行の再開指示で起動した場合、指示に沿ってテストコードを修正して commit push してから実行する（シナリオ修正が伴う場合は修正後のシナリオを取り込む。差分の取得は共通ルール『PR差分の取得』）

### テストの実行

テスト結果表の全行を実行し、結果を収集する（実行コマンドは `テスト/テスト実行方法.md`。ターミナルへの報告は共通ルール『ターミナル出力』）。

### テスト結果表の記入

結果列を実行結果で埋める（`✅` / `❌`）。

- fail がある場合、補足列に失敗したケース名と失敗内容を記録する

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### 指示コメントの Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 実行指示（または修正 + 再実行の再開指示）コメントの node_id

### single-scenario-writer への報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `single-scenario-tester`
- `receiver`: `single-scenario-writer`
- `body`:
  - 全 pass の場合: 実行したテストの一覧と全 pass の結果 + 積んだ commit の表（修正を伴った場合）
  - fail がある場合: 失敗したケース名・失敗内容・実行ログの要点

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_WRITER` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `single-scenario-tester`
- `number`: $pr_number
