# 応答ループ

シナリオ作成後の待機中に来たユーザーフィードバックに応じてシナリオ md を修正 push し、再び待機に入る。

## 手順

### 内容に応じた対応


| フィードバックの種別 | 対応 |
| --- | --- |
| ノードの追加・削除・順序変更 | シナリオ md の mermaid 図を修正 |
| つなぎ目の粒度・focus 範囲の変更 | `subgraph FOCUS` の範囲やラベルを修正 |
| 異常シナリオの追加 | 該当シナリオファイルに `## 異常シナリオ（{条件}）` を追加 |
| 質問への回答 | 回答を該当コメントに返信追記（本文・シナリオファイルは触らない） |

シナリオ修正の場合は 成果物ブランチの worktree で:

- `git add docs/wiki/設計図/シナリオ/複合ユースケース/{機能名}.md`
- `git commit -m "{機能名}複合シナリオを{修正内容の要約}"`
- `git push`

修正内容はユーザーがその指摘を書いたコメントに返信追記する（規約『コメント』の「どのコメントに返信するか」）。
自分が過去に投稿した提案・報告コメントに積み増さない。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: ユーザーが指摘を書いたコメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 修正内容の要約

### タスク一覧のチェック

修正を commit した場合だけ実行する。

成果物 PR 本文の `## タスク一覧` のうち、自分が作成 / 更新した複合 UC シナリオとシナリオ索引の行が未チェックなら `[x]` にする。
チェックを入れるのは作業した本人なので、モック作成・E2E テストの行には触れない。
待機を挟むと、ユーザーが開いたときに commit 済みなのに未チェックの状態になる。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### 決着したスレッドの Resolve


インライン確認事項のスレッドを 1 件ずつ見て、この往復で内容が確定したものだけを畳む。

MCP `list_review_threads` を呼ぶ:
- `pr_number`: 対象 PR の番号
- `addressee`: 自分のエージェント名
- `include_resolved`: false

スレッドごとに、ユーザーの返信（`thumbs_up_by` に本人が入っていれば推奨案への同意とみなす）で論点が決まったかを判断する。

- 決まった場合、MCP `reply_review_thread` で確定内容を返信してから MCP `resolve_review_threads` で畳む
- 決まっていない場合（回答がない・回答だけでは実装を決められない）は畳まず、次の「未決着スレッドの再確認」へ持ち越す

### 未決着スレッドの再確認


畳めなかったスレッドが 1 件も無い場合、本手順は実行しない。

残っている場合は、何が未回答かを名指しした確認コメントを MCP `comment` で投稿する:
- `number`: 対象 PR の番号
- `is_pr`: true
- `sender`: 自分のエージェント名
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 未決着スレッドの一覧（各スレッドへのリンク + 何が決まっていないか + 選べる案）

続けて MCP `add_labels` で `$AI_MONITOR_LABEL_IN_DISCUSSION` の値を付ける（既に付いていれば冪等）。
ユーザーが `議論中` を外して完了へ進めようとした場合でも、決めきれていない論点が残っていればここで議論に戻す。
- ただし戻すのは 1 回まで。回答なしの除去が 2 回目以降なら推奨案への承認とみなし、本手順を実行せず各スレッドに確定の返信をして Resolve する（共通ルール『議論中ラベル』の「回答なしで外されたとき」）

### assignee 再設定


MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告


MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-writer`
- `number`: $pr_number
