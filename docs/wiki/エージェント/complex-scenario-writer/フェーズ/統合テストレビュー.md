# 統合テストレビュー

complex-scenario-tester が実装した E2E テストコードと実行対象（新規 + 回帰）を複合 UC シナリオと照合し、テストを実行して結果を判定する。
指摘は tester に直接差し戻し、fail は原因をトリアージして差し戻し先を決める。

## 手順

### テストコードの照合

epic ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は epic PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

完了報告のコミット表から見る範囲を決めて差分を取得し（共通ルール『PR差分の取得』）、自分が確定させた複合 UC シナリオと一対一で突き合わせて確認する。

- シナリオの正常 / 異常の各シナリオがテスト関数として実装されているか
- 期待値がシナリオの `### 期待値` と一致しているか
- テスト結果表の回帰対象が、本 epic で変更した結合ドキュメントの影響範囲を覆っているか

分岐:

- 過不足がある場合、「インライン指摘の投稿」へ進む
- 過不足がない場合、「テストの実行」へ進む（「インライン指摘の投稿」は実行しない）

### インライン指摘の投稿

指摘 1 件ごとに MCP `create_review_comment` を呼ぶ:
- `pr_number`: $pr_number
- `path`: 指摘対象のファイルパス
- `line`: 指摘対象の行
- `sender`: `complex-scenario-writer`
- `receiver`: `complex-scenario-tester`
- `body`: シナリオとの差異（観点の欠落・期待値の不一致・回帰対象の漏れ）と期待する修正

続けて MCP `reply_comment` を呼ぶ:
- `comment_node_id`: complex-scenario-tester のテスト実装完了報告コメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: `complex-scenario-tester`
- `format`:
  - `type`: `plain`
  - `body`: インライン指摘への対応依頼（指摘の件数と要点。スレッドは Resolve しない）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_TESTER` の値

「作業完了報告」を実行して自ターンを終える（以降の手順は実行しない）。

### テストの実行

`テスト/テスト実行方法.md` のコマンドで、テスト結果表の全行（新規 + 回帰）を実行する。

実行結果でテスト結果表（`## 複合ユースケースシナリオテスト結果`）の結果列を埋める（`✅` / `❌`）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

分岐:

- 全行が `✅` の場合、「レビュー結果の返信と Resolve」へ進む
- `❌` がある場合、「fail のトリアージ」へ進む

### レビュー結果の返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: complex-scenario-tester のテスト実装完了報告コメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: `complex-scenario-tester`
- `format`:
  - `type`: `plain`
  - `body`: レビュー結果（照合した観点 + 指摘なし + 全 pass の実行結果）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: complex-scenario-tester のテスト実装完了報告コメントの `node_id`

### インライン指摘スレッドの解決

MCP `list_review_threads` を呼ぶ:
- `pr_number`: $pr_number
- `addressee`: `complex-scenario-writer`
- `include_resolved`: false

続けて MCP `resolve_review_threads` を呼ぶ:
- `thread_node_ids`: 取得したスレッドの `node_id` 配列

### 全 pass の完了報告

MCP `comment` を呼ぶ:
- `number`: 親 epic Issue 番号（epic PR 本文の `## 紐づく Issue` から取得）
- `is_pr`: false
- `sender`: `complex-scenario-writer`
- `receiver`: `epic-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 統合テストの完了報告（実行したテストの一覧と全 pass の結果）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値

「ラベル除去」へ進む。

### fail のトリアージ

失敗したケースの内容を複合 UC シナリオ・実装コード・E2E テストコードと照合し、原因を判定する。

| 判定 | 根拠 | 対応 |
| --- | --- | --- |
| 実装側の問題 | シナリオもテストコードも正しく、実装が期待値を満たしていない | 「実装側の問題の報告」へ進む |
| シナリオ側の問題 | シナリオの期待値が実装すべき要件と矛盾している | 「シナリオ側の問題の修正」へ進む |
| テストコード側の問題 | シナリオも実装も正しく、テストコードが誤っている | 「テストコード側の問題の差し戻し」へ進む |
| 上記以外 | 3 つのどれとも判定できない | 判定できない旨と調べた内容を添えて「実装側の問題の報告」へ進み、epic-conductor の判断を仰ぐ |

### 実装側の問題の報告

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: complex-scenario-tester のテスト実装完了報告コメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: `complex-scenario-tester`
- `format`:
  - `type`: `plain`
  - `body`: トリアージ結果（fail 内容 + 実装側の問題と判定した根拠）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: complex-scenario-tester のテスト実装完了報告コメントの `node_id`

続けて MCP `comment` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `sender`: `complex-scenario-writer`
- `receiver`: `epic-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 失敗報告（fail 内容の要約 + 該当するシナリオ + 元報告コメントへのリンク）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値

「ラベル除去」へ進む。

### シナリオ側の問題の修正

epic ブランチの worktree で複合 UC シナリオを修正して commit push する。

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: complex-scenario-tester のテスト実装完了報告コメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `plain`
  - `body`: 修正内容（修正したシナリオページ名 + 修正 commit の ID）と確認依頼

続けて MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

`確認:complex-scenario-writer` は除去しない（承認後の再開指示で復帰するため）。
「作業完了報告」を実行して自ターンを終える（「ラベル除去」は実行しない）。

### テストコード側の問題の差し戻し

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: complex-scenario-tester のテスト実装完了報告コメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: `complex-scenario-tester`
- `format`:
  - `type`: `plain`
  - `body`: テストコードの誤りの指摘と修正の再開指示（スレッドは Resolve しない = tester が処理時に Resolve する）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_TESTER` の値

「作業完了報告」を実行して自ターンを終える（「ラベル除去」は実行しない）。

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-writer`
- `number`: $pr_number
