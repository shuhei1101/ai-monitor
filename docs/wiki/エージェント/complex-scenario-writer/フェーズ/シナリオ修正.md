# シナリオ修正

epic-conductor のエスカレーション対応で決まった方針に沿って複合ユースケースシナリオを修正し、親 epic Issue へ完了報告する。

## 手順

### 修正指示の確認

修正指示コメントから、決定した方針とシナリオのどこをどう直すかを読む。
epic Issue 本文（`## ユースケース一覧` / `## 横断要件`）が更新されている場合は最新の本文も取得する。

### シナリオファイルの修正

epic ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`）で対象の複合ユースケースシナリオを修正する。
索引の記述が変わる場合は `docs/wiki/設計図/シナリオ/README.md` も更新する。

修正したファイルを commit + push する。

### 修正指示への返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: epic-conductor の修正指示コメントの node_id
- `sender`: `complex-scenario-writer`
- `receiver`: `epic-conductor`
- `body`: 修正内容（修正したシナリオページ名 + 積んだ commit の表。commit の書式は共通ルール『コミット報告』）

続けて MCP `resolve_comments` を呼ぶ:
- `node_ids`: 修正指示コメントの `node_id`

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値
- `add_labels_`: なし

### 親 epic Issue への完了報告

$pr_number の PR 本文の `## 紐づく Issue` から親 epic Issue 番号を得る。

MCP `comment` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `sender`: `complex-scenario-writer`
- `receiver`: `epic-conductor`
- `body`: エスカレーション対応で指示されたシナリオ修正の完了報告（修正したシナリオページ名 + 反映した方針 + 積んだ commit の表）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-writer`
- `number`: $pr_number
