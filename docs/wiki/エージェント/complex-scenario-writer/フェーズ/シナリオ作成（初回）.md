# シナリオ作成（初回）

親 epic PR の `## ユースケース一覧` から複合ユースケースシナリオを設計し、成果物ブランチに commit + 索引更新 push した上で待機に入る。

## 手順

### 親 epic PR の確認

成果物 PR 本文の `## 紐づく Issue` から親 epic PR 番号を得て MCP `get_issue_or_pr` を呼ぶ:
- `number`: 親 epic PR 番号
- `is_pr`: true
- `comments`: false

成果物 PR 本文の `## ユースケース一覧` の各 UC 名（`単一ユースケース/{UC名}.md` のノード名になる）と `## 横断要件` を抽出する。
画面変更ありの epic では 成果物 PR 本文の `## UI 設計` も参照する。

### シナリオファイルの新規作成

テンプレート（シナリオ）に従い、`docs/wiki/設計図/シナリオ/複合ユースケース/{機能名}.md` を新規作成する（`{機能名}` は 成果物 PR のタイトルまたはドメイン名から決める）。

- 中間ノードは `{UC名}:{シナリオ見出し}` 形式で `## ユースケース一覧` の UC 名と 1:1 対応
- 検証したい UC 間のつなぎ目を `subgraph FOCUS["検証対象: {要約}"]` で囲む
- 各 UC ノードに `click {ノードID} "../単一ユースケース/{UC名}.md#{アンカー}"` を並べる
- 正常シナリオ + 起こりうる異常シナリオを H2 で並列に書く

### 索引の更新

`docs/wiki/設計図/シナリオ/README.md` の索引に行を追加する（種別カラム = `複合ユースケース`）。

### commit + push

成果物ブランチの worktree（`.claude/worktrees/{ブランチ名}` = `${BRANCH}` を `/` → `-` 置換したパス）で以下を実行する:

- `git add docs/wiki/設計図/シナリオ/複合ユースケース/{機能名}.md docs/wiki/設計図/シナリオ/README.md`
- `git commit -m "{機能名}複合シナリオを追加"`
- `git push`

### 確認事項の投稿

確認したい論点を洗い出し、1 論点 = 1 コメントで投稿する。
投稿先は論点がシナリオの特定箇所に紐づくかで分ける。

特定の記述についての判断（期待値の置き方・異常シナリオの切り出し方 等）は、論点 1 件ごとに MCP `create_review_comment` を呼ぶ:
- `pr_number`: $pr_number
- `path`: 対象シナリオのパス
- `line`: 論点にあたる行
- `sender`: `complex-scenario-writer`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `body`: その行で選んだ内容 + 他に取り得た選択肢 + 推奨（いま書いてある案）と理由

シナリオに紐づかない全体の方向性（UC の粒度・他 UC との境界 等）は、論点 1 件ごとに MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `complex-scenario-writer`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 論点 + 他に取り得た選択肢 + 推奨と理由

### 補足事項の投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って補足事項を該当行へ投稿する。

### 完了報告の投稿

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `complex-scenario-writer`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: シナリオ作成の完了報告（シナリオファイルへのリンク + 正常 / 異常シナリオの要点 + 承認・修正方法の案内）

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-writer`
- `number`: $pr_number
