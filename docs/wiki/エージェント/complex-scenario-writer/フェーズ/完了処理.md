# 完了処理

シナリオ合意（`議論中` 除去）を受けて、PR の `確認:complex-scenario-writer` を除去し、親 epic Issue に確認ラベルを渡して役割を終える。

## 手順

### 自分宛コメントの選別

未回答・未対応の自分宛コメントが残る場合は「応答ループ」に戻ってユーザーに確認質問を投げる（以降の手順は実行しない）。

未解決のインライン確認事項スレッドが残っている場合も同じ扱いにする（応答ループの「決着したスレッドの Resolve」で畳めなかったものが該当する）。
決めきれていない論点を残したまま次工程へ渡さない。

### 一括 Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分宛コメントの `node_id` 配列

### タスク一覧のチェック

epic PR 本文の `## タスク一覧` のうち、自分が作成 / 更新した複合 UC シナリオとシナリオ索引の行を `[x]` にする。
チェックを入れるのは作業した本人なので、モック作成・E2E テストの行には触れない。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### 完了報告の投稿

$pr_number の PR 本文の `## 紐づく Issue` から親 epic Issue 番号を得る。

MCP `comment` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `sender`: `complex-scenario-writer`
- `receiver`: `epic-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 複合シナリオ設計の完了報告（シナリオファイルへのリンク + 検証対象のつなぎ目の要点 + 確認後の Resolve 依頼）

### 確認ラベルの引き継ぎ

MCP `add_labels` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-writer`
- `number`: $pr_number
