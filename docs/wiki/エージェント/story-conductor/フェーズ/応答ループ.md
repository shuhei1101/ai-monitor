# 応答ループ

待機中のユーザーフィードバックに対応し、再び待機に入る。
どの待機（要件確定・バグ差し戻しの方針調整・エスカレーション対応の方針調整）かは、未解決の自分宛スレッドの文脈で判断する。

## 手順

### 内容に応じた対応

| 待機の文脈 | 対応 |
| --- | --- |
| 要件確定の本文修正指示 | 本文を修正（`update_body`）して「本文の `## XXX` を更新しました」と短く追記 |
| バグ差し戻しの方針調整 | 方針案コメントを更新して短く追記 |
| エスカレーション対応方針案の調整 | 方針案コメントを更新して短く追記 |
| RE の起こし漏れの指摘 | 共通フェーズ『リバースエンジニアリング起動』の `### 作成依頼` を追加範囲で実行して短く追記 |
| RE 差し戻しの相談への判断 | 判断内容を短く追記（担当範囲の見直しなら `### 作成依頼` を実行） |
| 上記以外 | 文脈から必要な対応を判断して実施し、対応内容を短く追記 |

追記は MCP `reply_comment` を呼ぶ:
- `comment_node_id`: ユーザーが指摘を書いたコメントの node_id（規約『コメント』の「どのコメントに返信するか」。自分の過去の報告コメントに積み増さない）
- `sender`: `story-conductor`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 返信本文

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $issue_number
