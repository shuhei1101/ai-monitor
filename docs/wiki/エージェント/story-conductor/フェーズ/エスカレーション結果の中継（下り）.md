# エスカレーション結果の中継（下り）

epic-conductor から降りてきたエスカレーションの決定を受けて、発生元の subsystem へ降ろす。

## 手順

### 決定内容の確認

決定コメントから、subsystem が再開時に従うべき方針（要件の変更点・前提の変更）を読み取る。

- story Issue 本文（`## ユースケース要件`）の変更を伴う決定だった場合、先に `update_body` で本文を更新する

### 決定コメントへの返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: epic-conductor の決定コメントの node_id
- `sender`: `story-conductor`
- `receiver`: `epic-conductor`
- `body`: 受領と、subsystem に降ろす作業の要約

続けて MCP `resolve_comments` で自分宛コメントを一括 Resolve する。

### 発生元 subsystem への決定通知

MCP `add_labels` を呼ぶ:
- `number`: 発生元の subsystem Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値

続けて MCP `comment` を呼ぶ:
- `number`: 発生元の subsystem Issue 番号
- `is_pr`: false
- `sender`: `story-conductor`
- `receiver`: `subsystem-conductor`
- `body`: 決定した方針と、それを踏まえて再開してほしい作業

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $issue_number
