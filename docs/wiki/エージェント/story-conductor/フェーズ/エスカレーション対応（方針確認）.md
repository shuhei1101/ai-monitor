# エスカレーション対応（方針確認）

subsystem-conductor から上がった論点に対して、story レイヤー（単一 UC の範囲）で打てる手と上位への中継を選択肢にしてユーザーに確認する。

## 手順

### 論点の整理と解決案の検討

中継コメントから論点と経緯を読む。
そのうえで、story レイヤー（単一 UC の分割・subsystem の分け方の組み替え・UC 内での代替手段など、1 ユースケースに閉じた範囲）で打てる手があるかを検討する。

素通しはしない。
打てる手が思いつかない場合も、その理由を添えて選択肢に「上位への中継」だけを残す形で提示する。

### 対応方針案の投稿

MCP `comment` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `sender`: `story-conductor`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `plain`
  - `body`:
    ```
    {論点の要約} について、story レベルでの対応方針案です。

    | 案 | 内容 | 想定影響 |
    | --- | --- | --- |
    | A | {単一 UC の範囲で打てる手} | {影響する subsystem} |
    | B | 親 epic へエスカレーションする | {story では解決できない理由} |

    推奨: {A / B}（{理由}）

    - 方針が決まったら記号で返信 + `議論中` ラベルを外す → その方針で進めます
    - 調整が必要なら assignee を外してフィードバックコメントを記入
    ```

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $number
- `is_pr`: true

`確認:story-conductor` は除去しない（選択後の実行で復帰するため）。

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $number
