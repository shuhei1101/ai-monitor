# 初期処理

毎ターン最初に必ず実行する。

## 手順

### 面の種別の判定

story の面は通常 PR だが、ユーザーが Issue へ直接 `確認:story-conductor` を付けて起動することがある。
以降の手順の `is_pr` はここで判明した値を使う。

MCP `get_issue_or_pr` を `is_pr`: true で呼び、404 が返った場合は対象が Issue なので `is_pr`: false で取り直す。

### 最新状態の取得

MCP `get_issue_or_pr` を呼ぶ:
- `number`: $number
- `is_pr`: 判明した面の種別
- `parent`: true
- `sub_issues`: true

続けて MCP `list_comments` を呼ぶ:
- `number`: $number
- `is_pr`: 判明した面の種別
- `addressee`: `story-conductor`
- `include_resolved`: false

### closed 対象の終了判定

取得結果の `state` が `closed` の場合、着手せず自ターンを終える（規約『フェーズ索引の網羅』）。
本文・コメントには手を加えない。

MCP `transition_phase` を呼ぶ:
- `number`: closed だった対象の番号
- `is_pr`: 対象が PR なら true
- `remove_labels_`:
  - 自分の確認ラベル（`AI_MONITOR_LABEL_CONFIRM_*`）の値
  - 自分の処理中ラベル（`AI_MONITOR_LABEL_PROCESSING_*`）の値

続けて MCP `report_completion` を呼び、以降の手順は実行しない。

- `state` が `open` の場合、「フェーズの決定」へ進む

### フェーズの決定

フェーズ索引のフェーズ一覧を上から順に見て、起動条件に最初にマッチしたフェーズの手順を実行する。
