# エスカレーションの中継

subsystem-conductor から上がった論点のうち story レイヤーで判断できないものを、親 epic Issue の epic-conductor へ渡す。

## 手順

### 中継内容の整理

エスカレーションコメントから論点と経緯を要約する。
方針の決定は論点のレイヤーの conductor が行うため、中継役は判断を書かない。

- story レイヤーで判断できる論点だった場合、中継せず該当フェーズ（子subsystem起票 / バグ差し戻し 等）で応答する（以降の手順は実行しない）

### エスカレーションコメントの Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: subsystem-conductor のエスカレーションコメントの `node_id`

### 親 epic Issue への中継

MCP `add_labels` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_EPIC_CONDUCTOR` の値

続けて MCP `comment` を呼ぶ:
- `number`: 親 epic Issue 番号
- `is_pr`: false
- `sender`: `story-conductor`
- `receiver`: `epic-conductor`
- `body`: 論点の要約 + 元コメントへのリンク（発生元の subsystem Issue / PR 番号を含める）

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値
- `add_labels_`: なし（発生元の subsystem 側は保留のまま）

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $issue_number
