# 要件確定（完了処理）

承認された要件をもとに story Draft PR を作成し、single-scenario-writer に引き継ぐ。

## 手順

### 自分宛コメントの選別

未回答・未対応の自分宛コメントが残る場合は「応答ループ」に戻ってユーザーに確認質問を投げる（以降の手順は実行しない）。

### 一括 Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分宛コメントの `node_id` 配列

### 成果物 Draft PR の作成

単一 UC 影響がある場合だけ、単一UCシナリオの成果物ブランチ + Draft PR を作る。

- 単一 UC 影響なしの場合は本手順を実行せず、次ターンで「子subsystemPR作成（初回）」へ進む

自分の story ブランチ名 `{type}/story/{ドメイン}/{UC名}/base` からドメイン部と UC 名を取り出して成果物ブランチを組み立てる。

MCP `worktree_create` を呼ぶ:
- `branch`: `docs/story/{ドメイン}/{UC名}/scenario`
- `base_ref`: `origin/{自分の story ブランチ}`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: 自分の story ブランチ
- `title`: `{story のタイトル}（単一ユースケースシナリオ）`
- `body`: `## 紐づく Issue`（story PR と同じ起点の Issue 番号）と `## タスク一覧`
- `labels`: `$AI_MONITOR_LABEL_TYPE_DOCS` の値

`## タスク一覧` は作成 / 更新する単一 UC シナリオのページとシナリオ索引の更新をチェックボックスで列挙する（書式はテンプレート「PR本文/成果物」）。
チェックは各行を担当した作業者が入れるので、ここでは全行を未チェックで作る。
単一 UC E2E テストの作成 / 実行は、後続で切る `test/story/{ドメイン}/{UC名}/integration` の成果物 PR が持つ。

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $number
- `watch_numbers`: 作成した PR の番号

### 次フェーズの割り当て

単一 UC 影響なしの場合は本手順を実行しない。

MCP `add_labels` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_WRITER` の値

### ラベル除去

単一 UC 影響なしの場合は本手順を実行しない（`確認:story-conductor` を保持したまま自ターンを終え、次のターンで「子subsystem起票（初回）」に入る）。

MCP `transition_phase` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $number
