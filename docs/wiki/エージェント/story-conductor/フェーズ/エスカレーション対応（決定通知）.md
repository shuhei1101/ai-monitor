# エスカレーション対応（決定通知）

エスカレーション対応で指示した単一シナリオ修正の完了を受けて、発生元の subsystem へ決定を降ろす。

## 手順

### 修正内容の確認

single-scenario-writer の完了報告のコミット表から差分を取得し（共通ルール『PR差分の取得』）、指示した方針が単一 UC シナリオに反映されているかを照合する。

### 完了報告の Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: single-scenario-writer の完了報告コメントの `node_id`

### 発生元 subsystem への決定通知

MCP `add_labels` を呼ぶ:
- `number`: 発生元の subsystem Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値

続けて MCP `comment` を呼ぶ:
- `number`: 発生元の subsystem Issue 番号
- `is_pr`: false
- `sender`: `story-conductor`
- `receiver`: `subsystem-conductor`
- `body`: 決定した方針・修正後の単一 UC シナリオのページ名・それを踏まえて再開してほしい作業

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `story-conductor`
- `number`: $issue_number
