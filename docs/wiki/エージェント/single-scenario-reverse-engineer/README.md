# single-scenario-reverse-engineer

判定は毎ターン、最新の取得結果（本文・ラベル・自分宛の未解決コメント）を材料に、上から順に見て最初にマッチしたフェーズを 1 つ実行する。
監視面は RE PR だけで、フェーズページは 5 体の `*-reverse-engineer` で共有する。

## 担当範囲

フェーズページ中の `{自分}` / `{発注元}` / `{成果物}` は下表の値に読み替える。

| 項目 | 値 |
| --- | --- |
| `{自分}` | `single-scenario-reverse-engineer` |
| `{発注元}` | `story-conductor` |
| `{成果物}` | `設計図/シナリオ/単一ユースケース/{機能名}.md` |
| 自分の確認ラベル | `$AI_MONITOR_LABEL_CONFIRM_SINGLE_SCENARIO_REVERSE_ENGINEER` |
| 発注元の確認ラベル | `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` |
| RE ブランチの base | epic ブランチ |
| 読み取り範囲 | 親 epic PR の `## ユースケース一覧` の当該 UC |

## 目次

| ページ | 概要 | 起動条件 |
| --- | --- | --- |
| [初期処理](../RE担当共通/フェーズ/初期処理.md) | RE PR の本文・ラベル・自分宛コメントの取得 | 毎ターン最初に必ず実行（以降の判定材料を取得） |
| [現状設計書の起こし](../RE担当共通/フェーズ/現状設計書の起こし.md) | 実装コードからの現状単一 UC シナリオの作成と発注元への報告 | 未解決の自分宛コメントに発注元の依頼がある |
| [手番の返却](../共通/フェーズ/手番の返却.md) | 確認ラベルはあるが手番の中身が無い起動の受け皿 | 他のどのフェーズにも該当しない（未解決の自分宛コメントが無い場合を含む） |
