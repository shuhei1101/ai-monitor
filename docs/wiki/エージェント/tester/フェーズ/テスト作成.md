# テスト作成

architect が確定させた設計 Wiki を元に、テストコードを Red 状態で作成して architect に報告する。
作るのはテストコードとテスト用 fixture のみで、実装コード（データモデル・スタブ含む）は implementer の領分。

## 手順

### 割り当て内容の確認

architect の割り当てコメント（または設計修正後の再開指示）から、テスト観点の起点になる設計 Wiki のページ名を読む。

### 設計 Wiki の確認

subsystem ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は subsystem PR の `head_ref`）へ移動する。

割り当てられた結合 / モジュール構成のページを読み、テスト観点を洗い出す（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。

- 結合ドキュメントの `## 正常系` / `## 異常系（{条件}）` が結合テストのケース
- モジュール構成の `#### 単体テスト` 表が単体テストのケース
- 対応関係は 1 設計書 = 1 テストファイル

再開指示で起動した場合は、修正 commit の内容を取り込んだうえで観点を洗い直す（差分の取得は共通ルール『PR差分の取得』）。

### テストコードの作成

洗い出した観点をテストコードに変換し、既存のテスト規約（`テスト/テスト実行方法.md` と注入済みの言語規約）に従って書く。

テストを実行し、想定どおり fail することを確認する（実装ファイル不在による import エラーも Red として扱う）。

subsystem ブランチに commit push する。

- 設計 Wiki どおりに書けない構造問題（設計にないモジュール分割が必要 等）を見つけた場合、「設計の差し戻し」を実行して自ターンを終える（以降の手順は実行しない）

### テスト結果表への行追加

subsystem PR 本文のテスト結果表（`## 単体テスト結果` / `## 結合テスト結果` / `## 単一ユースケースシナリオテスト結果` / `## 複合ユースケースシナリオテスト結果`）に、作成したテストファイルの行を追加する。
結果列は未記入のままにする（記入は implementer）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### 差し戻しスレッドの Resolve

再開指示で起動した場合に実行する（設計修正の反映が済んで対応が確定したため）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分が投稿した差し戻し報告コメントの node_id

### architect への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `tester`
- `receiver`: `architect`
- `body`: テスト作成の完了報告（作成したテストファイル一覧 + 元にした設計ページ + Red であることの実行結果 + 積んだ commit の表。commit の書式は共通ルール『コミット報告』）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

「作業完了報告」へ進む。

### 設計の差し戻し

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `tester`
- `receiver`: `architect`
- `body`: 差し戻し報告（設計 Wiki のどの記述がテスト構造として成立しないか + 理由 + 想定する修正の方向）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `tester`
- `number`: $pr_number
