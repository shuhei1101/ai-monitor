# テスト作成

architect が確定させた設計 Wiki（結合 / モジュール構成）を元に、テストコードを作成して architect に報告する。
作るのはテストコードとテスト用 fixture のみで、実装コード（データモデル・スタブ含む）は implementer、テストの実行は architect の領分。

## 手順

### 割り当て内容の確認

architect の割り当てコメント（または設計修正後の再開指示）から、テスト観点の起点になる設計 Wiki のページ名と、そのページを作成 / 更新した commit 範囲を読む。

### 設計 Wiki の確認

成果物ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は 成果物 PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

割り当てられた結合 / モジュール構成のページを読み、テスト観点を洗い出す（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。

- 結合ドキュメントの `## 正常系` / `## 異常系（{条件}）` が結合テストのケース
- モジュール構成の `#### 単体テスト` 表が単体テストのケース
- 対応関係は 1 設計書 = 1 テストファイル

あわせて渡された commit 範囲の差分を取り、今回新規に定義された構成要素と既存から変更された構成要素を区別する（差分の取得は共通ルール『PR差分の取得』）。
新規はテストを新設し、変更は既存テストの改修になる。

### テストコードの作成

洗い出した観点をテストコードに変換し、既存のテスト規約（`テスト/テスト実行方法.md` と注入済みの言語規約）に従って書く。

成果物ブランチに commit push する（テストの実行は architect が行うので、ここでは実行しない）。

- 設計 Wiki どおりに書けない構造問題（設計にないモジュール分割が必要 等）を見つけた場合、「設計の差し戻し」を実行して自ターンを終える（以降の手順は実行しない）

### テスト結果表への行追加

親 subsystem PR 本文のテスト結果表（`## 単体テスト結果` / `## 結合テスト結果` / `## 単一ユースケースシナリオテスト結果` / `## 複合ユースケースシナリオテスト結果`）に、作成したテストファイルの行を追加する。
結果列は未記入のままにする（記入は architect）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### タスク一覧のチェック

親 subsystem PR 本文の `## タスク一覧` のうち、自分が作成したテストに対応する行を `[x]` にする。
チェックを入れるのは作業した本人なので、設計・実装・テスト実行の行には触れない。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### インラインコメントの投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って確認事項と補足事項を該当行へ投稿する。

### 差し戻しスレッドの Resolve

再開指示で起動した場合に実行する（設計修正の反映が済んで対応が確定したため）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 自分が投稿した差し戻し報告コメントの node_id

### 依頼コメントの Resolve

起動のトリガーになった依頼 / 割り当てコメント（再開指示で起動した場合は再開指示コメント）を畳む。
受け取った依頼は自分の作業が終わった時点で片付ける（ユーザーが読む必要はなく、未解決のまま溜めない）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 初期処理で取得した、起動のトリガーになった依頼コメントの `node_id`

- 依頼コメントを伴わずに確認ラベルだけで起動した場合は、本手順を実行しない

### architect への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `tester`
- `receiver`: `architect`
- `format`:
  - `type`: `commits`
  - `body`: テスト作成の完了報告（作成したテストファイル一覧 + 元にした設計ページ）
  - `entries`: 積んだ commit の `commit` と `summary` の組

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

「作業完了報告」へ進む。

### 設計の差し戻し

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `tester`
- `receiver`: `architect`
- `format`:
  - `type`: `plain`
  - `body`: 差し戻し報告（設計 Wiki のどの記述がテスト構造として成立しないか + 理由 + 想定する修正の方向）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `tester`
- `number`: $pr_number
