# 指摘対応

architect の指摘（設計 Wiki との差異・テストコードの誤り）に沿ってテストコードを修正し、同じスレッドに返信して再レビューに戻す。

## 手順

### 指摘の取得

MCP `list_review_threads` を呼ぶ:
- `pr_number`: $pr_number
- `addressee`: `tester`
- `include_resolved`: false

テストコードの誤りの指摘（実装レビューの fail トリアージ由来）はインラインではなく通常コメントで届くため、初期処理で取得した自分宛コメントもあわせて対象にする。

各スレッドの `path` / `line` / `diff_hunk` / 本文から、指摘対象の箇所と期待する修正を把握する。

### テストコードの修正

成果物ブランチの worktree へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

指摘 1 件ずつ修正する。

修正したテストコードを commit push する。

- 指摘の内容が設計 Wiki の見直しを要する場合、「テスト作成」の「設計の差し戻し」を実行して自ターンを終える（以降の手順は実行しない）

### テスト結果表の更新

テストファイルの追加・削除を伴う修正だった場合、親 subsystem PR 本文のテスト結果表の行を実態に合わせる。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### インラインコメントの投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って確認事項と補足事項を該当行へ投稿する。

### 指摘スレッドへの返信

`is_addressed` が true のスレッドごとに MCP `reply_review_thread` を呼ぶ:
- `thread_node_id`: 対象スレッドの `node_id`
- `sender`: `tester`
- `receiver`: `architect`
- `body`: その指摘に対する対応内容（対応した commit の ID を含める）

指摘ごとに 1 回ずつ呼ぶ（指摘と対応が同じスレッドに並ぶ状態にする）。

### 対応依頼への返信

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: architect の対応依頼コメントの node_id
- `sender`: `tester`
- `receiver`: `architect`
- `format`:
  - `type`: `commits`
  - `body`: 修正完了の報告（指摘ごとの対応内容）
  - `entries`: 積んだ commit の `commit` と `summary` の組

### ラベル遷移

MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `tester`
- `number`: $pr_number
