# テスト実装

複合 UC シナリオを E2E テストコードに変換し、回帰確認の対象とあわせてテスト結果表に並べて complex-scenario-writer に報告する。
テストの実行は行わない（実行は complex-scenario-writer が統合テストレビューで行う）。

## 手順

### シナリオと回帰対象の確認

成果物ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は 成果物 PR の `head_ref`）へ移動し、`git pull --ff-only` でリモートの最新を取り込む。

complex-scenario-writer の割り当てコメントから、E2E テスト化するシナリオのページ名と、そのページを作成 / 更新した commit 範囲を読む。

`docs/wiki/設計図/シナリオ/複合ユースケース/{シナリオ名}.md` を読み、正常 / 異常の各シナリオと期待値を把握する（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。
あわせて渡された commit 範囲の差分を取り、今回新規に書かれたシナリオと既存から変更されたシナリオを区別する（差分の取得は共通ルール『PR差分の取得』）。
新規はテストを新設し、変更は既存テストの改修になる。

`設計図/シナリオ/README.md` の索引と、本 epic で変更した結合ドキュメントから、影響を受ける既存 E2E テストを回帰確認の対象として洗い出す。

### E2E テストコードの作成

シナリオの `### セットアップ` / `### フロー` / `### 期待値` を、既存のテスト規約（`テスト/テスト実行方法.md` と注入済みの言語規約）に従って E2E テストコードへ変換する。
1 シナリオ = 1 テスト関数で、関数名はシナリオ見出しと機械対応させる。

commit push する。

### テスト結果表への行追加

成果物 PR 本文の `## 複合ユースケースシナリオテスト結果` に、新規作成したテストと回帰確認の対象の行を追加する（セクションが無ければ新設する。書式は PR本文テンプレート「統合テスト」）。
結果列は未記入のままにする（記入は complex-scenario-writer）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### タスク一覧のチェック

成果物 PR 本文の `## タスク一覧` の E2E テストコード作成の行を `[x]` にする。
チェックを入れるのは作業した本人なので、モック・シナリオ・テスト実行の行には触れない。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

- PR 本文に `## タスク一覧` が無い場合、本手順は実行しない（シナリオ影響なしで通過した epic / story が該当する）

### インラインコメントの投稿

commit した内容を読み返し、共通ルール『インラインコメント』に沿って確認事項と補足事項を該当行へ投稿する。

### 依頼コメントの Resolve

起動のトリガーになった依頼 / 割り当てコメント（再開指示で起動した場合は再開指示コメント）を畳む。
受け取った依頼は自分の作業が終わった時点で片付ける（ユーザーが読む必要はなく、未解決のまま溜めない）。

MCP `resolve_comments` を呼ぶ:
- `node_ids`: 初期処理で取得した、起動のトリガーになった依頼コメントの `node_id`

- 依頼コメントを伴わずに確認ラベルだけで起動した場合は、本手順を実行しない

### complex-scenario-writer への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `complex-scenario-tester`
- `receiver`: `complex-scenario-writer`
- `format`:
  - `type`: `commits`
  - `body`: テスト実装の完了報告（作成したテストファイル一覧 + 対応シナリオ + 回帰対象に選んだテストとその理由）
  - `entries`: 積んだ commit の `commit` と `summary` の組

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-tester`
- `number`: $pr_number
