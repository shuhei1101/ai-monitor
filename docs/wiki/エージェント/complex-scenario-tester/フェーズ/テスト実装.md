# テスト実装

複合 UC シナリオを E2E テストコードに変換し、回帰確認の対象とあわせてテスト結果表に並べて complex-scenario-writer に報告する。
実行は次のターン（レビュー通過後の実行指示）で行う。

## 手順

### シナリオと回帰対象の確認

epic ブランチの worktree（`.claude/worktrees/{ブランチ名の / を - に置換}`。ブランチ名は epic PR の `head_ref`）へ移動する。

`docs/wiki/設計図/シナリオ/複合ユースケース/{シナリオ名}.md` を読み、正常 / 異常の各シナリオと期待値を把握する。
`設計図/シナリオ/README.md` の索引と、本 epic で変更した結合ドキュメントから、影響を受ける既存 E2E テストを回帰確認の対象として洗い出す（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）。

### E2E テストコードの作成

シナリオの `### セットアップ` / `### フロー` / `### 期待値` を、既存のテスト規約（`テスト/テスト実行方法.md` と注入済みの言語規約）に従って E2E テストコードへ変換する。
1 シナリオ = 1 テスト関数で、関数名はシナリオ見出しと機械対応させる。

commit push する。

### テスト結果表への行追加

epic PR 本文の `## 複合ユースケースシナリオテスト結果` に、新規作成したテストと回帰確認の対象の行を追加する（セクションが無ければ新設する。書式は PR本文テンプレート「ストーリー」）。
結果列は未記入のままにする（記入は実行フェーズ）。

MCP `update_body` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `body`: 更新後本文

### complex-scenario-writer への完了報告

MCP `comment` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `sender`: `complex-scenario-tester`
- `receiver`: `complex-scenario-writer`
- `body`: テスト実装の完了報告（作成したテストファイル一覧 + 対応シナリオ + 回帰対象に選んだテストとその理由 + 積んだ commit の表。commit の書式は共通ルール『コミット報告』）

続けて MCP `transition_phase` を呼ぶ:
- `number`: $pr_number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_TESTER` の値
- `add_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_COMPLEX_SCENARIO_WRITER` の値

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `complex-scenario-tester`
- `number`: $pr_number
