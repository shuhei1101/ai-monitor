# 要件確定（完了処理）

承認された SA をもとにインターフェース定義の成果物 Draft PR を作成し、architect に設計を委任する。

以降の段階（モジュール構成 → テスト → 実装）は成果物ブランチが分かれるため、完了報告を受けるたびに「成果物の受け取り」で次を切る。

## 手順

### 自分宛コメントの選別

未回答・未対応の自分宛コメントが残る場合は「応答ループ」に戻ってユーザーに確認質問を投げる（以降の手順は実行しない）。

### 一括 Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: subsystem PR の自分宛コメントの `node_id` 配列

### 成果物 Draft PR の作成

自分の subsystem ブランチ名 `{type}/{scope}/{ドメイン}/{UC名}/base` から scope・ドメイン部・UC 名を取り出して成果物ブランチを組み立てる。

MCP `worktree_create` を呼ぶ:
- `branch`: `docs/{scope}/{ドメイン}/{UC名}/interface`
- `base_ref`: `origin/{自分の subsystem ブランチ}`

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: 自分の subsystem ブランチ
- `title`: `{subsystem のタイトル}（インターフェース定義）`
- `body`: `## 紐づく Issue`（subsystem PR と同じ起点の Issue 番号）と `## タスク一覧`
- `labels`: `$AI_MONITOR_LABEL_TYPE_DOCS` の値

`## タスク一覧` は作成 / 更新するインターフェース定義・ER図・画面構成のページを `## システム要件（SA）` から起こして列挙する（書式はテンプレート「PR本文/成果物」）。
チェックは各行を担当した作業者が入れるので、ここでは全行を未チェックで作る。

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: $number
- `watch_numbers`: 作成した PR の番号

### architect への設計の委任

MCP `comment` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `sender`: `subsystem-conductor`
- `receiver`: `architect`
- `format`:
  - `type`: `plain`
  - `body`: 設計の委任（確定した SA の要点と、インターフェース定義で確定させたい範囲）

続けて MCP `add_labels` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $number
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: $number
