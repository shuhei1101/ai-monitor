# エスカレーション結果の中継（下り）

story-conductor から降りてきたエスカレーションの決定を受けて、architect に再開指示を出す。

## 手順

### 決定内容の確認

決定コメントから、architect が再開時に従うべき方針（設計方針の変更点・前提の変更）を読み取る。

- subsystem PR 本文の `## システム要件（SA）` の変更を伴う決定だった場合、先に `update_body` で本文を更新する

### 決定コメントへの返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: story-conductor の決定コメントの node_id
- `sender`: `subsystem-conductor`
- `receiver`: `story-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 受領と、architect に渡す作業の要約

続けて MCP `resolve_comments` で自分宛コメントを一括 Resolve する。

### architect への再開指示

再開指示は architect が作業している成果物 PR へ返す（決定が降りてきた面とは別。architect は自分の成果物 PR で待っている）。

MCP `comment` を呼ぶ:
- `number`: architect が作業している成果物 PR の番号
- `is_pr`: true
- `sender`: `subsystem-conductor`
- `receiver`: `architect`
- `format`:
  - `type`: `plain`
  - `body`: 決定した方針と、それを踏まえて再開してほしい作業

続けて MCP `add_labels` を呼ぶ:
- `number`: architect が作業している成果物 PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: 決定コメントを受け取った面の番号（subsystem PR or $number）
- `is_pr`: 受け取った面が PR なら true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: `$AI_MONITOR_LABEL_PROCESSING_SUBSYSTEM_CONDUCTOR` が付いている面の番号（subsystem PR or $number）
