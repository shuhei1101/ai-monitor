# バグ修正着手

上位 conductor から差し戻されたバグの影響範囲を分析し、修正用 Draft PR を作成して architect に委任する。

## 手順

### 影響範囲の分析

バグ内容コメントの fail 内容から、修正が必要な設計書・実装・単体テストを洗い出す。
あわせて、原因が要件の誤りで `## システム要件（SA）` の変更を伴うかを判定する。

- SA の変更が必要な場合、「SA 変更案の提示 + 待機」へ進む（「修正用 PR の作成」以降は実行しない）
- SA の変更が不要な場合、「修正用 PR の作成」へ進む

### SA 変更案の提示 + 待機

MCP `comment` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `sender`: `subsystem-conductor`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `plain`
  - `body`: SA 変更案（変更箇所 + 変更後の要件 + バグとの因果）

続けて MCP `add_labels` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false

「作業完了報告」を実行して自ターンを終える（承認後は「SA変更確定」で再開する）。

### 修正用 PR の作成

MCP `search_issues_and_prs` で親 story Issue 番号を本文に含む open PR を特定し、MCP `get_issue_or_pr`（`is_pr`: true・`comments`: false）の `head_ref` から親 story ブランチ名を得る。
取り出したドメイン部と UC 名 + 本 subsystem の `scope:*` + 修正内容から修正用ブランチを組み立てる。

MCP `worktree_create` を呼ぶ:
- `branch`: `fix/{scope}/{ドメイン}/{UC名}/{変更内容}`
- `base_ref`: `origin/{統合テストを実行しているブランチ}`（差し戻し元のレイヤーに対応）

続けて MCP `create_draft_pr` を呼ぶ:
- `head_branch`: 作成したブランチ
- `base_branch`: 統合テストを実行しているブランチ（story レベルの差し戻しは親 story ブランチ・epic レベルの差し戻しは story ブランチ削除済みのため epic ブランチ）
- `title`: 修正内容のタイトル
- `body`: `## 紐づく Issue`（`- #$issue_number`）と `## タスク一覧`（設計書修正・実装修正・単体テスト修正）

### 監視面の登録

MCP `add_watch_targets` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: $issue_number
- `watch_numbers`: 作成した PR の番号

### バグ内容コメントへの返信と Resolve

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: バグ内容コメントの node_id
- `sender`: `subsystem-conductor`
- `receiver`: `story-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 着手報告（修正用 PR のリンク + 影響範囲の要約）

続けて MCP `resolve_comments` で subsystem Issue の自分宛コメントを一括 Resolve する。

### architect への一式委任

MCP `add_labels` を呼ぶ:
- `number`: 作成した PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値
- `add_labels_`: なし（subsystem Issue は open のまま）

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: $issue_number
