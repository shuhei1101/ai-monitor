# エスカレーション対応（実行）

承認された方針で、architect に再開指示を出すか、親 story Issue へ中継する。

## 手順

### 選択された方針の確認

対応方針案コメントへのユーザー返信から、選ばれた案を確定する。

- subsystem レベルの解決案が選ばれた場合、「architect への再開指示」へ進む
- 上位への中継が選ばれた場合、「親 story Issue への中継」へ進む（「architect への再開指示」は実行しない）

### architect への再開指示

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: architect のエスカレーション報告コメントの node_id
- `sender`: `subsystem-conductor`
- `receiver`: `architect`
- `body`: 決定した方針と、それを踏まえて再開してほしい作業

続けて MCP `resolve_comments` で subsystem PR の自分宛コメントを一括 Resolve する。

続けて MCP `comment` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true
- `sender`: `subsystem-conductor`
- `receiver`: `architect`
- `body`: 決定した方針と、それを踏まえて再開してほしい作業

続けて MCP `add_labels` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値

「ラベル除去」へ進む。

### 親 story Issue への中継

MCP `reply_comment` を呼ぶ:
- `comment_node_id`: architect のエスカレーション報告コメントの node_id
- `sender`: `subsystem-conductor`
- `receiver`: `architect`
- `body`: 親 story へ中継する旨（決定は上位から降りてくるため待機を継続する）

続けて MCP `resolve_comments` で subsystem PR の自分宛コメントを一括 Resolve する。

続けて MCP `comment` を呼ぶ:
- `number`: 親 story Issue 番号
- `is_pr`: false
- `sender`: `subsystem-conductor`
- `receiver`: `story-conductor`
- `body`: 論点の要約 + subsystem レベルで解決できない理由 + 元コメントへのリンク（発生元の subsystem PR 番号を含める）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 story Issue 番号
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_CONFIRM_STORY_CONDUCTOR` の値

### ラベル除去

MCP `transition_phase` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true
- `remove_labels_`:
  - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値
- `add_labels_`: なし

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: subsystem PR の番号
