# 要件確定（初回）

subsystem Issue 本文（前提条件 / 概要 / 背景 / 現状 / システム要件（SA））の草案を作成し、確認事項を投稿して待機に入る。

## 手順

### 親 story の確認

MCP `get_issue_or_pr` を呼び、親 story の内容を読む:
- `number`: 初期処理で取得した `parent` の番号
- `is_pr`: false
- `comments`: false
- `sub_issues`: true

親 story の `## ユースケース要件` と自 Issue の `scope:*` ラベルを照合し、自 subsystem が担当する範囲を特定する。
親 story ブランチに commit 済みの単一 UC シナリオも読み、自 subsystem が実現するフローを把握する（シナリオの participant のうち自分の `scope:*` に対応するものが担当範囲、他の participant は兄弟 subsystem の担当）。

### 現状調査

`## 現状` の 2 表（関連 Issue/PR / 関連ドキュメント）の材料を集める。
判断材料は親 story と設計 Wiki に閉じ、実装コード・テストコードは読まない（実装の調査は architect の SS設計 が担う）。

- 関連 Issue / PR: サブエージェント `ai-monitor:related-issue-finder` と `ai-monitor:related-pr-finder` を並列起動し、戻り値（番号 / 状況 / 概要 / 関連性）をそのまま `### 関連 Issue/PR` の表に整形する（入力: $issue_number と本文から抽出したキーワード）
- 関連ドキュメント: 注入済みの Wiki 索引を起点に、担当範囲に関係する設計 Wiki を洗い出す（オンデマンド取得は共通ルール『Wikiページのオンデマンド取得』）

`## 現状` の追加サブセクション:
- 親 story が `type:bug` の場合、親 story の記述から `### 再現手順` に期待と実際を転記する

### 本文の作成

テンプレート（イシュー本文/サブシステム）に沿って各セクションの草案を作成する。

- `## 背景` に「親 story #{番号} の {対象システム} 担当」の 1 行を必ず含める
- `## システム要件（SA）` は自 subsystem の担当範囲だけを書き、兄弟 subsystem の範囲は `### スコープ外` に回す
- 親 story の `sub_issues` に自分以外の subsystem がいる場合、`## 前提条件` に兄弟 subsystem との順序を書く（先に起票済みの兄弟が依存順で自分より前）

MCP `update_body` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `body`: 作成した本文

### 完了報告の投稿

MCP `comment` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `sender`: `subsystem-conductor`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `body`: 本文草案の完了報告（現状調査で分かったことと SA の要約 + 承認・修正方法の案内）

### 確認質問の投稿

以下の観点から今回の subsystem に該当するものだけを抽出し、本文・親 story の内容から AI 側で推奨案を判断して投稿する。
抽出結果が 0 件のときは `ask_questions` を呼ばずに次の手順へ進む。

| 観点 | 質問 | 選択肢例 |
| --- | --- | --- |
| 担当範囲の境界 | 「{境界にある機能} は本 subsystem と兄弟 subsystem のどちらで実装しますか？」 | A. 本 subsystem / B. 兄弟 subsystem（{番号}） |
| 既存機能の扱い | 「既存の {機能} は拡張しますか、新規に作りますか？」 | A. 既存を拡張 / B. 新規作成して既存は残す / C. 置き換える |
| バリデーション方針 | 「{入力} の検証はどこまで本 subsystem で持ちますか？」 | A. 本 subsystem で完結 / B. 兄弟 subsystem と二重に持つ |
| 非機能要件の基準値 | 「{性能 / セキュリティ} の基準値は {推奨値} でよいですか？」 | A. 推奨値でよい / B. 別の値（{値}） |
| スコープ外の確認 | 「{周辺機能} は今回スコープ外という理解で合っていますか？」 | A. 合っている / B. 含める |

MCP `ask_questions` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `sender`: `subsystem-conductor`
- `receiver`: ユーザーログイン名
- `intro`: `以下の点についてご確認ください。記号（例: A）で返信いただければ、その方針で進めます。`
- `questions`: 上記観点表から抽出

### 議論中 付与 + 待機

MCP `add_labels` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: $issue_number
- `is_pr`: false

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: $issue_number
