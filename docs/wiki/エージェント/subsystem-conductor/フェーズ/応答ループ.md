# 応答ループ

待機中のユーザーフィードバックに対応し、再び待機に入る。
どの待機かは、未解決の自分宛スレッドの文脈と待機している面（Issue / PR）で判断する。

## 手順

### 内容に応じた対応

| 待機の文脈 | 面 | 対応 |
| --- | --- | --- |
| 要件確定の本文修正指示 | subsystem Issue | 本文を修正（`update_body`）して「本文の `## XXX` を更新しました」と短く追記 |
| SA 変更案の調整 | subsystem Issue | 変更案コメントを更新して短く追記 |
| タスク一覧の修正指示 | subsystem PR | PR 本文の `## タスク一覧` を修正（`update_body`）して短く追記 |
| エスカレーション対応方針案の調整 | subsystem PR | 方針案コメントを更新して短く追記 |
| マージ前の最終確認への質問 | subsystem PR | 質問に回答して短く追記 |
| マージ時のコンフリクト解消の指示 | subsystem PR | 指示どおり解消して commit push し、解消内容を短く追記（追加の競合があれば再相談） |
| 上記以外 | 文脈から判断 | 文脈から必要な対応を判断して実施し、対応内容を短く追記 |

追記は MCP `reply_comment` を呼ぶ:
- `comment_node_id`: 返信対象コメントの node_id
- `sender`: `subsystem-conductor`
- `receiver`: ユーザーログイン名
- `format`:
  - `type`: `plain`
  - `body`: 返信本文

### assignee 再設定

MCP `set_assignee` を呼ぶ:
- `number`: 待機している面の番号（$issue_number or subsystem PR の番号）
- `is_pr`: 待機している面が PR なら true

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: `$AI_MONITOR_LABEL_PROCESSING_SUBSYSTEM_CONDUCTOR` が付いている面の番号（$issue_number or subsystem PR の番号。会話している面とは別のことがある）
