# マージ起動

architect の一式完了報告を検収し、検収結果を記録して次のターンのマージ実行へ進む。

検収の条件（タスク一覧の全チェック・テスト結果表の全 ✅・Ready 状態）は機械的に判定できるため、ユーザー確認は挟まない。

## 手順

### 一式完了報告の検収

一式完了報告と subsystem PR 本文を照合する。

- `## タスク一覧` の全行がチェック済みであること（チェックの記入は architect の担当）
- テスト結果表 4 表の結果列が全て `✅` であること
- PR が Ready 状態であること

未達がある場合は、次の順で処理して自ターンを終える（以降の手順は実行しない）。

1. 一式完了報告に不足内容を返信追記する（`reply_comment`・`receiver`: `architect`）
2. MCP `transition_phase` を呼ぶ:
   - `number`: $pr_number
   - `is_pr`: true
   - `remove_labels_`:
     - `$AI_MONITOR_LABEL_CONFIRM_SUBSYSTEM_CONDUCTOR` の値
   - `add_labels_`:
     - `$AI_MONITOR_LABEL_CONFIRM_ARCHITECT` の値
3. MCP `report_completion` を呼ぶ（`agent_name`: `subsystem-conductor` / `number`: $pr_number）

相手が読む材料（不足内容の返信）を置き終えてから確認ラベルを遷移させる。
自分の確認ラベルを外すのは、確認ラベルが 2 つ同時に付いた状態を作らないため（付いたままだと architect が本文を直すまで空振りのターンを繰り返す）。

### 一式完了報告の Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: architect の一式完了報告コメントの `node_id`

### 検収結果の記録

MCP `comment` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true
- `sender`: `subsystem-conductor`
- `format`:
  - `type`: `plain`
  - `body`: 検収結果の記録（照合したタスク一覧・テスト結果表・Ready 状態）

`議論中` の付与と `set_assignee` は行わない。
`確認:subsystem-conductor` を保持したまま自ターンを終え、次のターンで「subsystemマージ」へ進む。


### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: subsystem PR の番号
