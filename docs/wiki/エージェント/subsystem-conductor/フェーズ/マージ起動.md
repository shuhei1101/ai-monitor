# マージ起動

architect の一式完了報告を検収し、マージ前のユーザー最終確認ゲートを開く。

## 手順

### 一式完了報告の検収

一式完了報告と subsystem PR 本文を照合する。

- `## タスク一覧` の全行がチェック済みであること（チェックの記入は architect の担当）
- テスト結果表 4 表の結果列が全て `✅` であること
- PR が Ready 状態であること

未達がある場合は一式完了報告に不足内容を返信追記（`reply_comment`・`receiver`: `architect`）し、`確認:architect` を再付与して自ターンを終える（以降の手順は実行しない）。

### 一式完了報告の Resolve

MCP `resolve_comments` を呼ぶ:
- `node_ids`: architect の一式完了報告コメントの `node_id`

### 最終確認の依頼 + 待機

MCP `comment` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true
- `sender`: `subsystem-conductor`
- `receiver`: ユーザーログイン名（`gh api user --jq '.login'` で取得）
- `format`:
  - `type`: `plain`
  - `body`: マージ前の最終確認依頼（実装・テスト結果の要約 + 承認方法の案内）

続けて MCP `add_labels` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true
- `labels`:
  - `$AI_MONITOR_LABEL_IN_DISCUSSION` の値

続けて MCP `set_assignee` を呼ぶ:
- `number`: subsystem PR の番号
- `is_pr`: true

`確認:subsystem-conductor` は除去しない（承認後のマージ実行で復帰するため）。

### 作業完了報告

MCP `report_completion` を呼ぶ:
- `agent_name`: `subsystem-conductor`
- `number`: subsystem PR の番号
