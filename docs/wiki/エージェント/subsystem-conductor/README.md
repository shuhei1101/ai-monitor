# subsystem-conductor

判定は毎ターン、最新の取得結果（本文・ラベル・自分宛の未解決コメント）を材料に、上から順に見て最初にマッチしたフェーズを 1 つ実行する。
監視面は subsystem Issue（要件確定・バグ差し戻し）と subsystem PR（タスク一覧・設計以降の報告）の 2 つで、起動条件の「本文」「ラベル」はフェーズごとに対象の面のものを見る。

## 目次

| ページ | 概要 | 起動条件 |
| --- | --- | --- |
| [初期処理](./フェーズ/初期処理.md) | Issue / PR の本文・ラベル・自分宛コメントの取得 | 毎ターン最初に必ず実行（以降の判定材料を取得） |
| [要件確定（初回）](./フェーズ/要件確定（初回）.md) | 現状調査と SA 草案の作成・確認事項の投稿 | subsystem Issue 本文の `## システム要件（SA）` が未記入（未作業） |
| [エスカレーションの中継](./フェーズ/エスカレーションの中継.md) | subsystem レイヤーで判断できない論点の story-conductor への中継 | 未解決の自分宛コメントに architect のエスカレーション報告がある |
| [応答ループ](./フェーズ/応答ループ.md) | フィードバックへの対応 | `議論中` あり + 未解決の自分宛コメントがある |
| [バグ修正着手](./フェーズ/バグ修正着手.md) | 差し戻しの影響範囲分析と修正用 PR の作成（SA 変更が要る場合は変更案の確認） | 未解決の自分宛コメントに story-conductor のバグ差し戻しがあり、SA 変更案コメント未投稿 |
| [SA変更確定](./フェーズ/SA変更確定.md) | 承認された SA の本文反映と修正用 PR の作成 | `議論中` なし + SA 変更案コメント投稿済み（未 Resolve） |
| [要件確定（完了処理）](./フェーズ/要件確定（完了処理）.md) | subsystem Draft PR の作成とタスク一覧の確認ゲート | `議論中` なし + SA 記入済み + subsystem Draft PR 未作成 |
| [タスク一覧確定](./フェーズ/タスク一覧確定.md) | 承認されたタスク一覧での architect への一式委任 | `議論中` なし + subsystem PR が Draft + PR に `確認:architect` 未付与 |
| [インターフェース確定の中継](./フェーズ/インターフェース確定の中継.md) | architect のインターフェース確定報告の story-conductor への中継 | 未解決の自分宛コメントに architect のインターフェース確定報告がある |
| [マージ起動](./フェーズ/マージ起動.md) | 一式完了報告の検収とマージ前のユーザー最終確認ゲート | 未解決の自分宛コメントに architect の一式完了報告がある |
| [subsystemマージ](./フェーズ/subsystemマージ.md) | subsystem PR の親 story ブランチへのマージと完了報告 | `議論中` なし + subsystem PR が Ready + `## タスク一覧` 全チェック済み |
