# ai-monitor: マージ手順

各レイヤーの conductor が自分の配下 PR を base ブランチへマージするときの共通手順。
subsystem → story / story → epic / epic → master の全昇格マージで同じ。
conductor スキルに動的コンテキストとして注入して使う。

## 手順

1. 対象 PR の Draft を MCP `mark_pr_ready` で解除する（Ready 済みなら何も起きない）
2. 対象 PR の worktree に復帰し、base ブランチを取り込む（`git fetch` + `git merge origin/{base}`）
3. コンフリクトがないことを確認する（あれば「コンフリクト時の対応」へ）
4. MCP `merge_pr`（`strategy`: `squash`）で squash マージ + リモートブランチ削除
5. MCP `worktree_remove` でローカルの worktree を削除する
6. 紐づく Issue を MCP `close`（`reason`: `completed`）で閉じる

昇格マージの base は master ではないため、PR 本文にクローズキーワードを書いても紐づく Issue は閉じない。
close は各レイヤーのマージフェーズが明示的に実行する。

## コンフリクト時の対応

1. 対象 PR に競合ファイルと「どちらの変更を残すか」の相談コメントを投稿 + `議論中` 付与 + `assignee=ユーザー` 設定
2. 応答ループ: ユーザーの判断コメント + assignee 外し → 指示どおり解消 commit → 解消内容を同スレッドに返信追記（追加の競合・疑問があれば再相談 + `assignee=ユーザー` 再設定）
3. 全競合解消後、手順 4（squash マージ）に合流する
