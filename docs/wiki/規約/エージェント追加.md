# ai-monitor: エージェント追加

エージェントを新設 / 改名 / 削除するときに更新するファイル一式。
エージェント名は複数のレイヤー（ラベル定数 / Python の型定義 / 設定 / Wiki）に分散しているため、1 箇所でも漏れると起動時エラーかサイレントな未起動になる。

## 更新対象

上から順に実施する。
`{名前}` はケバブケース（例: `reverse-architect`）、`{スネーク}` はそのアンダースコア置換（例: `reverse_architect`）。

| 対象 | ファイル | 追加する内容 | 漏れたときの症状 |
| --- | --- | --- | --- |
| ラベル定数 | `plugins/ai-monitor/constants.env` | `AI_MONITOR_LABEL_CONFIRM_{大文字スネーク}` と `AI_MONITOR_LABEL_PROCESSING_{大文字スネーク}` | フェーズページのラベル参照が空文字に展開される |
| ラベル型 | `src/ai_monitor/shared/settings.py` の `Labels` | `confirm_{スネーク}` と `processing_{スネーク}` のフィールド | 起動時に定数の読み込みで検証エラー |
| エージェント名一覧 | `src/ai_monitor/shared/settings.py` の `_AGENT_NAMES` | `{名前}` を 1 要素 | モデル設定の完全性チェックを素通りして未起動になる |
| モデル設定サンプル | `settings.yaml.example` の `agents` | `{名前}: model: {モデル}` | 新規セットアップ時に起動エラー |
| モデル設定 | `~/.config/ai-monitor/settings.yaml` の `agents` | 同上 | 起動時に「欠落しているエージェント」で例外 |
| フェーズ注入 | `config/agent_phases.yaml` | `{名前}:` とフェーズページのパス一覧（並び順が注入順） | 起動プロンプトが空になる |
| フェーズ索引 | `docs/wiki/エージェント/{名前}/README.md` | 起動条件付きの目次 | 同上 |
| フェーズページ | `docs/wiki/エージェント/{名前}/フェーズ/{フェーズ名}.md` | 各フェーズの手順 | 同上 |
| エージェント索引 | `docs/wiki/エージェント/README.md` | 目次に 1 行 | 一覧から辿れない |
| 指揮系統 | `docs/wiki/プロジェクト管理/エージェント組織図.md` | 組織図の mermaid と連絡先一覧に 1 行 | 連絡先が不明で他エージェントから呼べない |
| シナリオ | `docs/wiki/設計図/シナリオ/単一ユースケース/{UC名}.md` | 担当フェーズに対応するユースケース | E2E テストの対象にならない |
| プラグイン版数 | `.claude-plugin/marketplace.json` と `plugins/ai-monitor/.claude-plugin/plugin.json` | 両方を同じ値に同時インクリメント | `constants.env` の変更がキャッシュに反映されない |
| GitHub ラベル | 監視対象リポジトリ | 追加した 2 ラベルを作成 | ラベル付与の MCP 呼び出しが失敗する |

## 反映手順

`constants.env` を変更した場合、プラグインキャッシュ経由で届くため反映に手順が要る。

1. プラグイン版数を 2 ファイルとも同じ値にインクリメントする
2. push する（ユーザー操作）
3. `/plugin` でマーケットプレイスを更新する
4. `/reload-plugins` を実行する
5. `~/.claude/plugins/cache/ai-monitor/ai-monitor/{新版数}/` が生成されたことを確認する

`docs/wiki/` と `src/` の変更はモニターがローカルクローンから直読みするため、この手順は不要。

## フェーズページの共有

既存エージェントの派生（同じ工程で入力源だけが違うもの）を作る場合、フェーズページはファイルを複製せず `config/agent_phases.yaml` で共有する。

```yaml
architect:
  - エージェント/architect/README.md
  - エージェント/architect/フェーズ/初期処理.md
  - エージェント/architect/フェーズ/SS設計（初回）.md
  - エージェント/architect/フェーズ/設計ページ確定.md

reverse-architect:
  - エージェント/reverse-architect/README.md
  - エージェント/architect/フェーズ/初期処理.md
  - エージェント/reverse-architect/フェーズ/コード読解によるSS設計.md
  - エージェント/architect/フェーズ/設計ページ確定.md
```

差分になるフェーズだけを新設し、共通部分は元エージェントのページを参照する。
確認ラベルが別になるため、派生側の起動条件はフェーズ索引だけで表現でき、エージェント側にモード判定を持たせずに済む。

## 削除 / 改名

更新対象の表を逆順に辿って除去する。
GitHub 側の既存ラベルは、そのラベルが付いた Issue / PR が残っていないことを確認してから削除する。
