# 最終マージの判定

conductor が PR をマージする前に、そのマージがワークフロー全体の終端かどうかを判定する。

## 判定

マージ対象の PR に紐づく Issue の `parent` を見る。

| 親 Issue | 判定 | 根拠 |
| --- | --- | --- |
| なし | 最終マージ | 報告先が存在しない |
| `layer:intake` | 最終マージ | intake は起票専用で、以降の会話を持つ conductor がいない |
| 上記以外（`layer:system` / `layer:epic` / `layer:story` 等） | 通常マージ | 親レイヤーの conductor へ返す必要がある |

## 判定後にやること

| 項目 | 最終マージ | 通常マージ |
| --- | --- | --- |
| 監視面の除去 | 監視面に残っている全番号を除去する | マージした PR の番号だけを除去する |
| 上位への完了報告 | 行わない | 親 Issue に `確認:{親レイヤーの conductor}` + 完了報告コメントを投稿する |
| セッションの一括解放 | 自 Issue の close をモニターが検知して配下を解放する | 走らせない（最上位が close するまで配下のセッションは常駐する） |

最下位から着手した場合（親を持たない subsystem Issue を直接起票した場合 等）も同じ判定で最終マージになる。
