# 最終マージの判定

conductor が PR をマージする前に、そのマージがワークフロー全体の終端かどうかを判定する。

## 判定

マージ対象の PR の base ブランチを見る。

| base | 判定 | 根拠 |
| --- | --- | --- |
| `master` | 最終マージ | 上位レイヤーが存在しない |
| 上記以外（親レイヤーのブランチ） | 通常マージ | 親レイヤーの conductor へ返す必要がある |

最下位から着手した場合（親を持たない subsystem PR を直接作った場合 等）も base が `master` になるため最終マージになる。

## 判定後にやること

| 項目 | 最終マージ | 通常マージ |
| --- | --- | --- |
| 監視面の除去 | 監視面に残っている全番号 | マージした PR の番号だけ |
| 上位への完了報告 | 行わない | 親 PR へ投稿する |
| セッションの一括解放 | 起点の Issue に紐づく PR が全てマージされたことをモニターが検知して配下を解放する | 走らせない（起点の Issue が close するまで配下のセッションは常駐する） |

### 監視面の除去

フェーズの最後（作業完了報告の後）に実行する。
先に除去すると、作業完了報告が処理中ラベルの付いた面の番号でセッションを解決できずに失敗する。

MCP `remove_watch_targets` を呼ぶ:
- `agent_name`: 自分のエージェント名
- `number`: $number
- `watch_numbers`: 上表の範囲

### 上位への完了報告

最終マージの場合は実行しない。

MCP `comment` を呼ぶ:
- `number`: 親 PR 番号
- `is_pr`: true
- `sender`: 自分のエージェント名
- `receiver`: 親 PR の `layer:` に対応する conductor（`layer:system` なら `system-conductor`）
- `format`:
  - `type`: `plain`
  - `body`: マージ完了報告（対象 PR 番号 + マージした PR へのリンク + 実装内容の要約。規約『コメント』の「報告には作業した面のリンクを載せる」）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 PR 番号
- `is_pr`: true
- `labels`:
  - 報告先 conductor の確認ラベルの値
