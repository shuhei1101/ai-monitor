# 最終マージの判定

conductor が PR をマージする前に、そのマージがワークフロー全体の終端かどうかを判定する。

## 判定

マージ対象の PR に紐づく Issue の `parent` を見る。

| 親 Issue | 判定 | 根拠 |
| --- | --- | --- |
| なし | 最終マージ | 報告先が存在しない |
| `layer:intake` | 最終マージ | intake は起票専用で、以降の会話を持つ conductor がいない |
| 上記以外（`layer:system` / `layer:epic` / `layer:story` 等） | 通常マージ | 親レイヤーの conductor へ返す必要がある |

最下位から着手した場合（親を持たない subsystem Issue を直接起票した場合 等）も同じ判定で最終マージになる。

## 判定後にやること

| 項目 | 最終マージ | 通常マージ |
| --- | --- | --- |
| 監視面の除去 | 監視面に残っている全番号 | マージした PR の番号だけ |
| 上位への完了報告 | 行わない | 親 Issue へ投稿する |
| セッションの一括解放 | 自 Issue の close をモニターが検知して配下を解放する | 走らせない（最上位が close するまで配下のセッションは常駐する） |

### 監視面の除去

フェーズの最後（作業完了報告の後）に実行する。
先に除去すると、作業完了報告が処理中ラベルの付いた面の番号でセッションを解決できずに失敗する。

MCP `remove_watch_targets` を呼ぶ:
- `agent_name`: 自分のエージェント名
- `number`: $issue_number
- `watch_numbers`: 上表の範囲

### 上位への完了報告

最終マージの場合は実行しない。

MCP `comment` を呼ぶ:
- `number`: 親 Issue 番号
- `is_pr`: false
- `sender`: 自分のエージェント名
- `receiver`: 親 Issue の `layer:` に対応する conductor（`layer:system` なら `system-conductor`）
- `format`:
  - `type`: `plain`
  - `body`: マージ完了報告（対象 Issue 番号 + マージした PR へのリンク + 実装内容の要約。規約『コメント』の「報告には作業した面のリンクを載せる」）

続けて MCP `add_labels` を呼ぶ:
- `number`: 親 Issue 番号
- `is_pr`: false
- `labels`:
  - 報告先 conductor の確認ラベルの値
